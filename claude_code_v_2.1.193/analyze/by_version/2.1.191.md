# 2.1.191 — Source Diff Analysis

**Theme:** **MCP reliability + perf, with a permissions/lifecycle correctness sweep and a render-pipeline cost reduction.** 2.1.191 is the heaviest reliability release of the v2.1.183→v2.1.193 window (20 bullets). The headline is **MCP self-healing**: capability discovery (`tools/list` / `prompts/list` / `resources/list`) and OAuth discovery/token requests now **retry transient network errors with short backoff**, headless environments skip the browser popup and go straight to paste-the-URL, and a 404 now surfaces the **URL** plus a pointer to your MCP config instead of an opaque error. Around that sit two genuinely new capabilities — `/rewind` can now resume a conversation from **before `/clear`** was run, and sandbox network "Yes" answers are **remembered for the session** — plus a cluster of lifecycle/correctness fixes: stopping a background agent from the tasks panel is now **permanent**, approving a `/permissions` recently-denied entry now **persists on close**, and hooks with **comma-separated matchers** (`"Bash,PowerShell"`) finally fire. The perf story is the **~37% streaming-CPU reduction** (coalescing text updates to a 100 ms cadence) and reduced long-session memory growth from the terminal-output cache — both real, both render-pipeline internals out of scope for the twelve-theme tree. The tail is the usual terminal/UX correctness batch: `/voice` now explains an org-policy restriction instead of a generic "not available", `claude agents` shows a hint for builtin slash commands instead of sending them as prompt text, the `/login` URL no longer truncates when Windows Terminal wraps it, Cmd+click works in Ghostty over ssh/tmux, the welcome splash fits an 80×24 window, and managed `forceRemoteSettingsRefresh` now takes effect via MDM/file policy (with a `Cache-Control: no-cache` fetch). (Build: VERSION `2.1.193`, GIT_SHA `a1938d2a`, cli_inner_pretty.js:162,214 — this delta ships *inside* the 193 bundle; 2.1.191 was not separately extracted.)

> Twelve-theme **in-scope** items (covered by a module doc) are summarized with their verified anchor and linked to the deep-dive — not re-derived here. **Out-of-scope** items get their primary analysis in this file, honestly flagged `(not isolable)` where the fix lives inside a large carried-over render region with no distinctive declaration, exactly as the 2.1.183 reference does.

## 2. MCP reliability — discovery retries, OAuth retries + headless paste-URL, 404-with-URL (IMPROVEMENT — FOCUS: MCP)

**Type:** improvement (3 bullets) · **Modules:** MCP discovery, MCP OAuth, MCP error messages · **In-scope**

Three MCP-robustness bullets land together:

- **Capability discovery retries transient errors with backoff.** `listWithPaginationAndRetry` (`P1n`, cli_inner_pretty.js:292176) wraps `tools/list` / `prompts/list` / `resources/list` with a retry loop using the backoff schedule `mpp = [250, 500, 1000]` ms (cli_inner_pretty.js:293455). The 183 lister was single-try.
- **OAuth discovery + token requests retry once; headless skips the browser.** `createRetryingOAuthFetch` (`AOn`, cli_inner_pretty.js:281573) wraps the carryover single-fetch body with one retry (500 ms) after a transient error; in a headless environment the browser popup is skipped and the flow goes straight to the paste-the-URL prompt.

## 7. `/voice` explains an organization-policy restriction (FIX — out of scope, primary analysis here)

**Type:** fix · **Modules:** `/voice` command, Org policy / entitlements

### TL;DR

When voice mode is disabled by an organization's policy, `/voice` previously printed a generic *"Voice mode is not available."* Now it explains the restriction — *"Voice mode is disabled by your organization's policy. Contact your organization admin to enable it."* — or, if the policy couldn't be fetched, a network-error hint.

### How it works

The `/voice` handler `bFf` (cli_inner_pretty.js:572485) early-returns when voice is not enabled for the account. The new step is a call to the generic org-policy explanation builder `gG` (cli_inner_pretty.js:572489): `let S = gG("allow_voice_mode", "Voice mode", "is")`; if it returns a non-null string the handler returns *that* (cli_inner_pretty.js:572490), only falling back to the generic *"Voice mode is not available."* (cli_inner_pretty.js:572491) when no policy explanation applies.

```javascript
// ============================================
// orgPolicyExplanation - build a human-readable org-policy denial / verify-failure message
// Location: cli_inner_pretty.js:148824-148829 (v2.1.193)
// ============================================

// ORIGINAL (for source lookup):
function gG(e, t, n) {
  if (Fs(e)) return null;
  if (hG() === null)
    return `Couldn't verify your organization's policy for ${t.charAt(0).toLowerCase() + t.slice(1)}. Check your network connection and try again.`;
  return `${t} ${n} disabled by your organization's policy. Contact your organization admin to enable ${n === "are" ? "them" : "it"}.`;
}

// READABLE (for understanding):
function orgPolicyExplanation(entitlementKey, label, verb) {
  if (isEntitlementAllowed(entitlementKey)) return null;       // not actually blocked → no message
  if (loadPolicyLimits() === null)                              // policy cache cold / unreachable
    return `Couldn't verify your organization's policy for ${lowerFirst(label)}. Check your network connection and try again.`;
  return `${label} ${verb} disabled by your organization's policy. Contact your organization admin to enable ${verb === "are" ? "them" : "it"}.`;
}

// Mapping: gG→orgPolicyExplanation, Fs→isEntitlementAllowed, hG→loadPolicyLimits, e→entitlementKey ("allow_voice_mode"), t→label ("Voice mode"), n→verb ("is")
```

`gG` is a **shared** builder — the same `allow_voice_mode` / `allow_web_fetch` / `allow_memory_sync` / … entitlement table feeds it (the pairs are enumerated at cli_inner_pretty.js:148870+). The 2.1.191 delta is wiring it into the `/voice` handler.

### Before / after

| | v2.1.183 (before-picture) | v2.1.191 (in 193 bundle) |
|---|---|---|
| voice-disabled message | `return { type:"text", value:"Voice mode is not available." }` only — no policy explanation (cli_inner_pretty.js:561695, **183**) | calls `gG("allow_voice_mode","Voice mode","is")`; returns the org-policy / verify-failure explanation when applicable, generic only as fallback (cli_inner_pretty.js:572489-572491) |

**Why:** A blanket *"not available"* gives the user nothing to act on — they can't tell a missing-account state from a corporate policy block. Routing through the entitlement explainer turns the dead-end into an actionable message (contact your admin) and distinguishes a *policy denial* from a *couldn't-verify-the-policy* network state. **Confidence:** high — the `gG` call at 572489 and the generic-string fallback at 572491 are verified, and the 183 handler at 561695 (**183**) has no equivalent call.

## 8. Managed `forceRemoteSettingsRefresh` takes effect via MDM/file policy + `Cache-Control: no-cache` (FIX — out of scope, primary analysis here)

**Type:** fix · **Modules:** Managed settings, Remote settings fetch, Policy tiers

### TL;DR

`forceRemoteSettingsRefresh` (which forces a blocking remote-settings fetch at startup) now takes effect when it is set via an **MDM tier or file policy**, not only via the primary policy slice; and the remote-settings fetch now sends `Cache-Control: no-cache` (+ `Pragma: no-cache`) so proxies can't serve a stale response.

### How it works

Two net-new pieces:

- **Policy-tier OR-merge.** The managed-settings resolver folds `forceRemoteSettingsRefresh` from *any* policy tier into the merged `policySettings` object:

```javascript
// ============================================
// mergePolicyTiers - OR forceRemoteSettingsRefresh across all policy tiers (MDM + file)
// Location: cli_inner_pretty.js:57812-57814 (v2.1.193)
// ============================================

// ORIGINAL (for source lookup):
let i = ZV({}, o ?? {}, r ?? {}, EK);
if (n.some((a) => a.forceRemoteSettingsRefresh === !0)) i.forceRemoteSettingsRefresh = !0;
return { settings: i, errors: s };

// READABLE (for understanding):
let merged = deepMerge({}, parentSlice ?? {}, adminSlice ?? {}, FROZEN_EMPTY);
if (policyTiers.some((tier) => tier.forceRemoteSettingsRefresh === true))
  merged.forceRemoteSettingsRefresh = true;          // honor it from ANY tier (MDM/file), not just the primary slice
return { settings: merged, errors };

// Mapping: i→merged, n→policyTiers, o→parentSlice, r→adminSlice
```

  This OR-merge is absent in 183 (`grep "forceRemoteSettingsRefresh === !0"` → 0 hits in 183). The consumer at cli_inner_pretty.js:712189 (`_n("policySettings")?.forceRemoteSettingsRefresh && !f` → blocking `await Uuo(aFn)`) is carryover; the schema field is at cli_inner_pretty.js:56637.

- **`Cache-Control: no-cache` on the fetch.** The remote-settings fetcher `Fka` (cli_inner_pretty.js:312112) builds its request headers with `"Cache-Control": "no-cache", Pragma: "no-cache"` (cli_inner_pretty.js:312125), alongside the existing `If-None-Match` ETag handling. The `"Cache-Control": "no-cache"` literal went **0→1** vs 183.

### Before / after

| | v2.1.183 (before-picture) | v2.1.191 (in 193 bundle) |
|---|---|---|
| tier coverage | only the primary/admin slice's `forceRemoteSettingsRefresh` was honored (apply sites at cli_inner_pretty.js:693044/694181, **183**); no tier OR-merge | OR-merge across all tiers at cli_inner_pretty.js:57813 |
| fetch caching | no `Cache-Control` header (`Fka`-equivalent at cli_inner_pretty.js:302495, **183**) | `Cache-Control: no-cache` + `Pragma: no-cache` (cli_inner_pretty.js:312125) |

**Why:** Enterprises push `forceRemoteSettingsRefresh` through MDM or a file-based policy tier, not the primary slice — without the OR-merge that intent was silently dropped. And a caching proxy could serve a stale `200` for the settings endpoint, defeating the "force refresh"; `Cache-Control: no-cache` makes the round-trip authoritative. **Confidence:** high — both the OR-merge (57813) and the header (312125) are verified net-new, with verified 183 before-pictures.

## 9. `claude agents` shows a hint for builtin slash commands instead of sending them as prompt text (FIX — out of scope, primary analysis here)

**Type:** fix · **Modules:** `claude agents` background sessions, Local slash-command dispatch

### TL;DR

In a `claude agents` background (non-interactive) session, typing a builtin slash command like `/usage` was sent to the agent as **prompt text**. It now emits a **hint** explaining the command isn't available in that session instead of polluting the conversation.

### How it works

The slash-command dispatcher `v9p` (cli_inner_pretty.js:398029) checks whether the command is permitted (`!Zx(c)`); when it is not, it builds the hint *"/<name> isn't available in this session."* (cli_inner_pretty.js:398034) and, in a **non-interactive session**, returns it wrapped as a `<local-command-stdout>` result with `shouldQuery: !1` (cli_inner_pretty.js:398035-398041) — i.e. it short-circuits to a hint rather than feeding the command string into the model turn.

```javascript

// Location: cli_inner_pretty.js:398032-398042 (v2.1.193)
// ============================================

  return { messages: [Pc(d, "warning")], shouldQuery: !1, command: c, resultText: d };
}

// READABLE (for understanding):

  telemetry(evt, "cmd_policy_disabled");
  let hint = `/${name} isn't available in this session.`;
  if (opts.isNonInteractiveSession)
    return { messages: [echoTyped(command), localCommandStdout(hint)], shouldQuery: false, command, resultText: hint };
  return { messages: [warningMessage(hint)], shouldQuery: false, command, resultText: hint };
}

// Mapping: v9p→dispatchLocalSlashCommand, Zx→isCommandPermitted, e→name, isNonInteractiveSession→background/claude-agents session
```

The hint string *"isn't available in this session."* is **net-new** (grep 0→1 vs 183). The adjacent *"opens an interactive panel and isn't available in this environment."* branch (cli_inner_pretty.js:398087) is carryover (1=1).

**Why:** A background `claude agents` session has no TUI for `/usage`, `/config`, etc. Forwarding the literal `/usage` text as a prompt makes the agent try to *answer* a command instead of running it — confusing and wasteful. Returning a `<local-command-stdout>` hint with `shouldQuery:false` ends the turn cleanly with an explanation. **Confidence:** medium-high — the net-new hint string and the `isNonInteractiveSession` short-circuit are verified; the precise tie to the `/usage`-in-`claude agents` repro is inferred from the string and the non-interactive gate.
