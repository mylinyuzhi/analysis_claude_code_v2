# 2.1.187 — Source Diff Analysis

**Theme:** **Permissions + subagent-depth correctness, wrapped in a broad agents/MCP/Remote reliability sweep.** 2.1.187 is the heaviest release in the 2.1.183→2.1.193 window (21 bullets). Its center of gravity is **enterprise-grade gating**: a new `sandbox.credentials` setting that folds credential-file and secret-env protection into the live sandbox deny lists, and **org-configured model restrictions** that propagate through the model picker, `--model`, `/model`, and `ANTHROPIC_MODEL` with a "restricted by your organization's settings" message and an opus→sonnet→haiku fallback. Sitting next to that is a cluster of **subagent/agent-team correctness** fixes: fork-aware depth-cap accounting plus resume-restore of a subagent's original spawn depth; stop-notification **attribution** ("who stopped this agent", finished/stopped wording replacing "came to rest"); and a remote-MCP **idle-timeout watchdog** that aborts a 5-minute hang instead of blocking the loop. The structured-output path gets a real behavior change — after a successful `StructuredOutput` call the model can **no longer re-call it indefinitely**, and follow-up turns reliably return structured output, replacing the per-turn Stop-hook nudge that 2.1.183 used. Around the focus work is a long tail of terminal/UX polish: **mouse click** in fullscreen select menus, `--bg`/`--background` finally listed in `claude --help`, Ghostty macOS Cmd+click URLs, `/btw` ←/→ history navigation, an optional-workflow `/install-github-app`, and several Remote-Control/paste/`/share` input fixes. (Build: VERSION `2.1.193` tree, build `a1938d2a`; line numbers are 193-bundle-specific.)

> Focus / in-scope items (covered by a depth module doc) are summarized here with their verified anchor and a link to the module doc — the full mechanism lives there. Out-of-scope items get their primary analysis here, with a cited anchor where the change is isolable and explicit candor where it is not.

## 13. Mouse click support in fullscreen select menus (NEW — primary analysis here)

**Type:** feature · **Modules:** UI (Select component), Fullscreen TUI input · **Out of scope** (no module doc) — analyzed here.

### TL;DR

In **fullscreen mode** you can now click an option in a select menu — permission prompts, `/model`, `/config`, and any other `Select`-based menu — to choose it, instead of only using the keyboard.

### How it works

Each option row in the select component now receives an `onClick` handler. The row element `V1d` is rendered with `onClick: ce(Tt.option)` (`cli_inner_pretty.js:191075`), where `ce` is the option-select callback and `Tt.option` is the row's option; the same wiring appears on the scroll-affordance rows at `cli_inner_pretty.js:190873` and `cli_inner_pretty.js:190974` (`onClick: ce(Ne)`). Mouse events reach those handlers through the fullscreen renderer's mouse dispatch path (`kind === "mouse"` → `H0d`, `cli_inner_pretty.js:171735`/`171774`), the same SGR-mouse plumbing used for hover and selection.


### Before / after vs 2.1.183

Total `onClick:` handlers in the bundle go **47 (183) → 54 (193)**; the new ones include the select-menu option rows (`:191075`) and the menu scroll rows (`:190873`, `:190974`). In 2.1.183 the same select rows had no `onClick` — menus were keyboard-only.

**Why:** fullscreen mode already captures SGR mouse events (for scroll/hover/selection), so the click target was free — wiring each option row's `onClick` to the existing select callback turns the menu into a pointer-navigable surface without a new input subsystem. **Confidence: high** (the net-new `onClick` on the option row is verbatim, and the 47→54 delta is direct).

## 17. Remaining out-of-scope fixes (anchors where isolable, candor where not)

These five bullets have no module doc; primary analysis is here. Two are isolable to a region; three are honestly **not isolable to a single declaration**.

- **`--resume` "No conversation found" when the original `-p` run produced no model turns (FIX).** A `-p` invocation that produced zero model turns left no resumable session record, so a later `--resume` failed. The resume read path is `Zue(...)` at `cli_inner_pretty.js:714259`, whose `null` result raises *"No conversation found with session ID: <id>"* at `cli_inner_pretty.js:714266` (the same string is also used for an explicit session id at `cli_inner_pretty.js:708957`). The **root cause** is upstream session **persistence** — a no-model-turn `-p` run must still write a session record — which is **not isolable to a single distinctive declaration** in the persistence path. (anchors: the resume-read + error string are high confidence; the persistence patch site is not isolable.)

- **Pasted Korean/CJK text turning into mojibake on terminals that deliver paste as per-byte extended-key events (FIX).** Some terminals deliver a paste byte-by-byte as extended-key (Kitty/CSI-u) events; decoding each byte independently splits multi-byte UTF-8 sequences (Korean/CJK) into garbage. The relevant machinery is the extended-key parser (`kittyKeyboard`, `cli_inner_pretty.js:160490`), the paste-buffer accumulation in the input parser (`pasteBuffer`/`isPasted`, `cli_inner_pretty.js:160545-160906`), and the streaming UTF-8 decoder `decode(bytes, { stream: true })` (`Yln`, `cli_inner_pretty.js:50194`). The fix is a **byte-accumulate-before-decode** adjustment across these and is **not isolable to a single declaration**. (Note: the unrelated VS Code message at `cli_inner_pretty.js:155997`, *"VS Code 1.123/1.124 will mojibake this paste — update to ≥1.125"*, is a *different* mojibake path keyed on the `TERM_PROGRAM_VERSION 1123000–1125000` range check at `cli_inner_pretty.js:155912` (the version string is parsed by `OTd` at `cli_inner_pretty.js:155918`).) (anchors: high confidence; exact patch site: not isolable.)

- **`/update` over Remote Control hanging when a startup trust dialog would have shown (FIX).** When `/update` ran over Remote Control on a workspace that would otherwise present the startup **trust dialog**, the update hung waiting on a dialog that can't be shown remotely. The Remote Control surface (`enableRemoteControl`, `cli_inner_pretty.js:564413`; `disableRemoteControl` setting, `cli_inner_pretty.js:56463`) and the trust-dialog gating are spread across many sites (e.g. `cli_inner_pretty.js:241761`, `569808`); the specific "skip/auto-resolve the trust dialog on the Remote-Control `/update` path" patch is **not isolable to a single declaration**. (anchors: the Remote-Control + trust-dialog regions are high confidence; the `/update` patch site is not isolable.)

- **Esc, Ctrl-C, and Ctrl-D not working while `/share` is uploading (FIX).** During a `/share` upload the dialog showed *"Uploading share…"* (`cli_inner_pretty.js:484277`) but swallowed Esc/Ctrl-C/Ctrl-D, so the upload couldn't be interrupted. The fix is in the share/feedback dialog's input handling during the `submitting` state; it is **not isolable to a single distinctive declaration** (the submit-state keyboard handling rides the shared consent/feedback component, not a grep-able `/share`-specific handler). (anchors: the submit-state string is high confidence; the keyboard-handling patch site is not isolable.)

- **[VSCode] extension becoming unresponsive when resuming a large session (FIX).** This fix lives in the **VS Code extension** codebase, which is a separate package from `cli_inner_pretty.js`; there is **no anchor in the CLI bundle**. Out of scope for this tree. (confidence: n/a — not present in this artifact.)
