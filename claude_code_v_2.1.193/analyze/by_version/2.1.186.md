# 2.1.186 — Source Diff Analysis

**Theme:** **The densest release of the v2.1.183 → v2.1.193 window — net-new CLI surface, a default-on behavior upgrade, and a broad correctness/UX sweep across MCP, Tools, Skills, Permissions, Agent-team, Workflow, Auth, and the background-agents panel.** 2.1.186 ships 33 changelog items, more than any other release in the window. The headline capabilities are genuinely new: a non-interactive **`claude mcp login`/`logout`** CLI (with `--no-browser` stdin redirect for SSH), the **`!` bash auto-respond** upgrade that now feeds bash output back to Claude by default (the one upgrade gotcha — opt out with `"respondToBashCommands": false`), a **`/plugin` Installed → Skills** section, a **`teammateMode: "iterm2"`** backend, and a **"Claude Platform on AWS · refresh credentials"** `/login` option. Around those sit two safety fixes that close real enforcement gaps — **`Agent(type)` deny / `Agent(x,y)` allow-list enforcement** for named subagent spawns and the **workflow `agent({schema})` 5-attempt abort** that stops a structured-output subagent looping forever — plus a cluster of MCP, skills-frontmatter, retry-cap, and background-panel reliability fixes. Several changelog lines describe behavior that is **byte-identical carryover from 2.1.183** (the MEMORY.md compact reminder, the bg-subagent permission forwarding, the `/plugin` "more above" indicator) — those are labeled honestly so the delta isn't inflated. (Build: VERSION `2.1.193`, GIT_SHA `a1938d2a`, anchors are 193-bundle line numbers.)

> Focus-feature items (covered by a module doc) get a short summary + the verified anchor + a link to the depth doc. Non-focus items get their primary analysis here, with an isolable anchor where one exists and an honest "(not isolable)" + nearest verified region where the fix lives in a large carried-over render path.

### 1. `claude mcp login <name>` / `claude mcp logout <name>` CLI (NEW)

**Type:** feature · **Modules:** MCP, CLI

New CLI verbs authenticate (or sign out of) an MCP server without opening the interactive `/mcp` menu — useful for headless/SSH setups; `--no-browser` redirects the OAuth handshake through stdin so it can be completed over a remote shell. ### 3. `!` bash commands now auto-trigger a Claude response (NEW — upgrade gotcha)

**Type:** behavior change (default-on) · **Modules:** Tools, CLI

Typing `!<cmd>` previously injected the command's output into context **silently**; now Claude automatically responds to that output. `processBashCommand` (`y6f`, cli_inner_pretty.js:617562) returns `shouldQuery: true` unless the run was interrupted, backgrounded, or aborted, gated at cli_inner_pretty.js:617604. The new setting `respondToBashCommands` (cli_inner_pretty.js:56492) **defaults to `true`** — set it `false` in settings.json to keep the old context-only behavior. This is the release's one upgrade gotcha: a workflow that used `!` purely to stash output now spends a model turn reacting to it. (183 `Owf@604506` was always silent.)

→ [../04_tools/bash_input_respond.md](../04_tools/bash_input_respond.md)

### 12. "Claude Platform on AWS · refresh credentials" `/login` option (NEW — isolable)

**Type:** feature · **Modules:** Auth / `/login`, AWS (Bedrock/Platform)

**TL;DR.** When `awsAuthRefresh` (a path to a credential-refresh script) is configured in settings, the `/login` menu now offers a "Claude Platform on AWS · refresh credentials" entry that runs that script in-place.

**How it works.** The option is appended to the `/login` provider list only when the gate `C2e()` (cli_inner_pretty.js:135747 → `return (jo() || {}).awsAuthRefresh`) is truthy — i.e. an `awsAuthRefresh` script path is set (declared at cli_inner_pretty.js:56244, *"Path to a script that refreshes AWS authentication"*). The menu entry `{ label: "Claude Platform on AWS · refresh credentials", value: "aws_refresh" }` is built at cli_inner_pretty.js:369751-369758 behind that gate. Selecting it fires telemetry `tengu_oauth_aws_refresh_launched` and drives a small state machine: `aws_refresh_running` (cli_inner_pretty.js:369842, renders *"Running awsAuthRefresh…"*) → `aws_refresh_done` (cli_inner_pretty.js:369849).

**Before / after.** All signals are net-new: `aws_refresh` 0→7, `tengu_oauth_aws_refresh_launched` 0→1, `aws_refresh_done` 0→3 between 183 and 193. 183 had the `awsAuthRefresh` setting and the security-trust guard (cli_inner_pretty.js:135849) but **no `/login` menu entry** to invoke it on demand.

**Why.** AWS SSO/STS credentials expire mid-session; before this you had to restart or re-run the refresh script out-of-band. Surfacing it as a `/login` action — only when a refresh script is actually configured — lets a user top up expired credentials without leaving the CLI. Confidence: high (fully isolable, gate + state machine + telemetry all verified).
