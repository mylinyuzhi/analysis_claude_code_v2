# v2.1.143 — Source Diff Analysis

**Theme:** A **background-agent reliability + plugin-dependency-graph** release. The headline features are **plugin dependency enforcement** (`claude plugin disable` refuses when something still depends on the target; `claude plugin enable` force-enables transitive deps), the **`worktree.bgIsolation: "none"`** escape hatch (let bg sessions edit the working copy directly), **PowerShell `-ExecutionPolicy Bypass`** by default, and a **stop-hook block cap** (end the turn after 8 consecutive blocks). Around those sit a long tail of **bg flag-preservation fixes** — `--mcp-config`, `--settings`, `--add-dir`, `--plugin-dir`, `--strict-mcp-config`, `--fallback-model`, `--allow-dangerously-skip-permissions`, model, and effort now all survive `--bg`/`←`-detach and retire→wake — plus the **`/goal` evaluator deferral** while background shells/subagents are still running.

The release is best read as **the patch set that makes the v2.1.139–142 `claude agents`/`--bg` surface actually preserve the user's intent across the daemon's respawn boundary**, while wiring up the first real plugin dependency graph.

## 1. Plugin dependency enforcement (NEW)

**Type:** feature · **Modules:** Plugins

`claude plugin disable` / `enable` (and the `/plugin` UI) now consult a real dependency graph built from each plugin manifest's `dependencies` array.

- **Disable** refuses if any *enabled* plugin still depends on the target, and emits a copy-pasteable disable-chain hint (`claude plugin disable A && claude plugin disable B && …`).
- **Enable** computes the forward-dependency closure and force-enables the transitive deps, reporting missing/blocked/scope-shadowed deps with actionable messages.

Both directions live in one function, `togglePlugin` (`vs6`) (cli_inner_pretty.js:483804), with the dependency graph helpers `reverseDependents` (`I58`) (cli_inner_pretty.js:222981), `disableChainOrder` (`MA7`) (cli_inner_pretty.js:222993), `forwardDependencyClosure` (`JA7`) (cli_inner_pretty.js:223077), and `enabledPluginSet` (`ONH`) (cli_inner_pretty.js:223010).

| | |
|---|---|
| **Type** | Feature (plugin dependency graph) |
| **Modules touched** | Plugins, `/plugin` UI |
| **Before** | Disabling a plugin that another plugin depended on broke the dependent silently. Enabling a plugin did not pull in its dependencies; the user had to enable each one by hand and discover the chain by trial and error. |
| **After** | `disable` is blocked with `"<name> is still required by X, Y. Disable those plugins first, or disable everything together: claude plugin disable …"`. `enable` walks the closure, refuses with install/unblock/enable-at-scope hints when a dep is missing/policy-blocked/shadowed-disabled, otherwise force-enables the deps and appends `(also enabled N dependencies: …)`. |
| **Why** | A dependency graph without enforcement is just metadata. Enforcing it on the enable/disable transitions is the only place the user actually toggles state, so it's where breakage is prevented. The disable-chain hint turns a frustrating "why won't this turn off" into one paste. |

## 2. `worktree.bgIsolation: "none"` setting (NEW)

**Type:** feature · **Modules:** Background, Worktrees, Permissions

A new repo-level setting (`.claude/settings.json` → `"worktree": {"bgIsolation": "none"}`) lets background sessions edit the working copy directly instead of being forced through `EnterWorktree`. The worktree-isolation guard `worktreeIsolationViolation` (`esH`) consults it and short-circuits when isolation is off.

The setting is validated by the schema `bgIsolation: y.enum(["none", "worktree"]).optional()` (cli_inner_pretty.js:184360), read via `resolveBgIsolation` (`Eu6`) (cli_inner_pretty.js:346655) — which also honors a `CLAUDE_BG_ISOLATION` env override — and persisted into the bg session's task state so it survives respawn (cli_inner_pretty.js:184219, 541225-541228, 541760, 541857).

| | |
|---|---|
| **Type** | Feature (settings + guard bypass) |
| **Modules touched** | Background, Worktrees, Permissions (`Edit`/`Write` guard) |
| **Before** | Every bg session was forced to call `EnterWorktree` and isolate into a linked worktree before editing. For repos where worktrees are impractical (submodule-heavy, network-drive, generated checkouts, LFS), this was a hard wall: edits to the shared checkout were blocked with "this background session hasn't isolated its changes yet." |
| **After** | Set `"worktree": {"bgIsolation": "none"}` (or `CLAUDE_BG_ISOLATION=none`) and the guard returns `null` (allow) for shared-checkout writes. The guard's own error text now even tells you the escape hatch. Subagents inherit the parent's `bgIsolation`. |
| **Why** | The worktree-isolation guard (added so concurrent bg sessions don't stomp the shared checkout) is correct as a *default* but wrong as a *mandate* for repos that can't use worktrees. An explicit per-repo opt-out preserves safety-by-default while unblocking the long tail. |

## 5. `/goal` evaluator no longer fires while background work is running

## 6. Background sessions preserve model and effort after waking from idle

**Type:** fix · **Modules:** Background, Model

A bg session woken from idle could revert to default model/effort. The fix is the **respawn-flag preservation** machinery: the session's launch flags are captured by `preserveRespawnFlags` (`uwz`) / `extractValuedFlags` (`zH9`) (cli_inner_pretty.js:542476, 542542) into `respawnFlags`, persisted in task state (cli_inner_pretty.js:184218, 541844), and replayed on respawn. `--model`/`-m` and `--effort` are members of the preserved value-flag set `valuedRespawnFlags` (`hqq`) (cli_inner_pretty.js:542624-542668).

| | |
|---|---|
| **Type** | Fix (state preservation across wake) |
| **Before** | After a bg session retired and was woken (respawned), the `--model`/`--effort` the user had set were dropped — the worker came back on the daemon default. |
| **After** | Model and effort are part of `respawnFlags` and replayed verbatim on wake. |
| **Why** | The daemon respawns a bg worker as a fresh `claude` process; anything not in the persisted `respawnFlags` is lost. Adding model/effort to the preserved whitelist makes wake idempotent w.r.t. user choice. |

This is the same mechanism behind bullets 16, 18, 19, and 21 below — see §16 for the flag whitelist code. **Confidence: high** (whitelist + persistence read directly; model/effort are explicit members).

## 7. Shift+Tab in attached agent sessions includes auto mode

**Type:** fix · **Modules:** Permissions, Agent view

The Shift+Tab permission-mode cycle is computed by `nextPermissionMode` (`QCH`) (cli_inner_pretty.js:578712), which inserts `auto` into the cycle when `canCycleToAuto` (`PR8`) (cli_inner_pretty.js:578696) returns true — and that predicate keys off `ctx.isAutoModeAvailable`. In attached `claude agents` sessions, `isAutoModeAvailable` was not being propagated, so the cycle skipped auto. The fix flows `isAutoModeAvailable` (cli_inner_pretty.js:442951) into the attached session's permission context so `default → acceptEdits → plan → [bypass] → auto → default` includes auto.

**Before:** attaching to a bg agent and pressing Shift+Tab cycled through default/acceptEdits/plan (and bypass if available) but never auto, even when auto mode was available.
**After:** auto is part of the cycle in attached sessions. **Cross-reference:** `37_permission_policy/`. **Confidence: medium** (cycle/predicate read directly; the exact attach-context propagation is inferred from `isAutoModeAvailable` plumbing).

## 8. Corrupt `.credentials.json` with non-array `scopes` no longer hangs

**Type:** fix · **Modules:** Auth

When consuming an auth snapshot, scopes are only applied if they are actually an array (cli_inner_pretty.js:92783): `if ((Pt(K.accessToken), Array.isArray(K.scopes))) C7$(K.scopes);`. A non-array `scopes` value is silently ignored instead of crashing the scope-set construction.

**Before:** a `.credentials.json` with a malformed `scopes` (e.g. a string or object) hung the CLI on startup or silently aborted OAuth token refresh, because downstream scope code assumed an array.
**After:** `Array.isArray(scopes)` guards the apply; the access token still loads, scopes default to empty if malformed. **Confidence: high.**

## 16. `/bg` preserves `--mcp-config`/`--settings`/`--add-dir`/`--plugin-dir`/`--strict-mcp-config`

**Type:** fix · **Modules:** /bg, MCP, Settings

The respawn-flag preservation whitelist is the backbone of every "bg now preserves --X" bullet in this release. `valuedRespawnFlags` (`hqq`) holds value-taking flags; `booleanRespawnFlags` (`pwz`) holds boolean flags; `preserveRespawnFlags` (`uwz`) strips only session-management flags and keeps the rest.

```javascript
// ============================================
// respawnFlagWhitelist - flags carried across --bg / detach / respawn
// Location: cli_inner_pretty.js:542624-542676 (extractor 542476-542495)
// ============================================

// ORIGINAL (for source lookup):
hqq = new Set([
  "--exec","--model","-m","--permission-mode","--agent","--agents","--routine","--effort",

  "--plugin-dir","--plugin-url","--resume-session-at","--rewind-files","--thinking","--thinking-display"]);
pwz = new Set([
  "--dangerously-skip-permissions","--allow-dangerously-skip-permissions","--strict-mcp-config",
  "--dangerously-allow-browser-network-access","--disable-slash-commands","--reply-on-resume"]);

function uwz(H) {  // strip only session-management flags, keep everything else
  let $ = [];
  for (let q = 0; q < H.length; q++) {
    let K = H[q];
    if (K === "--fork-session" || K === "-c" || K === "--continue"
        || K.startsWith("--resume=") || K.startsWith("-r=") || K.startsWith("--session-id=")) continue;
    if (K === "--resume" || K === "-r" || K === "--session-id") {
      if (H[q + 1] !== void 0 && !H[q + 1].startsWith("-")) q++;
      continue;
    }
    $.push(K);
  }
  return $;
}

// READABLE (for understanding):
const valuedRespawnFlags  = new Set([/* --model, --effort, --add-dir, --mcp-config, --settings,
                                        --setting-sources, --fallback-model, --plugin-dir, … */]);
const booleanRespawnFlags = new Set([/* --strict-mcp-config, --allow-dangerously-skip-permissions, … */]);
function preserveRespawnFlags(argv) {
  const kept = [];
  for (let i = 0; i < argv.length; i++) {
    const arg = argv[i];
    if (isSessionMgmtFlag(arg)) {                 // --session-id / --resume / --fork-session / -c
      if (takesValue(arg) && argv[i + 1] && !argv[i + 1].startsWith("-")) i++;  // skip its value too
      continue;
    }
    kept.push(arg);                               // everything else is preserved
  }
  return kept;
}

// Mapping: hqq→valuedRespawnFlags, pwz→booleanRespawnFlags, uwz→preserveRespawnFlags
```

**Before:** backgrounding/detaching dropped `--mcp-config`, `--settings`, `--add-dir`, `--plugin-dir`, `--strict-mcp-config` — the worker came back without its MCP servers, custom settings, extra dirs, or strict-config enforcement.
**After:** all of them are in the preserved set (or filtered *in* by keeping everything that isn't a session-id flag), so the respawned worker keeps its full configuration.
**Why this is the right shape:** rather than maintaining a *deny*-list of flags to drop (which silently loses any new flag), `preserveRespawnFlags` keeps *everything* except the three session-identity flags that must change on respawn. New flags are preserved by default. **Cross-reference:** `36_background_agents/`. **Confidence: high.**

## Summary

v2.1.143 is two things at once. First, it **builds and enforces the plugin dependency graph**: `claude plugin disable`/`enable` now refuse or force-enable based on `dependencies` metadata, with copy-pasteable chains and scope-aware error messages — the central function `togglePlugin` (`vs6`) wires the reverse-dependents, disable-chain-order, and forward-closure helpers into the only place plugin state actually toggles. Second, it **finishes the background-agent intent-preservation arc** started in v2.1.139–142: the respawn-flag whitelist (`hqq`/`pwz` + `uwz`) now carries model, effort, `--mcp-config`, `--settings`, `--add-dir`, `--plugin-dir`, `--strict-mcp-config`, `--fallback-model`, and bypass-permissions across `--bg`/detach/wake, and `permissions.defaultMode` is honored for dispatched sessions.

The two notable *safety* moves are the **stop-hook block cap** (an unbounded blocking Stop hook is uniquely dangerous, so it gets an 8-block escape with `stop_hook_active` guidance) and the **worktree cleanup no longer `rm -rf`-ing** a path git itself refused to remove (keep + warn instead of destroy). The most user-visible new knob is **`worktree.bgIsolation: "none"`** — an explicit per-repo opt-out of the worktree-isolation mandate for repos where worktrees are impractical — which preserves the safe default while unblocking the long tail. **PowerShell `-ExecutionPolicy Bypass`** rounds it out: the agent's own permission layer is the real gate, so the OS interactive-user policy is bypassed process-scoped, with an env opt-out for audited orgs.
