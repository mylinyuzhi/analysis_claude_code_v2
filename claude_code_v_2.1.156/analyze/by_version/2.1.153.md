# v2.1.153 — Source Diff Analysis

**Theme:** **Plugin/marketplace ergonomics, install-health legibility, and a deep `claude agents` / background-session polish pass — plus two pointed correctness fixes (custom-gateway OAuth credential leak, stateful-MCP reconnect loop).** The headline-by-volume content of 2.1.153 is the largest single-version background/agent-view fix batch in the window: nearly twenty `claude agents` / `claude --bg` reliability and rendering fixes. On top of that sit a handful of genuinely new surfaces — the `skipLfs` marketplace-source option, `COLUMNS`/`LINES` injected into status-line commands, the `claude agents` dispatch-input autocomplete now drawing from native slash commands + bundled skills (not just project skills), a one-time "can't auto-update" notice for npm-global installs, and `claude doctor` reporting your last update attempt. The release also flips the **`/model` default-save semantics** (now `enter` = set-as-default, `s` = this-session-only) — the mirror image of v2.1.144's `d`-key behavior — and renames the `modelPicker:setAsDefault` keybinding to `modelPicker:thisSessionOnly`.

This reads as the **"make plugins/marketplaces, install health, and the still-young background-agents surface behave"** patch — heavy on fixes, with a thin layer of small but useful new capabilities. It is the last maintenance release before the 2.1.154 flagship (Opus 4.8 + dynamic workflows + lean prompt).

> Deeper coverage of the background/agent-view subsystem these fixes touch lives in `../36_background_agents/` (daemon lifecycle, worker state machine, worktree isolation). MCP-related items cross-reference `../00_overview/symbol_index_infra_platform.md`.

## 1. `skipLfs` marketplace-source option (NEW)

**Type:** feature · **Modules:** Plugins, Marketplace, Git

### TL;DR

`github`- and `git`-sourced plugin marketplaces gained an optional `skipLfs: boolean`. When set, every clone/pull for that marketplace runs with `GIT_LFS_SKIP_SMUDGE=1`, so Git LFS pointer files stay as pointers instead of downloading their (potentially huge) backing objects. This is for marketplaces hosted in repos that happen to carry large LFS assets the plugin tooling never needs.

### How it works

**Step 1 — Schema.** Both the `github` and `git` marketplace-source Zod schemas now declare `skipLfs` alongside the existing `ref`/`path`/`sparsePaths` fields (cli_inner_pretty.js:50410-50415 for `github`, cli_inner_pretty.js:50434-50439 for `git`). The describe text spells out the exact mechanism — it sets `GIT_LFS_SKIP_SMUDGE=1`.

**Step 2 — Threading the flag through clone/pull.** The git pull helper merges `GIT_LFS_SKIP_SMUDGE: "1"` into the subprocess env only when `skipLfs` is truthy (cli_inner_pretty.js:414950). The same `{ skipLfs }` object is threaded through the whole clone/update/sparse-checkout call chain — `KI_` (sparse-checkout), `HI_` (pull), `qI_` (clone), and `fqH` (the per-source fetch primitive) all receive and forward it (cli_inner_pretty.js:415193, 415196, 415253, 415393-415444).

## 2. Status-line commands receive `COLUMNS` and `LINES` (NEW)

**Type:** feature · **Modules:** Status line, Hooks (command execution)

### TL;DR

Status-line command scripts (and the shared command-execution path that backs them) now get `COLUMNS` and `LINES` in their environment, populated from the live terminal dimensions. A status-line script can finally size its output to the terminal width instead of guessing or shelling out to `tput`.

## 4. `claude agents` PR column: `PR #N` for one, `N PRs` for many (NEW)

## 7. Custom API gateway no longer receives the user's Anthropic OAuth credential

**Type:** fix (security/correctness) · **Modules:** API client, Auth

### TL;DR

A regression let a **custom API gateway** (a third-party endpoint configured via `ANTHROPIC_BASE_URL` + its own auth token) receive the user's **Anthropic OAuth credential** instead of the gateway's own token. 2.1.153 ensures the OAuth access token is only attached on the genuine first-party / claude.ai path, and that the presence of a user-supplied gateway token suppresses OAuth.

### How it works

Auth-method selection in the first-party client constructor (`createFirstPartyClient`, `sB`, cli_inner_pretty.js:129593) hinges on two predicates:

- `oauthEnabled` (`J = qfK({ anthropicAuthEnabled: Gj(), oauthScopes: D?.scopes })`, cli_inner_pretty.js:129619). `isAnthropicAuthEnabled` (`Gj`, cli_inner_pretty.js:130831-130848) returns **false** when a user-supplied token source is present and is *not* a managed/login-injected one: line 130846 `Y = ((K || z) && !bO$()) || ((q || A) && !hQH())`, where `K` is `ANTHROPIC_AUTH_TOKEN`, `z` is an `ANTHROPIC_API_KEY`/`apiKeyHelper` source, and `bO$`/`hQH` distinguish managed (remote/host-injected) tokens from genuine user gateway tokens. When `Y` is true (a real custom token), `Gj()` returns false → `oauthEnabled` false.
- The fallback OAuth-credential leg (cli_inner_pretty.js:129762) attaches `authToken: D?.accessToken` **only when `oauthEnabled` is true**: `let W = { apiKey: J ? null : Z, authToken: J ? D?.accessToken : void 0, ... }`. With `oauthEnabled` false, the gateway gets `apiKey: Z` (the user's gateway key) and `authToken: undefined` — the OAuth token is never sent.

Likewise the bearer-token header attach (`attachAuthHeader`, `Fe1`, cli_inner_pretty.js:129765-129768) is guarded by `if (!J && !If())` (cli_inner_pretty.js:129620) — skipped when OAuth is enabled and when a Cloud gateway is active (`If()`).

## 8. Stateful MCP servers without the optional GET SSE stream no longer reconnect-loop on `tools/list`

**Type:** fix (regression from v2.1.147) · **Modules:** MCP

**Before:** A stateful (session-bearing) MCP server that does *not* implement the optional GET SSE stream would, since v2.1.147, fall into a reconnect loop when `tools/list` was issued — the client expected the SSE channel and kept reconnecting when it wasn't there. The MCP client carries explicit reconnect machinery (`reconnectAttempts`/`reconnectDelay`/exponential backoff, cli_inner_pretty.js:10792-10880); the regression caused it to fire spuriously for GET-SSE-less servers.

**After:** Absence of the optional GET SSE stream is treated as a valid configuration; `tools/list` completes without triggering the reconnect path.

**Why this is subtle:** The MCP spec makes the server→client GET SSE stream optional. v2.1.147's transport rework implicitly assumed it. Stateful servers that reply to POSTs but never open an SSE channel are spec-compliant, so a missing stream must not be read as "connection dropped."

## 9. Subagent frontmatter MCP servers now respect strict/managed MCP policy

**Type:** fix · **Modules:** MCP, Subagent (Agent tool), Permissions

**Before:** MCP servers declared in a subagent's (Agent-tool) frontmatter bypassed `--strict-mcp-config`, `--bare`, remote mode, enterprise managed-MCP config, and managed-settings MCP allow/deny policy. A subagent could spin up MCP servers an admin had blocked at the org level.

**After:** Frontmatter-declared subagent MCP servers go through the same gating as any other MCP server: `--strict-mcp-config` (strictMcpConfig, parsed at cli_inner_pretty.js:87-88, threaded at 111/120), `--bare`, remote mode, managed config, and allow/deny policy all apply.

**Why:** A subagent is still the user's process; its MCP surface must obey the same enterprise and CLI-flag constraints as the main session. Letting frontmatter punch through `--strict-mcp-config` defeated the whole point of strict mode.

## 10. `--strict-mcp-config` keeps inline `mcpServers` on explicitly-passed agents + warns on blocked servers

**Type:** fix · **Modules:** MCP, Agent definitions

**Before:** `--strict-mcp-config` over-applied: it stripped inline `mcpServers` even from agent definitions the user explicitly passed (`--agents` / SDK `agents`). And when a subagent MCP server *was* blocked, it was dropped silently.

**After:** `--strict-mcp-config` no longer strips inline `mcpServers` from explicitly-passed agent definitions (those are user-authored, not ambient discovery), and a blocked subagent MCP server now surfaces a visible warning instead of vanishing.

**Why:** `--strict-mcp-config` exists to suppress *ambient/discovered* MCP config, not config the user typed on the command line or handed to the SDK. The silent-drop made blocked servers impossible to diagnose; the warning closes that gap.

## 11. `/bg` while Claude is responding continues the response in the background session

**Type:** fix · **Modules:** /bg, Background sessions

**Before:** Invoking `/bg` *while Claude was mid-response* dropped the in-flight response — the work being streamed was lost when the session was forked to the background.

**After:** `/bg` issued during a response now continues that response in the background session instead of discarding it.

**Why:** The whole value of `/bg` mid-turn is "let this finish without blocking me." Dropping the response inverted that — the user backgrounded to *keep* the work, not lose it. The fix hands the in-progress response off to the forked worker.

**Confidence:** medium — described from the changelog and the `/bg` fork semantics; the exact handoff site is in the `/bg` command handler / session-fork path (in the broader background-session subsystem covered by `../36_background_agents/`) and does not carry a distinctive grep string in this build.

## 13. macOS background agents appear as "Claude Code" in Privacy & Security; grants survive upgrades

**Type:** fix · **Modules:** Background agents (macOS), Permissions

**Before:** macOS background-agent helper processes did not present a stable app identity in Privacy & Security, so permission grants (Full Disk Access, etc.) were tied to a transient identity and lost across upgrades — re-prompting after every update.

**After:** Background agents run under a stable bundle identity — `CFBundleDisplayName` "Claude Code", `CFBundleIdentifier` `com.anthropic.claude-code`, `LSUIElement` true (a UI-less agent) — defined in the embedded Info.plist (cli_inner_pretty.js:559006). macOS keys permission grants to this bundle, so they persist across upgrades.

**Why:** macOS TCC (Transparency, Consent, and Control) keys grants by bundle identity. A stable `CFBundleIdentifier` + display name is the prerequisite for grants surviving binary replacement.

## 15. Compact `claude agents` / `claude --bg` reliability and rendering fixes

## Summary

v2.1.153 is a **plugin/install-health + background-agents-stabilization** release. The new surfaces are small but practical: `skipLfs` decouples marketplace install cost from a repo's LFS payload via a one-line `GIT_LFS_SKIP_SMUDGE=1` passthrough; status-line scripts finally learn the terminal size through conventional `COLUMNS`/`LINES`; the agents dispatch input grows up to offer the same command vocabulary as the main prompt; and `/doctor` plus a one-time notice make npm-global auto-update failures legible instead of silent.

The two correctness fixes carry the most weight. The **custom-gateway OAuth credential** fix is a credential-exposure hardening — making "user supplied a custom token" decisively suppress the subscriber-OAuth path, so an arbitrary third-party gateway never sees a first-party bearer token. The **MCP** trio (GET-SSE reconnect loop, subagent-frontmatter policy bypass, `--strict-mcp-config` over-stripping) closes a regression and two policy-enforcement gaps that mattered for enterprise deployments.

Everything else is the by-now-familiar **background-agents polish arc** — nearly twenty fixes spanning daemon staleness, worktree isolation, clipboard/IME/repaint quirks across terminals, and memory/stdin edge cases. Combined with the `/model` default-save flip (mirroring the IDE), 2.1.153 is the clean-up that clears the deck for the 2.1.154 flagship (Opus 4.8, dynamic workflows, lean prompt).
