## 2. Dynamic workflows + `/workflows` (NEW — the flagship feature)

**Type:** feature · **Modules:** Workflow tool, Coordinator, Subagent orchestration, `/workflows`

### TL;DR

A brand-new **`Workflow`** tool lets Claude author a small JavaScript script that *deterministically orchestrates* many subagents — `agent()`, `pipeline()`, `parallel()`, `phase()`, `log()`, plus a shared token `budget` and a `workflow()` sub-invocation primitive. Workflows run **in the background**: the tool returns immediately with a task ID, agents fan out (concurrency capped at `min(16, cores−2)` per workflow; lifetime cap 1000 agents), and a `<task-notification>` arrives on completion. `/workflows` browses running and completed runs. It's strictly opt-in: Claude only calls `Workflow` when the user explicitly asks for multi-agent orchestration (the "workflow" keyword, an `ultracode` standing opt-in, an explicit "fan out agents" ask, or a skill/saved-workflow that invokes it).

## 11. Opus 4.8 thinking-block hotfix (2.1.156)

## Summary

v2.1.154 is the flagship of the 2.1.143→2.1.156 window: **Opus 4.8** arrives across every provider as the new top model, defaulting to `high` effort with `/effort xhigh` reserved for the hardest work, and it's paired with the release's marquee capability — **dynamic workflows**, a `Workflow` tool whose description is effectively a complete deterministic-orchestration DSL (`agent`/`pipeline`/`parallel`/`phase`/`budget`/`workflow`, concurrency cap `min(16, cores−2)`, 1000-agent lifetime backstop, journal/resume), monitored via `/workflows`. The determinism constraints (no `Date.now()`/`Math.random()`) are what make resume and a hard token budget possible — the single cleverest decision in the release.

Surrounding the headline are several thoughtfully-gated quality changes: the **lean system prompt** becomes the per-model default (lean for Opus 4.8 and newer, verbose for Haiku/Sonnet/Opus 4.7-and-earlier — a capability-tiered rollout, not a flat flip), **`AskUserQuestion`** is reserved for decisions Claude genuinely can't make, **fast mode** moves to Opus 4.8 at 2×/2.5× while the 4.6 override env var is deprecated, `/simplify` is split cleanly back to cleanup-only, and the `/effort` slider gets clearer Faster/Smarter labels. `claude agents` gains the `! <command>`/`--exec` shell-background gesture and stops mis-routing `/logout`.

The fix tail is substantial and security-relevant: the auto-mode classifier learns to flag **bulk repository exfiltration**, the `rm -rf $HOME` guard closes a **trailing-slash bypass**, managed-settings MCP policy switches to **per-entry validation** so one typo can't discard a whole allow/deny list, and a cluster of background-agent reliability bugs (1M out-of-context, pinned-respawn churn, stuck-state retirement, worktree-isolation bypass, orphaned pty-host CPU) get resolved. **2.1.156**, the only follow-up in this pair, is a single targeted hotfix: detect the Opus-4.8 "thinking block cannot be modified" 400 and recover by stripping the stale signed thinking blocks and retrying. Together the two releases read as "ship the flagship, then immediately harden the one rough edge it exposed."
