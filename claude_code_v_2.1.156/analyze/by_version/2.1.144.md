# v2.1.144 — Source Diff Analysis

**Theme:** Background sessions become first-class in `/resume` (listed and marked `bg`), background subagent completion notifications gain elapsed-duration suffixes, `/model` flips to **session-only by default** (with `d` to set a new-session default), a startup hang when `api.anthropic.com` is unreachable is fixed by timing out side-channel calls, and a long tail of background attach/scroll/rendering fixes lands. Plus the rename of **"extra usage" → "usage credits"** (`/extra-usage` → `/usage-credits`).

This release is best read as **the background-session UX maturation patch**: 2.1.143 made backgrounding configurable; 2.1.144 makes backgrounded work *visible and resumable* through the normal session surfaces.

> Caveat on `/model`: the 2.1.144 behavior described in §3 (session-only default + `d` for default) was **reverted in 2.1.153**, which restored "default for new sessions" as the primary action and moved session-only to `s`. The 2.1.156 bundle under analysis therefore shows the *post-2.1.153* wiring. Where that matters, this doc cites the current 2.1.156 lines and flags the reversal explicitly.

## 2. Elapsed duration in background subagent completion notifications (NEW)

**Type:** feature · **Modules:** Background subagents, Notifications

### How it works

When a (background) subagent finishes, Claude Code already tracked `totalDurationMs` on the completion record (cli_inner_pretty.js:279166). v2.1.144 surfaces that elapsed time to the user by passing it through the human-friendly duration formatter `formatDuration` (`iK`), which produces strings like `3h 2m 5s`.

## 5. Startup hang (up to 75s) when `api.anthropic.com` is unreachable

**Type:** fix · **Modules:** Startup, Networking

**Before:** On a captive portal / firewall / VPN where `api.anthropic.com` was reachable for TCP connect but not actually responsive, startup-time **side-channel** API calls (auth/roles/utilization probes) had no aggressive timeout and could block the CLI from becoming interactive for up to ~75 seconds.

**After:** Side-channel API calls now time out after 15s, so the CLI proceeds (degraded) instead of hanging. The relevant machinery uses `AbortSignal.timeout(...)`/`timeout:`-bounded fetches throughout the API client layer (e.g. the Anthropic client wrapper applies `AbortSignal.timeout(1e4)` at cli_inner_pretty.js:101257; org/roles/utilization HTTP probes use `timeout: 15000` at cli_inner_pretty.js:372496, 372536, 372585, 372612).

**Why this is subtle:** The hang is not a connect failure (which fails fast) — it's a *responsive-but-silent* endpoint. Without a request-level deadline, the promise never settles and the startup sequence that awaits it stalls. Capping each side-channel call at 15s bounds worst-case startup latency.

**Confidence (medium):** the behavior and the 15s timeout idiom are verified, but the single startup-preflight call-site that the changelog refers to is not uniquely isolated in the obfuscated bundle (multiple side-channel calls now carry 15s deadlines); the cited lines are the verified timeout machinery, not a guaranteed one-to-one match to the fixed call.

## 6. Bash search no longer reports spurious failures: `head`/`tail` satisfy read-before-edit; `egrep`/`fgrep`/`git grep`/`git diff` "no matches" isn't a failure

## 7. Unrecoverable conversation when an image's extension doesn't match its content

## 13. Terminal rendering self-heals after missed resize / progressive corruption

**Type:** fix · **Modules:** Renderer

Three related rendering fixes:
- Garbled output after a **missed window-resize** event (e.g. dragging a VS Code split-pane divider) now self-heals on the next frame instead of requiring `Ctrl+L`.
- Progressive display corruption (stale/garbled glyphs) in very long sessions, previously clearing only on resize/restart, is fixed.
- VS Code rendering glitches reduced by **lowering the thinking-spinner's animation color count** (the same lever 2.1.156 later tightened further — "capping the number of distinct colors the thinking spinner produces").

**Why:** Terminal renderers diff against an internal model of the screen; a missed resize desyncs that model. Self-healing on the next frame re-establishes the baseline. Fewer distinct spinner colors reduces VS Code's per-cell repaint churn that triggered corruption.

## Summary

v2.1.144 is the patch that makes **background work visible through the normal session surfaces**: backgrounded sessions now show up (and are labeled `bg`) in `/resume`, and their completion notifications carry an elapsed-duration suffix so you can gauge what happened while you were away. The one notable *behavior* change — `/model` defaulting to session-only with `d` for the new-session default — was short-lived: 2.1.153 reversed it back to "default for new sessions" with `s` for session-only, which is the wiring visible in the 2.1.156 bundle, so this doc documents the 2.1.144 intent and the current-bundle reality side by side.

The reliability work splits cleanly: a genuinely impactful **startup-hang fix** (15s deadline on side-channel calls so a captive portal / dead VPN no longer freezes the CLI for over a minute), a satisfying **Bash search-error cleanup** (grep/diff exit-1 is data, not failure; `head`/`tail` count as reads — both directly cross-validated against v2.1.88's `commandSemantics.ts`), an **image read** that degrades to text instead of bricking the conversation, and a long tail of background attach/scroll/rendering fixes weighted toward Windows. The "extra usage → usage credits" rename is pure copy, but pervasive. Together the release rounds off the background-session arc that 2.1.143 began, ahead of the flagship 2.1.154 (Opus 4.8 + dynamic workflows + lean prompt).
