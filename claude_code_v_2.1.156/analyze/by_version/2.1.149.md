# v2.1.149 — Source Diff Analysis

**Theme:** **Cost legibility + display polish + a tight cluster of PowerShell / sandbox permission-hardening fixes.** The headline feature is the **`/usage` per-category breakdown** — the CLI now attributes your token spend to the *skills, subagents, plugins, and per-MCP-server* that drove it, turning an opaque "you used N%" into "X% came from MCP server Y / plugin Z / subagents under W." Alongside it: **`/diff` detail view becomes keyboard-scrollable** (arrows, `j`/`k`, PgUp/PgDn, Space, Home/End), **GFM task-list checkboxes render in markdown output** (`- [ ]` / `- [x]` instead of plain bullets), the **`allowAllClaudeAiMcps` enterprise managed setting**, and a security-flavored batch of fixes: a **PowerShell built-in `cd` permission bypass** (`cd..`, `cd\`, `cd~`, `X:`), the **sandbox write-allowlist over-broadening in git worktrees**, stale `PWD`/`OLDPWD`/`DIRSTACK` variable-tracking, PowerShell prefix/wildcard allow rules, and a macOS `find` vnode-table exhaustion crash.

This release reads as the **"make spend and display behave, and close the PowerShell/sandbox permission gaps"** patch — a maintenance-heavy version with one substantial new observability surface.

## 1. `/usage` per-category breakdown — what's driving your limits (NEW)

**Type:** feature (observability) · **Modules:** Usage/cost reporting, Telemetry, Permissions (attribution)

### TL;DR

`/usage` previously summarized spend by model. v2.1.149 adds a second, richer view: **"What's contributing to your limits usage?"** — a breakdown by **Skills**, **Subagents**, **Plugins**, and **MCP servers**, each with a top-line callout ("`X% of your usage came from MCP server "Y"`") and tailored advice. The data is built from a per-request **attribution** mechanism that stamps every LLM call with the skill/agent/plugin/MCP-server that triggered it, then aggregates locally.

### How it works

## 5. PowerShell built-in `cd` permission bypass (SECURITY FIX)

**Type:** fix (security) · **Modules:** Permissions, PowerShell parser · cross-ref [`37_permission_policy/`](../37_permission_policy/)

### How it works

PowerShell's directory-change detection previously relied on an alias/cmdlet name map (`cd` → `Set-Location`, etc.). But PowerShell ships **built-in convenience functions** whose names *concatenate* the verb and argument with no space: `cd..`, `cd\`, `cd/`, `cd~`, and bare drive-letter switches like `X:`. These tokenize as a single command name that the alias map doesn't recognize as a directory change — so the permission analyzer's path-validation cwd went stale and a later command in the same compound could read outside the workspace undetected.

The fix adds an explicit literal check to `isDirectoryChangingCommand` (`_v$`) before the alias-map lookup:

```javascript
// ============================================
// isDirectoryChangingCommand - now catches PowerShell built-in cd forms
// Location: cli_inner_pretty.js:417684-417695
// ============================================

// ORIGINAL (for source lookup):
function _v$(H) {
  let $ = H.toLowerCase();
  if ($ === "cd.." || $ === "cd\\" || $ === "cd/" || $ === "cd~" || /^[a-z]:$/.test($)) return !0;
  let q = EY(H);
  return (
    q === "set-location" || q === "push-location" || q === "pop-location" ||
    q === "new-psdrive" || (n$() === "windows" && (q === "ndr" || q === "mount"))
  );
}

// READABLE (for understanding):
function isDirectoryChangingCommand(name) {
  let lower = name.toLowerCase();
  // NEW in 2.1.149: PowerShell built-in functions concatenate verb+arg with no space.
  if (lower === "cd.." || lower === "cd\\" || lower === "cd/" || lower === "cd~" || /^[a-z]:$/.test(lower)) return true;
  let canonical = resolveCmdletAlias(name);                 // cd→set-location, sl→set-location, …
  return (
    canonical === "set-location" || canonical === "push-location" || canonical === "pop-location" ||
    canonical === "new-psdrive" || (platform() === "windows" && (canonical === "ndr" || canonical === "mount"))
  );
}

// Mapping: _v$→isDirectoryChangingCommand, EY→resolveCmdletAlias, n$→platform
```

| | |
|---|---|
| **Type** | Fix (permission bypass / security) |
| **Before** | `cd..`/`cd\`/`cd/`/`cd~`/`X:` were not recognized as directory changes, so the permission analyzer kept validating later commands against the *old* cwd — a later read could escape the workspace. (v2.1.88 `hasDirectoryChange` relied purely on `DIRECTORY_CHANGE_CMDLETS`/`DIRECTORY_CHANGE_ALIASES` maps — `/lyz/codespace/3rd/claude-code/src/utils/powershell/parser.ts:1578`.) |

**Confidence: high** — precursor `hasDirectoryChange` in v2.1.88 confirmed; the literal-form check is the 2.1.149 addition.

## 6. Sandbox write-allowlist over-broadening in git worktrees (SECURITY FIX)

**Type:** fix (security) · **Modules:** Sandbox, Worktrees, Permissions · cross-ref [`37_permission_policy/`](../37_permission_policy/), [`36_background_agents/`](../36_background_agents/)

### How it works

The sandbox scanner `buildGitDenyPaths` (`R05`) walks the project tree with ripgrep and builds the set of paths that must be **denied** write access even inside an otherwise-allowed root — specifically `.git/hooks` and `.git/config` (writable hooks/config are an obvious RCE vector). For a **git worktree**, the `.git` entry is a *file* pointing at the shared git dir under the main repo. The bug: the deny-resolution treated a worktree's git path by adding the *whole worktree root segment* to the allow set, effectively granting write access across the main repository root, instead of scoping the deny to just the shared `.git` directory's `hooks/` and `config`.

The fixed loop matches each scanned path's `.git` segment and, when the segment is exactly `.git`, pushes only `{gitRoot}/hooks` or `{gitRoot}/config` to the deny list — never the whole repo:

```javascript
  let J = NL.default.resolve(_, D), X = !1;
```

## 8. Stale `PWD`/`OLDPWD`/`DIRSTACK` variable tracking across `cd`/`pushd`/`popd`

**Type:** fix (security) · **Modules:** Permissions (Bash variable tracking)

### How it works

The Bash permission analyzer statically tracks shell-variable values to validate paths. When a command runs `cd`/`chdir`/`pushd`/`popd`, the *values* of `PWD`/`OLDPWD` (and for `pushd`/`popd`, `DIRSTACK`/`dirstack`) become unknowable statically — but the analyzer was trusting their previously-tracked values. The fix marks them as **untracked** (the `iO` "unknown / cannot-statically-verify" sentinel) whenever such a command runs.

```javascript

// Bash var-tracking: invalidate PWD/OLDPWD/DIRSTACK on directory change
// Location: cli_inner_pretty.js:208562-208578
// ============================================

// ORIGINAL (for source lookup):
} else if (!f && (O === "cd" || O === "chdir" || O === "pushd" || O === "popd")) {
  let M = !1;
  if (O === "pushd" || O === "popd")
    for (let j = 1; j < Y.length; j++) {
      let w = Y[j];
      if (w === "--") break;
      if (/^-[a-zA-Z]*n[a-zA-Z]*$/.test(w)) { M = !0; break; }
      if (O === "popd" && (/^\+0*[1-9]/.test(w) || /^-0+$/.test(w))) { M = !0; break; }
    }
  if (!M) (q.set("PWD", iO), q.set("OLDPWD", iO));
  if (O === "pushd" || O === "popd") (q.set("DIRSTACK", iO), q.set("dirstack", iO));
}

    }
  if (!suppressed) { vars.set("PWD", UNTRACKED); vars.set("OLDPWD", UNTRACKED); }
```

**Why this is subtle:** the analyzer respects `pushd -n` / `popd +N` (which manipulate the stack *without* changing the actual cwd) — those don't invalidate `PWD`, only `DIRSTACK`. Marking the right variables untracked forces the analyzer to *re-prompt* rather than auto-approve a path it can no longer prove. **Confidence: high** (clear before/after in source).

## 9. macOS `find` exhausting the system file/vnode table

**Type:** fix · **Modules:** Shell snapshot / tool aliasing · cross-ref [`38_shell_snapshot`](../../../claude_code_v_2.1.142/analyze/38_shell_snapshot/)

The Bash tool routes `find` to a bundled `bfs` (a faster `find`) via a shell-function shim. `bfs` defaults to **breadth-first** search, which holds open a directory handle for every level/sibling simultaneously — on huge trees this exhausted the macOS kernel file/vnode table and could crash the host. The fix passes `-S dfs` (depth-first strategy) so the open-handle count stays bounded.

```javascript

// Location: cli_inner_pretty.js:340964-340977
// ============================================

    xx6("grep", "ugrep", ["-G", "--ignore-files", "--hidden", "-I", ...nD_.map((H) => `--exclude-dir=${H}`)],
        ["-*-filter*", "-*-pager*", "-*-view*", "-*-format-open*", "-*-config*", "---*", "-@*", "-*-save-config*"]),
  ].join("\n");
}

// READABLE (for understanding):
function buildToolShims() {

  return [

    "unalias grep 2>/dev/null || true",

              [/* passthrough patterns */]),
  ].join("\n");
}

// Mapping: iD_→buildToolShims, xx6→shellShim, RL→shimsEnabled, nD_→defaultExcludeDirs
```

The `-S dfs` argument is the fix: depth-first descent keeps the live directory-handle set small regardless of tree fan-out. **Confidence: medium** — the `-S dfs` flag clearly bounds handles and matches the bullet, but the exact "before" (default BFS) is inferred from `bfs` semantics, not visible as a diff in this single bundle.

## Summary

v2.1.149 is a **cost-legibility-plus-hardening** release. The one substantial new surface is the `/usage` per-category breakdown, which leans on a clean design choice: attribution is captured at request-dispatch time by parsing the invocation source string, then aggregated locally from `attribution-snapshot` data (no extra network calls, explicit "this machine only" disclaimer). Two purely declarative UX wins — `/diff` keyboard scrolling (one keybinding-map entry set) and GFM task-list checkboxes (one renderer branch) — round out the feature side.

The fix list is dominated by a coherent **PowerShell + sandbox permission-hardening theme**: the built-in `cd` bypass (`cd..`/`cd\`/`cd~`/`X:`), stale `PWD`/`OLDPWD`/`DIRSTACK` tracking, PowerShell prefix/wildcard allow rules, and the worktree write-allowlist over-broadening all close gaps where a directory change or path indirection let a later command escape its intended scope. The worktree allowlist fix in particular pairs with the 2.1.156 background-subagent worktree-isolation fix — together they tighten the "background/sandboxed work stays in its worktree" guarantee. The macOS `find` vnode fix (`-S dfs`) is a quiet stability win for users searching huge trees. 2.1.150 that follows is internal-only.
