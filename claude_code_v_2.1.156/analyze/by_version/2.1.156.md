## 1. Opus 4.8 thinking blocks modified → API errors (FLAGSHIP FIX)

**Type:** fix · **Modules:** LLM API, Thinking, Streaming

This is the one and only bullet for 2.1.156. Extended-thinking models return *signed* `thinking` blocks; on the next turn Claude Code must replay those blocks back to the API **byte-for-byte** so the server can verify the cryptographic `signature`. If anything in the client pipeline mutates a signed block (re-trims text, drops a sibling block, re-serializes), the server rejects the whole request with a 400 like *"signature in thinking block … cannot be modified."* Opus 4.8 (new default in 2.1.154) exercised this path far more aggressively than prior models, surfacing the bug.

The fix has two halves: a **detector** that recognises the specific 400, and a **reactive strip-and-retry** that removes every signed block from history and retries the request unsigned.

## 2. `effort` parameter 400 fix when `CLAUDE_CODE_ALWAYS_ENABLE_EFFORT` is set

**Type:** fix · **Modules:** Model selection, Effort

`CLAUDE_CODE_ALWAYS_ENABLE_EFFORT` is an override that forces the `effort` request parameter on. The bug: the override was checked **before** the legacy-model exclusion list, so it would also force `effort` onto models that don't accept the parameter (claude-3.x, Opus 4.0/4.1, Sonnet 4.0/4.5, Haiku 4.5) → API 400. The fix reorders the checks so unsupported models short-circuit to `false` **first**.

## 3. Improved auto-mode classifier exfiltration detection (bulk repo transfers)

**Type:** behavior · **Modules:** Permissions (auto mode classifier)

## 5. `rm -rf $HOME` blocked even when `HOME` has a trailing slash

**Type:** fix · **Modules:** Permissions (dangerous-path detection)

The dangerous-path detector compares a candidate path against the user's home directory and the filesystem root. ## 8. Orphaned `claude --bg-pty-host` no longer spins at 100% CPU (macOS)

## Summary

v2.1.156 is a **single-bullet public release riding a much larger hardening sweep.** The headline fix — Opus 4.8 thinking blocks being modified and triggering API 400s — is resolved with a detect-strip-retry safety net (`B87` → `cG4`/`gG4` → `retry:thinking-signature-strip`) that complements the proactive trimming already present in the 2.1.152 line. Because Opus 4.8 became the default model in 2.1.154, this was a real-world reliability fix, not a corner case.

Underneath, three independent permission/safety fixes stand out for their care: the dangerous-path detector now normalises trailing slashes on **both** the candidate and `$HOME` (`PlH`), the `effort`-support check moves its model deny-list **ahead** of the `CLAUDE_CODE_ALWAYS_ENABLE_EFFORT` override (mirroring the v2.1.88 `utils/effort.ts` precursor that had the ordering wrong), and managed-settings MCP policy now validates **per element** so one typo no longer nukes an admin's entire allow/deny posture (with a `claude doctor` warning). The auto-mode classifier gets both a sharper exfiltration prompt (bulk-transfer red flag) and a false-positive fix (a `max_tokens`-truncated classifier no longer reads as a refusal).

The background-agent cluster is the quiet bulk of the work: an orphan watchdog so a daemon-less `--bg-pty-host` self-terminates instead of pinning a core, a CLI-version gate so pinned sessions respawn exactly once per update instead of every minute, a broadened settled predicate so blocked/working sessions actually retire, and an `agentId`-aware isolation guard so bg subagents can't write to the shared checkout. Together these continue the multi-version "make background agents trustworthy" arc that has run through 2.1.142–2.1.156. The two items I could not pin to exact source — the 1M-context completion-notification accounting and the scheduled-`/command` classifier goal loss — are background-agent fixes whose surrounding plumbing is verified but whose precise patch points were not isolatable in the bundle.
