# v2.1.145 — Source Diff Analysis

**Theme:** Observability & scripting hardening for the agent fleet. The headline is OTEL trace fidelity — **`agent_id`/`parent_agent_id` are now stamped on `claude_code.tool` spans** and background subagent spans nest correctly under their dispatching `Agent` tool span. Alongside it: **`claude agents --json`** turns the live session list into a scriptable feed, **Stop/SubagentStop hooks gain `background_tasks` + `session_crons`** so a hook can tell "session is done" from "session is paused waiting for background work," a **security fix for a bare-variable-assignment permission bypass** in Bash, and a **Read tool that degrades to a "PARTIAL view" first page** instead of hard-failing when a whole-file read blows the token cap.

This release reads as the **"make the multi-agent / background world legible to tools, scripts, and telemetry"** patch: 2.1.139–2.1.144 built the agent-view/background machinery; 2.1.145 wires that machinery into OTEL, JSON output, hook inputs, and the status line so external tooling can see and reason about it.

## 1. `agent_id`/`parent_agent_id` on `claude_code.tool` OTEL spans + trace parenting (NEW)

**Type:** feature (observability) · **Modules:** Telemetry/OTEL, Agents, Subagent

### How it works

Every tool invocation opens an OTEL span named `claude_code.tool`. v2.1.145 enriches that span with the *agent identity* of whoever ran the tool, read from the ambient agent context (`$D()` returns the current agent's `{agentId, parentAgentId, …}` record). The two attributes are set immediately after the span is created, and only when present (so the root agent — which has no parent — does not emit a null `parent_agent_id`).

## 4. Bare-variable-assignment permission bypass — fixed (SECURITY)

**Type:** fix (security) · **Modules:** Permissions, Bash policy, Shell parser

### How it works

The Bash read-only / auto-approve fast path parses a command and, among other safety checks, now inspects **bare variable assignments** — leading `VAR=value` tokens with no command after them, or env-prefix assignments that persist into the shell. The parser extracts these into `bareAssignmentNames` (`cli_inner_pretty.js:207809`, `441132`), and the policy passes the command through to a manual permission prompt when any assigned name is (a) **not** on the safe allowlist (`V5H`) and (b) is a tracked/known variable (`iD$()`).

## 5. Read tool returns a "PARTIAL view" first page instead of a hard error (NEW behavior)

**Type:** improvement · **Modules:** Tools (Read/FileRead), Context

### How it works

A whole-file Read (no `offset`/`limit`/`pages`) that exceeds the model's token budget used to throw. The banner prefix `$j$ = "[Truncated: PARTIAL view — "` is defined at `cli_inner_pretty.js:145392`. The cached read-state entry is marked `isPartialView: true` (`cli_inner_pretty.js:422485`) and the returned file payload carries `truncatedByTokenCap: true` (`cli_inner_pretty.js:422497`).

| | |
|---|---|
| **Type** | Improvement (graceful degradation) |
| **Modules touched** | Read/FileRead tool, Context/file-state cache |
| **Before** | A whole-file Read of a file too large for the token cap threw a hard error. The model got nothing — no content, no path forward — and often re-tried the same doomed read or gave up. |
| **After** | The Read returns a truncated first page (line-based, or character-based for files with pathologically long lines) plus a `[Truncated: PARTIAL view — …]` banner that states the totals, the token cap, **the exact next-page call to make** (`offset`/`limit`), and a warning not to answer from the partial page alone. The cached state is marked `isPartialView`. |
| **Why** | Turning a dead end into a usable, *self-describing* partial result. The two-stage shrink (line-based first, char-based fallback) handles both normal files and minified/single-line monsters; the surrogate-pair guard avoids emitting broken UTF-16. Marking `isPartialView` is load-bearing: Edit/Write require a *real* (non-partial) Read first, so the model can't silently edit a file it only partially saw. |

**Cross-validation (v2.1.88):** `isPartialView` already existed in v2.1.88 as a cache flag that forces Edit/Write to require a real Read (`src/utils/fileStateCache.ts:14`, `src/tools/FileReadTool/FileReadTool.ts:549`, `src/tools/FileEditTool/FileEditTool.ts:276`, `src/tools/FileWriteTool/FileWriteTool.ts:199`). What is **new in 2.1.145** is the *shrink-to-fit-on-token-overflow* behavior that produces the partial view instead of throwing. **Confidence: high** (algorithm + banner strings + cache flag all verified). Deeper coverage: `../04_tools/read_partial_view_and_streaming_exec.md`.

## Summary

v2.1.145 is the release that makes the multi-agent / background world built across 2.1.139–2.1.144 **legible to the outside**. Three of its features point the same direction: OTEL spans now carry `agent_id`/`parent_agent_id` and background subagent spans nest under their dispatcher (§1), `claude agents --json` exposes the live fleet to scripts without a TTY (§2), and Stop/SubagentStop hooks receive `background_tasks` + `session_crons` so automation can tell a finished session from a paused one (§3). The status-line JSON repo/PR fields (§6) and the awaiting-input tab-title count (§8) are smaller beats of the same "observe the fleet from outside" theme.

The two non-fleet items are quietly important. The **bare-variable-assignment bypass fix (§4)** closes a real auto-approve hole — `LD_PRELOAD=…`/`PATH=…` style assignments that looked output-free but poison later commands — in the same spirit as the 2.1.149 PowerShell `cd` fix. The **Read "PARTIAL view" (§5)** turns a hard failure into a self-describing, paginatable partial result, with an `isPartialView` flag that keeps Edit/Write honest. The remaining bullets are a normal tail of UX polish and platform fixes (Windows PS 5.1 separator, non-ASCII teammate headers, deprecated GraphQL, the `context: fork` self-loop). Deeper module coverage lives in `../11_hooks/stop_hook_background_tasks_and_block_cap.md`, `../37_permission_policy/powershell_cd_and_bare_assignment_bypass.md`, and `../04_tools/read_partial_view_and_streaming_exec.md`.
