## Integration 1: Tools ↔ System Reminder

### Attachment Types Generated by Tools

| Tool Event | Attachment Type | Description |
|------------|-----------------|-------------|
| Tool progress | `progress` | Streaming progress updates |
| Tool result | `structured_output` | Parsed tool result |
| Pre-hook context | `hook_additional_context` | Extra context from hooks |
| Pre-hook denial | `hook_blocking_error` | Hook blocked execution |
| Permission decision | `hook_permission_decision` | Permission outcome |

### Flow Diagram

```
Tool execution (Wi6 → fxY)
  │
  ├─→ Pre-tool hooks (y4q)
  │     └─→ May emit attachment messages
  │
  ├─→ Tool execution
  │     └─→ Progress updates → attachment
  │
  ├─→ Post-tool hooks (k4q)
  │     └─→ May modify result or emit attachments
  │
  └─→ Result normalization (Ui8)
        └─→ All attachments → user message with isMeta:true
              └─→ Injected before next LLM call
```

### Code Path

```javascript
// In fxY (toolExecutionPipeline)
for await (let result of executeToolWithProgress(...)) {
  if (result.message) {
    // Tool result or attachment
    yield result;
  }
}

// Collected by bG1 (buildContextMessages)
const attachments = await assembleAttachments(...);
for (const attachment of attachments) {
  yield normalizeAttachmentForAPI(attachment);  // Ui8 → K2z
}
```

## Integration 2: MCP ↔ System Reminder

### MCP-Generated Attachments

| MCP Event | Attachment Type | Description |
|-----------|-----------------|-------------|
| Tool discovery | `mcp_tools_available` | New tools registered |
| Resource content | `mcp_resource` | Resource data |
| Elicitation request | `elicitation` | Server needs user input |
| Connection status | `mcp_status` | Server connected/disconnected |

### Elicitation Flow

```
MCP Server sends elicitation/create
  │
  ├─→ Received by WT7 (setupElicitationRequestHandler)
  │
  ├─→ Added to elicitation queue
  │
  ├─→ Modal priority check
  │     └─→ Elicitation has lowest priority (after sandbox, tool permissions)
  │
  └─→ UI renders elicitation dialog
        ├─→ Form mode: ZIq (ElicitationDialog)
        └─→ URL mode: gWz (UrlElicitationDialog)
```

### Resource Injection

```javascript
// Resource → System Reminder
async function injectMcpResource(resource, serverName) {
  const content = await readResource(resource.uri, serverName);

  return {
    type: "mcp_resource",
    serverName,
    resourceUri: resource.uri,
    content: content.text || content.blob,
    mimeType: content.mimeType
  };
}
```

// azz - planModeReminderDispatcher
function selectPlanReminderVariant(attachment) {

## Integration 4: Task System ↔ System Reminder

### Task-Generated Attachments

| Event | Attachment Type | Description |
|-------|-----------------|-------------|
| Task status change | `task_status` | Status update notification |
| Task assignment | `task_assignment` | New owner assigned |
| Dependency resolved | `dependency_resolved` | Blocking task completed |
| Todo reminder | `todo_reminder` | Pending tasks summary |

### Task Status Attachment

```javascript
// Generated by suY (getTaskStatusAttachments)
function buildTaskStatusAttachment(tasks) {
  const pending = tasks.filter(t => t.status === "pending");
  const inProgress = tasks.filter(t => t.status === "in_progress");
  const blocked = tasks.filter(t =>
    t.blockedBy.some(id => !isTaskCompleted(id))
  );

  return {
    type: "task_status",
    summary: {
      total: tasks.length,
      pending: pending.length,
      inProgress: inProgress.length,
      blocked: blocked.length
    },
    tasks: tasks.map(t => ({
      id: t.id,
      subject: t.subject,
      status: t.status,
      owner: t.owner,
      isBlocked: blocked.includes(t.id)
    }))
  };
}
```

### Todo Reminder Throttling

```javascript
// Todo reminders are throttled to avoid noise
const TODO_REMINDER_INTERVAL = 3;  // Every 3 turns

function shouldShowTodoReminder(turnCount) {
  return turnCount % TODO_REMINDER_INTERVAL === 0;
}
```

## Integration 5: All Modules ↔ Hooks

### Hook Event Types

| Event | Module | Trigger |
|-------|--------|---------|
| PreToolUse | Tools | Before tool execution |
| PostToolUse | Tools | After tool success |
| PostToolUseFailure | Tools | After tool error |
| TaskCompleted | Task System | Task marked completed |
| PreCompact | Compact | Before compaction |
| Stop | Agent Loop | After turn complete |

### Hook Chain Flow

```
Event triggered
  │
  ├─→ Find matching hooks
  │     └─→ Check matcher conditions
  │
  ├─→ Execute hooks in order
  │     ├─→ Spawn hook process
  │     ├─→ Pass JSON via stdin
  │     └─→ Collect stdout response
  │
  └─→ Process results
        ├─→ Apply modifications
        ├─→ Generate notifications
        └─→ Handle preventContinuation
```

### Modal Priority System

```javascript
// Modal selection in REPL render
function selectActiveModal(state) {
  if (state.sandboxPermissions[0]) {
    return "sandbox-permission";        // Highest: Security
  }
  if (state.pendingWorkerRequest[0]) {
    return "tool-permission";           // High: Tool approval
  }
  if (state.workerSandboxQueue[0]) {
    return "worker-sandbox-permission"; // Medium: Worker sandbox
  }
  if (state.elicitation.queue[0]) {
    return "elicitation";               // Lowest: MCP input request
  }
  return null;  // No modal
}
```

## Cross-Feature Data Flow

### Example: Task Assigned → Tool Execution → System Reminder

```
User assigns task to agent
  │
  ├─→ TaskUpdate(status="in_progress", owner="agent-1")
  │     │
  │     └─→ Task attachment generated
  │           └─→ Injected as system reminder
  │
  ├─→ Agent reads task details
  │     └─→ Get task via TaskGet tool
  │
  ├─→ Agent executes tool
  │     ├─→ PreToolUse hook runs
  │     ├─→ Permission check
  │     ├─→ Tool execution
  │     └─→ PostToolUse hook runs
  │           └─→ Hook output → attachment
  │
  └─→ Agent marks task complete
        ├─→ TaskUpdate(status="completed")
        ├─→ TaskCompleted hooks fire
        │     └─→ Notifications generated
        └─→ Task status attachment updated
```

### Example: MCP Tool Execution Flow

```
LLM generates: tool_use { name: "mcp__sqlite__query", input: {...} }
  │
  ├─→ toolDispatcher (Wi6) receives tool_use
  │     │
  │     └─→ Lookup finds MCP tool (mcp__ prefix)
  │
  ├─→ toolExecutionPipeline (fxY)
  │     ├─→ Validate input against schema
  │     ├─→ Run PreToolUse hooks
  │     └─→ Call MCP tool
  │           │
  │           └─→ callMcpTool (pC)
  │                 ├─→ Parse server name: "sqlite"
  │                 ├─→ Parse tool name: "query"
  │                 └─→ Execute via MCP client
  │                       └─→ JSON-RPC tools/call
  │
  ├─→ Format result
  │     └─→ MCP JSON → formatted text
  │
  └─→ Generate attachments
        └─→ Tool result → system reminder
```
