## 1. Tools ↔ System Reminder Integration

### Attachment Types Generated by Tools

| Attachment Type | Generated By | Purpose |
|-----------------|--------------|---------|
| `progress` | Tool execution pipeline | Progress updates during long operations |
| `hook_additional_context` | PreToolUse hooks | Additional context from hook execution |
| `hook_blocking_error` | PreToolUse hooks | Hook denial message |
| `task_status` | Background tasks | Background task state changes |
| `permission_decision` | Permission flow | User permission decision result |
| `tool_result` | Tool execution | Tool result for LLM context |

### Key Integration Functions

### Attachment Flow

```
Tool execution (fxY)
  │
  ├─→ Progress callback
  │     └─→ j({ toolUseID, data })  // Progress callback
  │           └─→ C4q({ toolUseID, parentToolUseID, data })
  │                 └─→ Progress attachment
  │
  ├─→ Hook execution (y4q)
  │     ├─→ hook_additional_context
  │     ├─→ hook_blocking_error
  │     └─→ preventContinuation
  │
  └─→ Result assembly
        └─→ p1({ content: [...], toolUseResult: "...", attachment: {...} })
              └─→ User message with attachment
```

## 2. MCP ↔ System Reminder Integration

### Elicitation Attachments

MCP servers can request user input via elicitation, which generates special attachments:

```javascript
// ============================================
// Elicitation attachment structure
// ============================================

{
    type: "elicitation_request",
    serverName: "mcp-server",
    requestId: "uuid",
    message: "Please provide credentials",
    requestedSchema: {  // JSON Schema for form mode
        type: "object",
        properties: {
            username: { type: "string" },
            password: { type: "string" }
        }
    },
    // OR for URL mode:
    uris: ["https://auth.example.com/oauth"]
}
```

### MCP Tool Progress Attachments

```javascript
// ============================================

// ============================================

{
    type: "mcp_progress",

```

### Mode Transition Hook

```javascript
// ============================================
// Dp - handlePlanModeTransition
// Location: chunks.1.mjs:2946-2950
// ============================================

// ORIGINAL (for source lookup):
function Dp(A, q) {
    if (q === "plan" && A !== "plan") {
        // Entering plan mode
        Y.needsPlanModeExitAttachment = !1
    }
    if (A === "plan" && q !== "plan") {
        // Exiting plan mode
        Y.needsPlanModeExitAttachment = !0
    }
}

// READABLE (for understanding):
function handlePlanModeTransition(fromMode, toMode) {
    if (toMode === "plan" && fromMode !== "plan") {
        // Entering plan mode: reset exit attachment flag
        globalSessionState.needsPlanModeExitAttachment = false;
    }
    if (fromMode === "plan" && toMode !== "plan") {
        // Exiting plan mode: mark need for exit attachment
        globalSessionState.needsPlanModeExitAttachment = true;
    }
}

// Mapping: Dp→handlePlanModeTransition, A→fromMode, q→toMode, Y→globalSessionState
```
