# v2.1.92 — Source Diff Analysis

**Theme:** Enterprise managed-settings (`forceRemoteSettingsRefresh`), Bedrock setup wizard, `/cost` per-model breakdown, and the `/release-notes` interactive picker.

---

## 1. `forceRemoteSettingsRefresh` policy setting (NEW)

**Type:** infra · **Modules:** Settings, Managed-policy

### v2.1.88 baseline

`claude-code-kim/src/utils/managedSettings.ts` (and similar) load remote settings asynchronously at startup. If the fetch failed (network down, IdP outage), the CLI continued with **cached** settings — including potentially out-of-date allow/deny rules.

### v2.1.112 state

```javascript
// chunks.19.mjs (settings schema)
forceRemoteSettingsRefresh: y.boolean().optional()
  .describe("When set in managed settings, the CLI blocks startup until remote managed settings are freshly fetched, and exits if the fetch fails"),
```

### Why this approach

**The risk:** A stale managed-settings cache could keep allow rules valid that the admin has since revoked. For an enterprise compliance posture, "fail-closed" is required: if we can't verify policy is current, refuse to start.

**Why a setting instead of always-on:**
- Forcing a network round-trip on every start would brick offline development.
- Enterprises that need fail-closed already require connectivity via VPN; they can opt in.
- The setting is in *managed* settings only — users can't set it on themselves.

**Edge case:** If the remote settings server is genuinely down, the user sees a hard error with the URL of the settings endpoint. They can flip a local override or wait for the outage to clear.

## 2. Interactive Bedrock setup wizard (NEW)

**Type:** feature · **Modules:** Auth, Onboarding

### v2.1.88 baseline

To use Bedrock, users had to:
1. Configure AWS credentials via `aws configure` or env vars.
2. Set `CLAUDE_CODE_USE_BEDROCK=1`.
3. Pin model IDs in `settings.json`.

There was no in-CLI assist. Failures (wrong region, no inference profile, missing IAM permission) showed cryptic AWS error messages.

### v2.1.112 change

A new wizard accessible from the login screen by selecting "3rd-party platform" walks through:
1. AWS credential method (env vars / IAM role / profile).
2. Region configuration with inference-profile discovery.
3. Credential verification (a probe Sonnet call).
4. Model pinning ("with 1M context" option for supported models — added in v2.1.111).

### Why this approach

**Why a wizard:** Bedrock setup is the #1 first-run support burden for enterprise users. A wizard with explicit verification at each step turns "it doesn't work" into "step 3 said your region doesn't have an inference profile for Sonnet — try us-west-2."

**Why integrate into login:** Users discover Claude Code via `claude` and reach the login screen first. Adding "3rd-party platform" there meets them where they are.

The Vertex AI wizard ships in v2.1.98 with the same pattern.

## 3. `/cost` per-model + cache-hit breakdown (subscription users)

**Type:** UX · **Modules:** Cost tracking, Subscription telemetry

### v2.1.88 baseline

`claude-code-kim/src/cost-tracker.ts` already tracks per-model cost. The `/cost` command rendered a single roll-up: total tokens × per-model price.

### v2.1.112 change

For subscription users, `/cost` now shows:
- Per-model rows (Opus 4.7 / Sonnet / Haiku usage broken out).
- Cache-hit vs cache-miss split per model.
- Estimated cost based on the published Bedrock-equivalent rates (subscription users don't pay these, but the breakdown helps them understand burn rate).

### Why this approach

**Why expose this to subscribers (who don't pay per token)?** Two reasons:
1. Helps users understand *why* they hit usage limits (a session that burned 10M cache-miss tokens vs 10M cache-hit tokens has very different impact).
2. Encourages prompt-cache-friendly patterns (don't reload full file content on every turn).

## 4. `/release-notes` → interactive version picker

**Type:** UX · **Modules:** Slash commands

### v2.1.88 baseline (`commands/release-notes/release-notes.ts`)

```typescript
// v2.1.88 — claude-code-kim/src/commands/release-notes/release-notes.ts
function formatReleaseNotes(notes: Array<[string, string[]]>): string {
  return notes
    .map(([version, notes]) => {
      const header = `Version ${version}:`
      const bulletPoints = notes.map(note => `· ${note}`).join('\n')
      return `${header}\n${bulletPoints}`
    })
    .join('\n\n')
}

export async function call(): Promise<LocalCommandResult> {
  // ... 500ms timeout fetch ...
  return { type: 'text', value: formatReleaseNotes(freshNotes) }
}
```

The 2.1.88 version dumps **all** versions as text in a single `value`.

### v2.1.112 change

Now an **interactive picker** (JSX component) where the user can:
- Arrow-key through versions
- See changelog details for the focused version
- Filter to `Major changes only` or `Since I last upgraded`

The text-dump path is preserved for `--non-interactive` mode (subscript supports it), so scripts still work.

### Why this approach

**Why a picker:** Dumping 50 versions of changelog is overwhelming. A picker scopes attention to one version at a time and lets the user navigate.

**Why preserve text mode:** CI scripts that grep release-notes output rely on the dump format.

## 5. Remote Control session names use hostname prefix

**Type:** UX · **Modules:** Remote Control

Default session names are now `<hostname>-<adjective>-<animal>` (e.g. `myhost-graceful-unicorn`) instead of just `<adjective>-<animal>`. Overridable with `--remote-control-session-name-prefix`.

### Why this approach

**The pain point:** A user with sessions running on multiple machines (laptop + desktop + SSH server) couldn't tell *which* machine produced "graceful-unicorn" in the cloud session list. Hostname prefix solves the identification.

**Why a flag override:** Some users (e.g. on transient cloud VMs) want to override hostname (`ip-10-0-1-23` is not a useful prefix).

## 6. Pro-user prompt-cache-expiry warning

**Type:** UX · **Modules:** Prompt cache, Footer

When returning to a session after the prompt cache has expired (5min default, 1h with `ENABLE_PROMPT_CACHING_1H` per v2.1.108), Pro users see a footer hint estimating how many tokens the next turn will send uncached.

### Why this approach

A user who comes back to a long session after lunch may not realize they're about to spend 5x the tokens on the first message because the cache evicted. The footer hint warns *before* they send.

The estimate is computed from the current context size × an estimated cache-miss multiplier (~1.0 for non-cache, 0.1 for cache hit).

## 7. Subagent spawning fix — tmux pane count

**Type:** fix · **Modules:** Subagent, Agent teams

When tmux windows were killed or renumbered during a long-running session, the subagent spawner cached its earlier pane-count enumeration and failed with "Could not determine pane count" on the next spawn.

**Fix:** Pane count is queried fresh per spawn. The cost is a single `tmux list-panes` call per spawn — negligible.

## 8. Prompt-type Stop hooks failing on small fast-model "ok:false"

**Type:** fix · **Modules:** Hooks (prompt-type)

The Stop hook was incorrectly treating `{ok: false}` from the small fast classifier model as a fatal hook failure rather than an instruction to *continue*. Now Stop hooks distinguish:
- Classifier `ok:false` → continue (prevent stop)
- Hook execution error → fatal

Also restored `preventContinuation:true` semantics for non-Stop prompt-type hooks (PreToolUse, etc.).

---

## 9. Tool input validation: array/object as JSON-encoded strings

**Type:** fix · **Modules:** Tools

Some streaming tool input deltas emit array/object fields as JSON-encoded strings (e.g. `"items": "[1,2,3]"` instead of `"items": [1,2,3]`). The validator was rejecting these as type-mismatched.

**Fix:** When the schema expects an array/object and the value is a string, attempt `JSON.parse` before failing.

---

## 10. API 400 from extended-thinking whitespace-only blocks

**Type:** fix · **Modules:** LLM API, Thinking

Extended thinking sometimes produced a `text` block whose content was whitespace-only, alongside the real response. The API rejected this as malformed.

**Fix:** Empty/whitespace-only text blocks are stripped before sending.

---

## 11. Feedback survey accidental submission

**Type:** UX · **Modules:** Feedback

Auto-pilot keypresses (held arrow keys, fast typers) and consecutive-prompt digit collisions (typing `1` then Enter when the survey appeared between) were submitting surveys unintentionally. Added a `min-display-time` gate before any submission can fire.

---

## 12. "esc to interrupt" + "esc to clear" overlap

**Type:** fix · **Modules:** Footer hints

When a text selection existed in fullscreen mode during processing, both hints appeared together because the two state machines (selection state and processing state) didn't know about each other. Fixed by making the footer hint priority hierarchical.

---

## 13. Homebrew install update prompts

**Type:** fix · **Modules:** Updater

`brew install claude-code` (stable cask) was prompting to update from the `@latest` cask's release channel and vice versa. Now the updater detects which cask installed it and uses the matching channel.

---

## 14. `ctrl+e` jumping past line in multiline prompts

**Type:** fix · **Modules:** Input

`Ctrl+E` (end of line) was using the *visual* end-of-line which, when the cursor was already at end of a line, jumped to end of the *next* line. Fixed by checking position before moving.

---

## 15. Same message at two positions when scrolling up (DEC 2026 terminals)

**Type:** fix · **Modules:** Fullscreen renderer

In iTerm2/Ghostty (DEC 2026 synchronized output), the alt-screen renderer's scroll handler could double-paint a message during fast scroll. Race fixed by buffering scrolls inside the synchronized-output frame.

---

## 16. `/clear` token count

**Type:** fix · **Modules:** Hint footer

The "Clear to save X tokens" hint was using cumulative session tokens instead of *current* context size. Two users reported seeing 4M tokens when their context held 80k. Fix: use current context, not cumulative.

---

## 17. Plugin MCP servers stuck "connecting"

**Type:** fix · **Modules:** Plugins, MCP

Plugin-defined MCP servers that duplicated a claude.ai-side connector could get stuck "connecting" because both sides tried to authenticate. Now the plugin side defers to the connector when the connector exists and is unauthenticated.

---

## 18. Write tool diff perf for large files

**Type:** perf · **Modules:** Write tool

The diff computation was 60% slower than necessary on files with tabs/`&`/`$` due to a regex pass that re-parsed escape characters. Replaced with a single-pass byte scan.
