# v2.1.89 — Source Diff Analysis (vs v2.1.88 baseline)

**Theme:** Defer hooks, NO_FLICKER rendering, **autocompact dual circuit-breakers** (consecutive-failure + rapid-refill), expanded hook surface, and a wave of resume/transcript fixes.

The two architectural items are (1) the new `defer` permission decision for headless `PreToolUse` hooks and (2) the introduction of `CLAUDE_CODE_NO_FLICKER` flicker-free rendering — the latter eventually graduates into `/tui` in v2.1.110. The compact circuit-breakers (originally documented as "thrash circuit-breaker" in the changelog) are actually **two** independent guards, not one.

---

There are *two* switches — one on the outer `permissionDecision` (line 34) and one on the `hookSpecificOutput.permissionDecision` (line 58). Both gain a `defer` case in v2.1.89. The error message in the outer switch's default also widens from `"allow, deny, ask"` to `"allow, deny, ask, defer"`.

### Why this approach

**What `defer` does:** A hook returns `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "defer"}}` and Claude Code *pauses* execution at this tool call. A subsequent `claude -p --resume` re-runs the hook with the same input. If the hook still defers, the cycle repeats; otherwise the resolved decision is applied.

**Why not just use `ask`:** `ask` requires a *human* prompt, unavailable in headless `-p` mode. `defer` is the only decision that says "I don't have enough information yet — try again next cycle" without a UI roundtrip.

**Edge cases the v2.1.89 release explicitly fixes:**
- `-p --resume` hangs on >64KB deferred input — the deferred marker now stores out-of-band metadata, not the raw payload.
- `-p --continue` not resuming deferred tools — the resume picker now scans for the deferred sentinel.

**Trade-off:** A buggy hook stuck in `defer` would never resolve. There's no global deferral cap — it's the user's responsibility to ensure `--resume` cycles eventually converge. In practice, hooks deferring for "wait until CI passes" use the resume cadence as a polling interval.

## 2. CLAUDE_CODE_NO_FLICKER alt-screen rendering (NEW)

**Type:** feature · **Modules:** Ink renderer, REPL

### v2.1.88 baseline

The 2.1.88 codebase has `claude-code-kim/src/utils/fullscreen.ts` and `src/components/FullscreenLayout.tsx` — but those are tmux-specific helpers (handling `tmux` integration mode), **not** an alt-screen renderer. Default rendering is main-screen with append-style updates that flicker on reflow.

```javascript
//          Ja6→sharedFlagState (module-level mutable cache)
```

### Why a layered cascade

Each layer represents an orthogonal authority:

| Layer | Authority | Example use |
|-------|-----------|-------------|
| (1)/(2) Env vars | Operator override | CI runner forces `=0` to keep flat output |
| (3) tmux -CC | Terminal capability | Disabled because alt-screen breaks iTerm2 pane integration |
| (4) `tui` setting | Persistent user choice | Added in v2.1.110 — see that version's analysis |
| (5) `tengu_pewter_brook` | Anthropic-side rollout | Server can flip the default for cohorts |

The order — operator > terminal > user > rollout — follows the principle "the most explicit override wins."

**Note on layer (4):** v2.1.89 doesn't yet have the `tui` setting (added in v2.1.110). The cascade had only env-var + tmux + feature gate when first shipped; the case-statement appears here as an artifact of v2.1.110 backporting into the same function.

### What the alt-screen path enables

When `isFullscreenMode()` is true, the Ink renderer:
1. Enters DECSET 1049 (alt-screen buffer) on session start.
2. Maintains a **virtualized scrollback** in memory (the OS terminal's scrollback is suspended).
3. Repaints the visible window atomically, eliminating flicker.
4. Restores the terminal scrollback on exit (via DECRST 1049).

This is the foundation that v2.1.97 builds focus view on (`Ctrl+O` / `/focus`), v2.1.110 graduates to a setting, and v2.1.111 ships `autoScrollEnabled` for.

### Edge cases v2.1.89 fixes (rolled out under the same gate)

| Issue | Cause |
|-------|-------|
| Slow mouse-wheel scroll on Windows Terminal | Custom wheel handler used main-screen mouse codes |
| Custom status line not displaying on terminals <24 rows | Status line rendering bypassed alt-screen height check |
| Shift+Enter / Alt+arrow not working in Warp | Kitty keyboard protocol negotiation skipped |
| CJK garbled when copied (Windows) | Clipboard buffer used CRT byte encoding |
| Memory leak from API retries | Stale streaming-state references retained |

### Algorithm: Why two breakers?

**Circuit-Breaker A (`consecutiveFailures >= 3`):** Catches *crashing* compactions. A pathological transcript or a misbehaving compactor model that throws on every attempt trips this after the third failed attempt.

**Circuit-Breaker B (`consecutiveRapidRefills >= 3`):** Catches *successful but pointless* compactions. The agent compacts → context fills back to threshold within 3 turns → compacts again → fills again → compacts again. Three compactions in 9 turns means the system prompt itself is dominating the budget; further compactions won't help.

**Why three for both:**
- One failure could be a transient network blip.
- Two could be coincidence.
- Three in a row is strong evidence the issue is structural.
- The same threshold applies to both breakers — keeps the mental model simple.

**Why distinguish the two:**
A failure counter alone wouldn't catch the "compaction succeeds but is useless" pattern. A rapid-refill counter alone wouldn't catch outright crashes. Both are needed.

**Special-case: `PreCompact` hook block.** When a v2.1.105 PreCompact hook blocks compaction (errors with prefix `"Compaction blocked by PreCompact hook"`), the catch swallows the error *without* incrementing `consecutiveFailures`. A hook saying "not now" should not count toward the failure budget — that would punish the user for using the feature.

### What actually changed in v2.1.89

The changelog says "Added `PermissionDenied` hook" but the more accurate description is:

## 6. MCP_CONNECTION_NONBLOCKING + bounded `--mcp-config` connect (5 s)

**Type:** infra · **Modules:** MCP, Headless

### What it does

Two new behaviors:
- `MCP_CONNECTION_NONBLOCKING=true` (only honored in `-p` mode): skip waiting for MCP server connections at session start; tools may be unavailable on the first turn but become available as servers connect.
- `--mcp-config` per-server connect: capped at 5 seconds; slowest server no longer stalls the session.

### Why this approach

Running `claude -p "summarize the PR"` in CI shouldn't pay for an unresponsive MCP server. The 5-second cap is generous for healthy servers (typical MCP connect: <100ms), bounded for stalled ones.

The non-blocking env var is the escape valve when "connect them all in the background, fire later" is acceptable. The trade-off is **first-turn tool availability**: the user's prompt may execute before all tools are registered. The v2.1.105 fix "MCP tools missing on the first turn of headless/remote-trigger sessions when MCP servers connect asynchronously" is the dual — it adds a bounded wait when the first turn explicitly *needs* a tool from a connecting MCP.

## 8. Edit/Read symlink resolution

**Type:** security · **Modules:** Permissions

### What changed

`Edit(//path/**)` and `Read(//path/**)` allow rules now check the **resolved** symlink target, not just the requested path. Previously a symlink in an allowlisted directory pointing outside the allowed prefix would silently let the tool through.

### Why this is a security fix

Privilege escalation: an attacker (or careless user) places a symlink inside `~/projects/safe/` pointing to `~/.ssh/id_rsa`. With the old logic, an allowlist of `~/projects/safe/**` matches the requested path (which begins with the safe prefix), and the read goes through. The fix calls `realpath` (or equivalent) before the rule check.

## 10. StructuredOutput schema cache bug (~50% failure rate)

**Type:** fix · **Modules:** Structured output

### Bug

When multiple JSON schemas were used in a session, the cache was keyed by **reference identity** (the schema object's `===`-identity in JS), so two schemas with identical shape but different references collided in the cache. ~50% of validations failed.

### Fix

Cache key is now a stable string hash of the canonicalized schema (sorted keys, normalized whitespace).

## 12. Prompt cache misses on tool-schema bytes changing mid-session

**Type:** fix · **Modules:** Prompt cache, MCP

### Bug

In long sessions, the user's tool list could change (MCP server connect/disconnect, plugin enable/disable), causing the **bytes** of the system prompt to change between turns even when the *semantic* tools were stable. That invalidated the prompt cache and re-charged thousands of tokens per turn.

### Fix

Tool schemas are now serialized in a deterministic order with stable spacing. The cache is keyed by *semantic* tool list, not byte equality. Pairs with the v2.1.91 perf win (eliminating per-turn `JSON.stringify`).

## 13. Nested CLAUDE.md re-injection at every file read

**Type:** fix · **Modules:** Memory injection, System prompt

### Bug

CLAUDE.md files in nested directories were being re-injected each time the agent read a file in that directory tree. In a session that reads 100 files, the same CLAUDE.md could appear 100 times in the system prompt — wasting both context and prompt-cache hits.

### Fix

Track injection by `(path, content_hash)` and skip re-injection when nothing has changed.

**Type:** fix · **Modules:** Errors

### Bug

When the API returned an *entitlement* error (your account doesn't have access to this model), the error code was being misclassified as a rate-limit. The user saw "Rate limit reached, try again later" — useless because retrying won't fix entitlement.

### Fix

Distinguish 429 (rate-limit) from entitlement codes (403 with specific error body) and show the actual error with actionable hints.

## 15. Hook `if` filter on compound commands and env-var prefixes

**Type:** fix · **Modules:** Hooks

Hooks with `if` conditions (e.g. `if: "command contains 'git push'"`) failed to match:
- Compound commands (`ls && git push`) — the matcher only looked at the first segment
- Commands with env-var prefixes (`FOO=bar git push`) — the prefix shadowed the matcher

Fix: the matcher now walks all segments and strips known-safe env-var prefixes before testing.

## Summary

v2.1.89 is a **plumbing release** that pays down debt in three layered systems:
- **Permission decisions:** defer joins allow/deny/ask, PermissionDenied graduates from feature flag, message wording tightened.
- **Rendering:** flicker-free alt-screen lands as opt-in env var (graduates to setting in v2.1.110, command in v2.1.110).
- **Compaction:** dual circuit-breakers replace silent infinite retry (consecutive-failure breaker + rapid-refill breaker).

The fix tail is mostly *correctness under pressure*: the existing happy paths worked, but edge cases (long sessions, large transcripts, slow MCP servers, headless mode, Windows EOL, CJK boundaries) caused silent failures. v2.1.89 is the version where the team started actively measuring and patching those edges.
