## 1. `/powerup` interactive lessons (NEW)

**Type:** feature · **Modules:** Slash commands, UI

### v2.1.88 baseline

No `/powerup` command existed. There was no concept of "lessons" in `claude-code-kim/src/commands/`.

### v2.1.112 state

```javascript
//          eUK→initPowerupLessons, tUK→powerupLessonComponent, L→lazyInit
```

The lesson array (`Xg` at chunks.180.mjs:961) holds 5+ JSX-driven lessons covering:
- `at-mentions`
- `modes` (auto vs plan vs accept-edits)
- `undo` (the `/undo` ↔ `/rewind` alias from v2.1.108)
- More driven by feature-flag rollout

State is persisted to `~/.claude/config.json` as `powerupsUnlocked: string[]`. Telemetry events `tengu_powerup_lesson_opened` / `tengu_powerup_lesson_completed` fire for each interaction.

### Why this approach

**What it does:** A first-time-user education surface that lives inside the CLI itself rather than in docs. Lessons render as JSX with animation frames (CSS-like keyframe scrolling in the terminal).

**Why this approach:**
- Lessons need **animation** (showing the cursor moving, text streaming, etc.) which static markdown can't do.
- Lessons need **interactivity** (`Try it now`-style prompts) which a help command can't do.
- Wrapping each lesson in a JSX component lets the team A/B test individual lessons via the unlock state.

**Trade-off:** Lessons require updating the CLI binary itself when content changes. The team accepts this cost because the lessons are *teaching the CLI's own affordances* — they're tied to the CLI version anyway.

## 2. `CLAUDE_CODE_PLUGIN_KEEP_MARKETPLACE_ON_FAILURE` env var (NEW)

**Type:** infra · **Modules:** Plugin marketplace

When the periodic `git pull` of the marketplace cache fails (offline, transient network), the **default** behavior is to drop the cache so it gets re-fetched. With `CLAUDE_CODE_PLUGIN_KEEP_MARKETPLACE_ON_FAILURE=1`, the existing cache is preserved.

**Why:** Users on flaky networks (corporate VPNs, planes, ferries) saw their plugin marketplace empty itself when `git pull` momentarily failed. Persisting the stale cache is strictly better than showing nothing.

**Edge case:** A genuinely *corrupt* cache would also be preserved with the env var set. The user has to delete `~/.claude/plugins/marketplace-cache/` manually to force a refresh, which the doctor command should hint at.

## 3. `.husky` added to protected directories (acceptEdits mode)

**Type:** security · **Modules:** Permissions

### v2.1.88 baseline

`claude-code-kim/src/utils/worktree.ts:537-541` already special-cases `.husky` for *worktree creation* — but not as a **protected** directory in acceptEdits mode. Edits to `.husky/` would auto-approve.

### v2.1.112 change

`.husky` is added to the auto-deny list for `acceptEdits` mode, joining `.git/`, `.ssh/`, `node_modules/.bin/` and similar.

### Why this approach

**The risk:** `.husky/` contains git hook scripts that run automatically on commit/push. An LLM editing `.husky/pre-commit` could install a malicious hook that runs every time the user commits — a *persistent* compromise.

**Why protect it:** Hook scripts are executable code paths the user implicitly trusts. The auto-approve in acceptEdits mode is for *content* edits; *executable* paths need explicit consent.

## 4. Rate-limit options dialog infinite-loop fix

**Type:** fix · **Modules:** Auth, UI

### v2.1.88 baseline

`claude-code-kim/src/commands/rate-limit-options/index.ts` ships the dialog. After hitting the usage limit, the dialog opened. If the user dismissed it, *another* limit-event fired (e.g. from a queued message), opening it again — without any debounce. The agent could spin into a crash.

### v2.1.112 fix

The dialog now stores a "last shown at" timestamp and only re-opens after a cooldown (or after the user actively retries). The infinite-loop circuit is broken by the cooldown plus an early-return when the dialog is already mounted.

## 5. Edit/Write "File content has changed" race vs format-on-save

**Type:** fix · **Modules:** Tools (Edit, Write), Hooks

### v2.1.88 baseline

`claude-code-kim/src/utils/attachments.ts:2151` mentions:
> auto-save/format-on-save hits this race especially often.

So the team **knew** about the race; they hadn't fixed it. The race: PostToolUse hook runs `prettier`/`black` on a just-written file, which rewrites the bytes. The next consecutive Edit sees a *different* `old_string` than what it just read and aborts with "File content has changed."

### v2.1.112 fix

After a PostToolUse format-on-save hook completes, the in-memory file-state cache is *re-populated* from the formatter's output. Subsequent Edits now match against the formatted content rather than the pre-format content.

### Why this approach

**Alternative considered (and rejected):** Disable PostToolUse hooks during multi-Edit sequences. Rejected because it would silently break formatter-on-save for power users.

**Chosen approach:** Treat the PostToolUse output as the new "ground truth" file content. The Edit tool's content-cache reads the file's current bytes after every PostToolUse instead of trusting its own pre-edit snapshot.

**Edge case:** If the formatter *moved* the `old_string` to a different line (e.g. reformatted a function), the next Edit still finds the right anchor. If the formatter *removed* the `old_string` (rare), the Edit fails with a clearer error.

## 6. PreToolUse hooks JSON+exit-2 not blocking

**Type:** fix · **Modules:** Hooks

A PreToolUse hook that emitted JSON to stdout *and* exited with code 2 should block the tool call. v2.1.89 had a bug where the JSON parsing path stripped the exit-code metadata; the result was advisory rather than blocking.

**Fix:** The hook result merger now treats exit-code 2 as authoritative regardless of the JSON body — exit-code wins, JSON adds detail.

## 7. Collapsed search/read summary badge in fullscreen scrollback

**Type:** fix · **Modules:** UI, Fullscreen renderer

A collapsed "Read N files" badge could appear *multiple times* in scrollback when a CLAUDE.md auto-load tool call interleaved with the same group. Group identity now keys on (turn, tool, file-set) instead of just (tool); CLAUDE.md auto-loads no longer split a group apart.

## 8. Auto-mode boundary respect ("don't push", "wait for X")

**Type:** behavior · **Modules:** Auto mode classifier

Auto mode previously ignored explicit user boundaries phrased as conditional negatives ("don't push", "wait for me to confirm before X"). The classifier was scoring tool calls only against tool-level safety rules, not against *recent user instructions*.

**Fix:** Recent user instructions in the conversation are now first-class inputs to the classifier. A user saying "don't push" suppresses any subsequent `git push` regardless of allow rules.

**Why this approach:** The previous design assumed the model would just follow instructions — but in autopilot, the model can drift, and the classifier was meant to be the safety net. Now the safety net itself remembers boundary instructions.

## 12. PowerShell tool: hardened permission checks (4 specific bypass classes)

**Type:** security · **Modules:** PowerShell tool

Four distinct PowerShell hardening fixes:

### 12a. Trailing `&` background-job bypass
PowerShell's `cmd & cmd` is a *parallel start* (background job in PS 7+). The permission check was matching against the head command and ignoring the trailing background command, letting it bypass.

### 12b. `-ErrorAction Break` debugger hang
A command using `-ErrorAction Break` would drop into the PS debugger on error, hanging the tool indefinitely. Now denied at parse time.

### 12c. Archive extraction TOCTOU
`Expand-Archive` followed by writing into the extraction target is a time-of-check-time-of-use race: an attacker between check and use could swap the destination directory. Now the extraction is performed inside a sandboxed temp directory.

### 12d. Parse-fail fallback deny-rule degradation
When the PS parser failed (malformed command), the permission system fell back to *prompting* the user — but if the user had a deny-rule that *would have* matched the unparseable command, the fallback prompt incorrectly upgraded a deny → ask. Now parse-fail respects deny rules.

## 13. Performance — three perf wins

### 13a. Per-turn `JSON.stringify` of MCP tool schemas eliminated
The system prompt's tool-list section was being JSON.stringify'd on every turn for the *cache key*. Now the stringification is cached and only redone when tool schemas actually change. Pairs with the v2.1.89 prompt-cache fix.

### 13b. SSE transport linear-time large frame handling (was quadratic)
Streaming SSE frames over MCP HTTP/SSE were being parsed with `string += chunk` in a loop — O(n²) for large frames. Now uses a Uint8Array buffer with index-based parsing.

### 13c. SDK long-conversation transcript writes — quadratic → linear
Each transcript append was rewriting the whole file. Now appends with a fixed-size offset and only rewrites on rotation.

## 15. `--resume` picker excludes `claude -p`/SDK sessions

**Type:** UX · **Modules:** Resume picker

Headless and SDK sessions were polluting the interactive resume picker. Now the picker filters out sessions where `sessionSource === "headless"` or `"sdk"`, keeping only interactive ones.

## 16. DNS cache commands removed from auto-allow

**Type:** privacy · **Modules:** Bash permissions

`Get-DnsClientCache` (Windows PowerShell) and `ipconfig /displaydns` were on the auto-allow list. Removing them is a privacy fix: DNS cache reveals what hosts the user has been visiting (work, financial, etc.), which a malicious LLM could exfiltrate via `WebFetch`.

## Summary

v2.1.90 is **education + hardening**. `/powerup` is the user-visible feature; the rest is paying down race conditions (Edit/format-on-save, rate-limit dialog), security regressions (PowerShell, `.husky`), and quadratic perf on MCP/SDK paths.
