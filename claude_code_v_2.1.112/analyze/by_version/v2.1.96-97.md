# v2.1.96 — Bedrock 403 hotfix

## 1. Bedrock 403 "Authorization header is missing" regression (FIXED)

**Type:** fix · **Modules:** Bedrock auth

### v2.1.94 regression

In v2.1.94 the auth orchestration was refactored for Mantle support. A side effect: when using `AWS_BEARER_TOKEN_BEDROCK` or `CLAUDE_CODE_SKIP_BEDROCK_AUTH`, the *Authorization* header wasn't being attached to the request.

### v2.1.96 fix

Single-line fix in the Bedrock auth attachment step: explicitly populate the Authorization header from `AWS_BEARER_TOKEN_BEDROCK` when SigV4 is skipped.

**Why a hotfix?** Bedrock users were 100% broken on this codepath after v2.1.94. The team shipped a one-fix release rather than wait for v2.1.97.

# v2.1.97 — NO_FLICKER stabilization, Bash hardening, Focus view

## 2. Focus view (Ctrl+O) in NO_FLICKER mode (NEW)

**Type:** feature · **Modules:** Fullscreen renderer

### What it does

Pressing `Ctrl+O` in NO_FLICKER mode toggles a "focus view" that shows only:
- The current prompt
- A one-line tool summary with edit diffstats
- The final response

Hidden: turn-by-turn streaming, intermediate tool calls, status messages.

### Why this approach

**The pain point:** In long sessions with dozens of tool calls per turn, the *final answer* gets buried. Users want to compare "what I asked" vs "what I got" without scrolling through 200 lines of intermediate state.

**Why Ctrl+O:** It already mapped to "toggle transcript visibility" in the regular renderer. Reusing the chord in NO_FLICKER for an analogous (but more powerful) action gives users muscle-memory consistency.

**Note:** v2.1.110 splits this — `Ctrl+O` becomes "verbose toggle only," and focus view moves to a separate `/focus` command.

## 3. `refreshInterval` status line setting (NEW)

**Type:** feature · **Modules:** Status line

### v2.1.88 baseline

`claude-code-kim/src/services/analytics/growthbook.ts:786,1017` already uses a `refreshInterval` for feature-flag refresh — but the user-facing status line had no per-line refresh interval. Custom status lines refreshed only on agent state change.

### v2.1.112 change

A `refreshInterval` setting in the `statusLine` config: `{ "refreshInterval": 5 }` re-runs the status line command every 5 seconds.

### Why this approach

**Use case:** A status line that shows current git branch + dirty status + active task. Without periodic refresh, the dirty indicator goes stale when the user makes a file change outside of Claude Code.

**Why not push-based:** Watching the filesystem for status-line-relevant changes would require knowing what each user's status line cares about. A pull-with-interval is simpler and lets the user choose the cadence.

## 6. Cedar policy syntax highlighting (NEW)

**Type:** feature · **Modules:** Syntax highlight

```javascript
// chunks.102.mjs (highlight grammar)
xZz = (q) => ({
  name: "Cedar",
  aliases: ["cedarpolicy"],
  keywords: {
    keyword: "permit forbid when unless if then else in has like is",
    built_in: "principal action resource context decimal ip contains containsAll containsAny",
    // ...
  }
});
```

Files with `.cedar` or `.cedarpolicy` extensions now get syntax highlighting in Read/Edit views.

### Why this approach

**Why Cedar specifically:** Cedar is AWS's open-source authorization policy language. It's seeing rapid adoption in IaC contexts. Users editing `.cedar` files were getting unhighlighted plain text, making `permit/forbid` blocks hard to scan.

**Why ship a custom grammar:** Cedar isn't in the standard highlighting library bundle. Bundling our own grammar avoids a dependency update.

## 7. `--dangerously-skip-permissions` not being downgraded (FIXED)

**Type:** security · **Modules:** Permissions

### Bug

After approving a write to a protected path via Bash (e.g. someone accepted a write to `~/.ssh/config` once), the permission mode was being silently downgraded from `bypassPermissions` to `acceptEdits`. The user thought they were still in bypass mode but were actually in a stricter mode.

### Fix

The "approve once for protected path" path no longer mutates the global permission mode; it tracks per-path approvals separately.

---

## 8. Bash permission tightening (multi-fix)

**Type:** security · **Modules:** Bash permissions

A wave of perm-rule tightening:
- Env-var prefixes (`FOO=bar git push`) now require the var to be on a known-safe list (`LANG`, `TZ`, `NO_COLOR`, etc.). Unknown var prefixes prompt.
- `/dev/tcp/...` and `/dev/udp/...` redirects now prompt instead of being auto-allowed.
- Backslash-escaped flags (`\-rm`) no longer get auto-allowed as read-only.
- Compound commands (`ls && git push`) bypassing forced permission prompts: fixed.
- `cut -d /`, `paste -d /`, `column -s /`, `awk '{print $1}' file`, filenames containing `%`: false-positive prompts removed.

### Why this approach

The Bash permission classifier had several "sneaky path" bugs accumulated over months. v2.1.97 (and v2.1.98) does a cleanup pass.

**The recurring pattern:** A user complained about a false prompt → team adds an exception → exception widens the auto-allow surface → attacker finds a new bypass → team tightens. v2.1.97 is the "tightening" half of the cycle.

## 9. JS prototype-property permission rule names

**Type:** fix · **Modules:** Permissions, Settings

### Bug

A permission rule with a name matching a JavaScript prototype property (`toString`, `hasOwnProperty`, `__proto__`) caused `settings.json` to be silently ignored at parse time — because the rule was being installed as a property of an object created via `{}` and conflicted with the prototype chain.

### Fix

Use `Object.create(null)` for the rule registry, removing the prototype chain.

---

## 10. Managed-settings allow rules sticky after admin removal

**Type:** fix · **Modules:** Permissions, Managed settings

When an admin removed an allow rule from managed settings, in-process Claude Code sessions kept the rule active until restart. Now the rule revocation propagates immediately on next refresh.

---

## 11. `permissions.additionalDirectories` mid-session changes

**Type:** fix · **Modules:** Permissions

Two related bugs:
- Adding a directory to `additionalDirectories` didn't take effect until restart.
- Removing a directory revoked access only after restart.

Both fixed by re-reading additionalDirectories on settings change events. Specifically:
- Removing a directory from `additionalDirectories` now revokes access to the same directory passed via `--add-dir` (was previously double-counted).

---

## 12. MCP HTTP/SSE buffer leak (~50 MB/hr)

**Type:** fix · **Modules:** MCP

When MCP HTTP/SSE servers reconnected, the prior connection's stream buffers weren't being released. ~50MB/hour leak in long sessions with chatty MCP servers. Fixed by explicit cleanup in the disconnect handler.

---

## 13. MCP OAuth `oauth.authServerMetadataUrl` config override

**Type:** fix · **Modules:** MCP, OAuth

### Bug

After session restart, the MCP OAuth refresh path wasn't honoring the `oauth.authServerMetadataUrl` override. ADFS and similar IdPs that use a non-discovery-default metadata URL would fail to refresh.

### Fix

The override is now propagated through to the refresh codepath.

---

## 14. 429 retry burning all attempts in ~13 seconds

**Type:** fix · **Modules:** LLM API, Retry

When the server returned a small `Retry-After` (e.g. `Retry-After: 1`), the retry logic was *not* applying exponential backoff. The result: 5 retries × 1s = 5s wasted, then giving up. With backoff: ~1s, ~2s, ~4s, ~8s, ~16s, giving the rate-limiter time to clear.

### Fix

Server `Retry-After` is now treated as a **minimum**; exponential backoff applies on top.

---

## 15. Rate-limit upgrade options disappearing after compaction

**Type:** fix · **Modules:** Rate limit, Compact

After a context compaction, the rate-limit upgrade UI buttons would disappear because they were children of a message that got compacted. Now stored as session-level state outside the message tree.

## 16. `/resume` picker: cluster of fixes

**Type:** UX · **Modules:** Resume picker

- `--resume <name>` opening uneditable: was loading in read-only mode incorrectly.
- Ctrl+A reload wiping search: search state preserved on reload.
- Empty list swallowing navigation: arrow keys now jump to next view.
- Task-status text replacing conversation summary: race condition fixed.
- Cross-project staleness: project filter applies before render.

These are all small fixes accumulated from user reports.

## 17. File-edit diff disappearing on `--resume` >10KB files

**Type:** fix · **Modules:** Resume, Edit tool

For files >10KB, the diff was stored as a reference to a tmpfile. The tmpfile was being garbage-collected before resume could read it. Fixed by persisting >10KB diffs alongside the transcript.

---

## 18. `--resume` cache misses + lost mid-turn input

**Type:** fix · **Modules:** Resume, Attachments

Attachment messages weren't being saved to the transcript reliably. On resume, the cache miss caused full prompt resend. Fixed by ensuring attachments flush to transcript before the next turn.

Also: messages typed while Claude is working weren't being persisted. Now they are.

---

## 19. Subagent worktree leakage to parent Bash tool

**Type:** fix · **Modules:** Subagent, Worktrees

Subagents with worktree isolation or a `cwd:` override were accidentally exposing their working directory back to the **parent** session's Bash tool. Fixed by isolating the parent's cwd state from subagent spawns.

---

## 20. Compaction writing duplicate multi-MB subagent transcripts

**Type:** fix · **Modules:** Compact, Subagent

On a "prompt too long" retry during compaction, the subagent transcript was being written multiple times. The retry path wasn't checking for an existing partial write. Fixed by deduping transcript writes by content hash.

---

## 21. `claude plugin update` "already at latest" for git-based plugins

**Type:** fix · **Modules:** Plugin marketplace

For git-based marketplace plugins, `claude plugin update` was reporting "already at the latest version" even when the remote had newer commits — because the comparison was using the cached marketplace metadata, not a fresh `git ls-remote`.

### Fix

Check `git ls-remote` (cheap) before reporting "already at latest."

---

## 22. Slash command picker breaking on YAML boolean keyword names

**Type:** fix · **Modules:** Plugins, Slash commands

A plugin slash command with frontmatter `name: yes` (or `no`, `true`, `false`) was being parsed by YAML as a boolean, breaking the slash command picker. Fixed by quoting the name field on the parser side.

## 24. Bedrock SigV4 auth — empty string env vars

**Type:** fix · **Modules:** Bedrock

Bedrock SigV4 was failing with 403 when `AWS_BEARER_TOKEN_BEDROCK` or `ANTHROPIC_BEDROCK_BASE_URL` were set to **empty strings** (which GitHub Actions does for unset inputs). Empty-string values are now treated the same as unset.

## Summary

v2.1.96 is a one-fix Bedrock hotfix. v2.1.97 is the **stabilization wave** for everything new in v2.1.89-2.1.94: NO_FLICKER mode bugs, MCP buffer leaks, Bash permissions, sandbox enforcement, `/resume` picker. New features are minor (focus view, Cedar highlighting, refreshInterval). The team treated v2.1.97 as a checkpoint to land all the "we know it's slightly broken" items before pushing v2.1.98's bigger changes.
