# v2.1.107 — Thinking hints sooner

## 1. Thinking hint timing (single change)

**Type:** UX · **Modules:** Thinking indicator

The "thinking..." hint now appears sooner during long operations. Previously the hint had a 3+ second delay; now ~1 second. Users see the indicator faster on slow-starting requests.

**Why:** The previous delay was tuned for fast-starting requests where flickering would be annoying. With extended thinking and slow gateways becoming common, the "fast start" assumption broke.

### Why this approach

**The decision tree:**
1. `FORCE_PROMPT_CACHING_5M` is the hard override — even subscribers can opt out.
2. `ENABLE_PROMPT_CACHING_1H` (or Bedrock-specific) opts in explicitly.
3. Otherwise: subscriber + not in overage = check allowlist.
4. Allowlist gates by session source (`repl_main_thread*`, `sdk`, `auto_mode`).

**Why an allowlist:** 1-hour TTL is more expensive per cache entry but cheaper for users with long-running sessions. Rolling out via allowlist lets the team gate by session type.

**Why subscriber-only:** API-key users pay-per-token; the 1-hour TTL would reduce their costs but increase Anthropic's. The subscription tiers offset the cost-shift.

**Trade-off:** A user who toggles between long-form work (where 1h helps) and short ad-hoc queries (where 5min is fine) gets one TTL applied to both. The `FORCE_PROMPT_CACHING_5M` knob lets them downgrade for individual sessions.

## 3. `/recap` slash command (NEW)

**Type:** feature · **Modules:** Slash commands

### v2.1.88 baseline

`claude-code-kim/src/services/awaySummary.ts` (and `useAwaySummary.ts`) already exist — they generate a 1-3 sentence recap when the user returns after 5+ minutes of idle. **No `/recap` command yet** — the recap was implicit (auto-shown on focus return), not explicit.

### v2.1.112 state


The same recap generator (powered by the v2.1.88 `awaySummary.ts` infrastructure) is now also accessible on demand via `/recap`. The footnote "force with `CLAUDE_CODE_ENABLE_AWAY_SUMMARY` if telemetry disabled" lets users in DISABLE_TELEMETRY environments still use the feature.

### Why this approach

**The pattern:** A feature exists internally (auto-recap on idle return) → user research shows people want to *trigger* it explicitly → expose as a slash command.

**Why `disableModelInvocation` is *not* set here:** Recap *does* invoke a small fast model to summarize. Different from `/team-onboarding` (which is purely deterministic).

**Why "tengu_sedge_lantern" feature gate:** Staged rollout — even though the feature is "complete," wrap it in a flag so it can be disabled remotely if quality issues surface.

## 4. Model can discover and invoke built-in slash commands via Skill tool

**Type:** feature · **Modules:** Skills, Slash commands

A long list of built-in slash commands (`/init`, `/review`, `/security-review`, etc.) is now exposed to the model via the Skill tool. The model can decide to run `/security-review` on its own without the user typing the command.

### Why this approach

**The shape:** Pre-2.1.108, slash commands were *user-only* — even though they're useful actions the model could decide to take. The model had to type out instructions and the user had to manually invoke the command.

**The reframe:** Slash commands are just skills with a particular registration pattern. Letting the model invoke them via the Skill tool unifies the surface.

**Trade-off:** A model that calls `/security-review` autonomously might do so unnecessarily, burning tokens on review operations. Mitigated by (a) only "safe" built-ins are exposed, and (b) the Skill tool's existing rate limits.

## 6. `/model` warning before mid-conversation switch

**Type:** UX · **Modules:** /model

If you switch models mid-conversation, the next response re-reads the entire history *uncached* (because cache is keyed by model). For long sessions this is expensive.

`/model` now shows a warning ("This will cost ~X uncached tokens on the next turn") before confirming the switch.

### Why this approach

**Cost transparency.** A user switching from Sonnet to Opus mid-session might burn 50k uncached tokens; previously they only noticed in `/cost` later.

# v2.1.109 — Single change

## 26. Extended-thinking indicator with rotating progress hint

**Type:** UX · **Modules:** Thinking indicator

The thinking indicator now rotates through progress hints ("Considering edge cases…", "Tracing dependencies…", "Reviewing trade-offs…") so users have a sense of what's happening during long thinking phases.

### Why this approach

**The shape:** Extended thinking can take 30+ seconds. A static "thinking..." indicator is unhelpful at that scale. The rotating hints give a *cosmetic* sense of progress without claiming anything specific about what the model is actually doing.

**Trade-off:** The hints are heuristic, not real progress. Users who'd rather see a spinner can disable.
