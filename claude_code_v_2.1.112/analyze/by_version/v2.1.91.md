## 1. MCP `_meta["anthropic/maxResultSizeChars"]` annotation (NEW)

**Type:** feature · **Modules:** MCP, Tools

### v2.1.88 baseline

`claude-code-kim/src/Tool.ts:466` defines `maxResultSizeChars` as a per-tool *static* property, e.g. 100,000 for most tools, 20,000 for Grep. MCP tools used a fixed default with no way to override.

### v2.1.112 change

MCP servers can now override the cap per-tool via the standard MCP `_meta` annotation:

```javascript
// ============================================
// adaptMcpToolWithMetaOverride - apply _meta annotations to MCP tool wrapper
// Location: chunks.162.mjs:578-617
// ============================================

// ORIGINAL (for source lookup):
return _.map((Y) => {
  let A = tC(q.name, Y.name),
      O = Y._meta?.["anthropic/maxResultSizeChars"],
      w = typeof O === "number" && Number.isFinite(O) && O > 0;
  return {
    ...Zz7,
    name: z ? Y.name : A,
    // ...
    maxResultSizeChars: w ? Math.min(O, Vg1) : Zz7.maxResultSizeChars,
    persistenceThresholdCeiling: w ? Vg1 : void 0,
    // ...
  }
});

// READABLE (for understanding):
return mcpListedTools.map((toolDef) => {
  const fqn = formatToolName(server.name, toolDef.name);
  const requestedMax = toolDef._meta?.["anthropic/maxResultSizeChars"];
  const hasValidOverride =
    typeof requestedMax === "number" &&
    Number.isFinite(requestedMax) &&
    requestedMax > 0;
  return {
    ...defaultMcpToolBase,
    name: stripPrefixForSdk ? toolDef.name : fqn,
    maxResultSizeChars: hasValidOverride
      ? Math.min(requestedMax, MCP_MAX_RESULT_HARD_CEILING)  // Vg1 = 500_000
      : defaultMcpToolBase.maxResultSizeChars,
    persistenceThresholdCeiling: hasValidOverride ? MCP_MAX_RESULT_HARD_CEILING : undefined,
    // ...
  };
});

// Mapping: Y→toolDef, A→fqn, O→requestedMax, w→hasValidOverride,
//          Zz7→defaultMcpToolBase, Vg1→MCP_MAX_RESULT_HARD_CEILING (500000), tC→formatToolName
```

### Why this approach

**What it does:** An MCP server can advertise per-tool `_meta: {"anthropic/maxResultSizeChars": 250000}` to lift the default cap (typically 25–100k) up to a hard ceiling of **500,000** (`Vg1 = 500000` in `chunks.83.mjs`).

**How it works:**
1. The MCP server lists its tools with `_meta` annotations on each.
2. Claude Code reads `_meta["anthropic/maxResultSizeChars"]` per tool.
3. If the value is a positive finite number, the wrapper takes `min(value, 500_000)`.
4. The token-based persist layer (which would otherwise truncate for the model) is bypassed up to that ceiling — `persistenceThresholdCeiling` is set so the result skips the persist truncation gate too.

**Why this approach (vs a single global flag):**
- Some MCP tools legitimately need large output (DB schema dumps, API listings, file trees). Global tightening would break them.
- Some tools should *stay* tight (a search tool returning 500k of matches is noise). Global loosening would hurt these.
- Per-tool annotation lets the server author know best.

**Why a hard 500k ceiling:**
- 500k chars ≈ 125k tokens, fitting in even a 200k-context model with room left.
- A larger ceiling would tempt MCP servers to dump entire databases per call.

**Edge cases:**
- Negative or non-finite values: ignored, falls back to default. `Number.isFinite(O) && O > 0` is the gate.
- Annotations on a non-MCP tool: not honored. Only MCP tools (which take their tool list from a remote server) honor the annotation.

## 2. `disableSkillShellExecution` setting (NEW)

**Type:** security · **Modules:** Skills, Slash commands, Plugins

### v2.1.88 baseline

Skills and custom slash commands were allowed to run inline shell commands (`!command` syntax in skill body). No way to globally disable this.

### v2.1.112 change

A new `disableSkillShellExecution: true` setting in `settings.json` disables inline shell execution across:
- Skills (Markdown body with `!command` segments)
- Custom slash commands
- Plugin commands

When set, those segments are *rendered as text* instead of executed.

### Why this approach

**The risk:** Skills authored by third parties (plugin marketplace) can embed shell commands. Even with permission prompts, a sufficiently sneaky skill could trick the user into approving — and skills are pre-loaded silently into the session. An enterprise admin wants a **policy-managed** off-switch, not per-command vigilance.

**Why a setting (not a permission rule):**
- Permission rules are evaluated per-call; this needs to be evaluated *at parse time* so the skill can't construct novel commands at runtime.
- Setting allows admins to enforce via managed settings (locked from the user).

**Trade-off:** Disabling this kills a lot of legitimate utility (init scripts, env probing). The setting is **opt-in** rather than default.

## 3. Plugin `bin/` executables → bare commands

**Type:** feature · **Modules:** Plugins, Bash tool

Plugins can now ship executables under `bin/` and the Bash tool will resolve them as bare commands.

### v2.1.88 baseline

Plugins could ship slash commands and skills, but binaries had to be invoked with full paths (`./node_modules/my-plugin/bin/foo`). No PATH integration.

### v2.1.112 change

A plugin's `bin/` directory is added to a per-plugin Bash environment, so the plugin's binaries are accessible by their bare name during a Bash tool call originating from that plugin's slash command/skill.

### Why this approach

**Why scoped to the plugin's tool calls:** Adding `bin/` to a global PATH would let *any* tool call invoke them — which would let a plugin shadow system commands. Scoping to the plugin's own invocations keeps each plugin sandboxed.

**Edge case:** A plugin's `bin/` script could itself shell out to the user's PATH and confuse provenance. Plugins are still trusted code; this is convenience, not isolation.

## 4. Multi-line prompts in `claude-cli://open?q=` deep links

**Type:** fix · **Modules:** URL handler, CLI

`claude-cli://open?q=line1%0Aline2` was being rejected because the URL parser flagged percent-encoded newlines. Now `%0A` is allowed in the `q` param. The fix is a single regex relaxation.

## 5. Transcript chain breaks on `--resume` (async write failures)

**Type:** fix · **Modules:** Resume, Transcript persistence

If a transcript write failed silently (disk full, permission), the chain of message-references-message broke at that point. On `--resume`, the loader would dead-end at the broken link and load only the prefix.

**Fix:** Async transcript writes now have a callback that *retries* on failure (with backoff), and the chain reconstruction in the resume loader can *bridge* over a single missing message by following the next message's `parentId` rather than the previous message's `nextId`.

This is a classic doubly-linked-list reconstruction trick: when one direction breaks, traverse the other.

## 6. `cmd+delete` not deleting to start of line (multiple terminals)

**Type:** fix · **Modules:** Keybindings

iTerm2, kitty, WezTerm, Ghostty, and Windows Terminal each send a different escape sequence for `Cmd+Delete`. The keybinding handler had only the macOS Terminal.app sequence; v2.1.91 adds the rest.

---

## 7. Plan mode in remote sessions: container restart resilience

**Type:** fix · **Modules:** Plan mode, Remote Control

After a container restart, the path to the plan file would change — but the remote session's in-memory plan reference was stale. The user would see a permission prompt on plan edits and an empty plan-approval modal.

**Fix:** Plan file path is now resolved on each access, not cached. The marginal cost of a `realpath` call per access is tiny compared to the bug.

## 8. JSON schema validation for `permissions.defaultMode: "auto"`

**Type:** fix · **Modules:** Settings

The settings.json schema didn't include `"auto"` in the `defaultMode` enum, even though auto mode was implemented. Setting it caused a validation error on session start. Schema enum updated.

## 9. Windows version cleanup protecting active rollback copy

**Type:** fix · **Modules:** Updater

The Windows updater scrubbed old versions but accidentally included the *current* version's rollback copy in the scrub list. Now the active version's rollback artifact is exempted explicitly.

## 12. `stripAnsi` perf — Bun.stripANSI on Bun

**Type:** perf · **Modules:** Output rendering

When running on Bun, ANSI stripping now uses `Bun.stripANSI` natively instead of a regex pass. ~10x faster for large outputs.

## 13. Edit tool shorter `old_string` anchors

**Type:** perf · **Modules:** Edit tool

The Edit tool's prompt now suggests using *shorter* `old_string` anchors when uniqueness is satisfied. This reduces output tokens (model writes fewer chars) without sacrificing correctness.

**Trade-off:** Shorter anchors are slightly more likely to be ambiguous in pathological files. The tool falls back to demanding a longer anchor on ambiguity.
