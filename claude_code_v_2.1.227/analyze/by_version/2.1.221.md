# Claude Code 2.1.221 Implementation Analysis

## Release shape

The supplied 2.1.221 section has 39 bullets. It is primarily a hardening and state-lifecycle release:
permissions became more conservative, previously ephemeral UI state became durable, background work
became more isolated, and several startup or retry paths stopped trusting stale state.

## Implementation themes

1. **Permission correctness.** Bash and PowerShell parsing rejects constructs that cannot be shown and
   authorized faithfully. Auto-mode decisions share the conversation prefix and invalidate queued
   answers when the permission mode changes. See
   [`38_permissions`](../38_permissions/permission_engine_and_auto_mode.md).
2. **Credential containment.** Linux/WSL sandbox masking separates the secret value visible to the
   egress proxy from the sentinel visible to a child process. See
   [`49_sandbox`](../49_sandbox/credential_masking_and_sigv4.md).
3. **MCP startup and identity.** Explicit MCP configuration participates in the print-mode readiness
   barrier, and connector/token refresh uses coordinated ownership. See
   [`39_mcp`](../39_mcp/mcp_runtime_configuration_auth_and_discovery.md).
4. **Durable interaction state.** Focus view, screen-reader deletion, Vim registers, emoji aliases, and
   plugin notifications all move state to the component or session lifetime that actually owns it. See
   [`48_accessibility_ui`](../48_accessibility_ui/README.md) and
   [`43_slash_commands`](../43_slash_commands/slash_command_registry_dispatch_and_menu.md).
5. **Work isolation.** Forked sessions receive their own worktrees; background sessions preserve work
   and report its location. See [`36_background_agents`](../36_background_agents/README.md) and
   [`53_subagent_limits`](../53_subagent_limits/delegation_and_containment.md).
6. **Plugin usability.** Validation understands Desktop marketplace constraints, root skills can use
   `"."`, installation retries after refreshing a stale catalog, and safe installs activate without a
   mandatory reload. See [`45_skills`](../45_skills/README.md).
7. **Model/runtime repair.** Thinking can be re-enabled after an initially disabled session, Vertex tool
   search is capability-gated, and fast-mode exhaustion is surfaced on-stream. See
   [`47_models`](../47_models/README.md) and [`57_api_reliability`](../57_api_reliability/README.md).

### Cache-efficient parallel permission classification

**What it does:** Evaluates parallel tool calls without rebuilding the entire classifier prompt for
each call and prevents a result computed under one mode from being applied under another.

**How it works:**
1. Requests enter a serialized classifier queue carrying the permission-mode generation they observed.
2. The stable conversation prefix is cached and reused across decisions; only action-specific suffixes
   differ.
3. Independent tool decisions can be prepared together while the model-facing classifier still sees a
   coherent context.
4. Before applying a result, the runtime compares the queued mode with the current mode.
5. A mismatch invalidates the stale automatic result and returns to an explicit prompt path.

**Why this approach:**
- Reusing the stable prefix lowers prompt-cache cost and latency for parallel calls.
- Applying old answers would be cheaper but unsafe after the user changes permission mode.
- Fully parallel classifier requests would reduce queue latency but duplicate prompt work and make mode
  changes harder to order.

**Key insight:** The optimization is valid because cache reuse and decision freshness are separated:
the prompt prefix may be old and reusable, while the permission-mode generation must still be current.
