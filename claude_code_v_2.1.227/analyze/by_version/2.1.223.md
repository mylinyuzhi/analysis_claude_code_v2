# Claude Code 2.1.223 Implementation Analysis

## Release shape

The supplied 2.1.223 section has 19 bullets. It combines three architectural cleanups: inputs are
normalized before security decisions, model/context policy is derived from capabilities instead of
hardcoded model lists, and code review is consolidated behind one command/state machine.

## Implementation themes

- Marketplace policy parses `owner/*` as a typed wildcard while preserving exact repository rules.
  See [`45_skills`](../45_skills/plugin_archive_and_marketplace_policy.md).
- Bash permission parsing and approval rendering normalize invisible Unicode and padding so the
  inspected command matches the command shown to the user. Workflow dynamic imports are rejected by
  AST instrumentation before VM execution. See [`38_permissions`](../38_permissions/README.md) and
  [`42_workflow`](../42_workflow/workflow_runtime_sandbox_scheduler_and_resume.md).
- The organization bypass-permissions policy remains authoritative even when an agent definition asks
  for bypass mode. See [`38_permissions`](../38_permissions/permission_engine_and_auto_mode.md).
- Model discovery canonicalizes provider-prefixed IDs, and unknown `modelOverrides` keys do not become
  canonical model identities. See [`47_models`](../47_models/catalogue_and_provider_architecture.md).
- Native-1M and unknown model context enforcement moved to catalog/assumed-window policy. See
  [`07_compact`](../07_compact/context_window_enforcement.md).
- `/review` became an alias of `/code-review`; explicitly typed effort is remembered and participates
  in local/workflow/fork routing. See [`52_code_review`](../52_code_review/README.md).

### Capability-derived context-window enforcement

**What it does:** Applies the 200K containment policy to every model known to have a native 1M window,
and gives unknown model IDs a conservative assumed limit.

**How it works:**
1. Model resolution first obtains the canonical catalog entry when one exists.
2. The runtime reads native context capability from that entry instead of checking a fixed model-name
   list.
3. With the 1M-disable switch active, a native-1M model receives a 200K effective window and an
   auto-compaction expectation.
4. Unknown IDs receive the assumed context window rather than being allowed to grow without a bound.
5. Explicit environment escape hatches can restore the legacy unknown-model behavior.
6. Startup diagnostics warn when the selected constraints and active auto-compaction state disagree.

**Why this approach:**
- Catalog capability survives provider prefixes, aliases, and new model releases better than a list of
  hardcoded names.
- Conservative unknown-model handling prevents an unrecognized gateway alias from silently disabling
  compaction.
- An escape hatch retains compatibility for custom gateways that can prove a larger window.

**Key insight:** Context safety follows resolved capability and explicit policy, not the spelling of the
user's model string.

### Unified code-review command state

**What it does:** Routes `/review` and `/code-review` through one parser while remembering only the
effort the user explicitly selected.

**How it works:**
1. Both command names enter the same registration and argument parser.
2. Parsing separates effort, target, and behavior flags before route selection.
3. An explicitly typed effort updates persisted review preference; omitted effort reuses it.
4. Organization/model policy adjusts the effective level without overwriting the user's remembered
   preference.
5. Repository state and effective effort choose inline review, local fork/workflow, or deep cloud review.

**Why this approach:**
- One parser prevents alias behavior from drifting from the primary command.
- Separating requested and effective effort avoids persisting a temporary policy downgrade as user
  intent.
- A standalone legacy `/review` implementation would preserve compatibility at the cost of two
  increasingly divergent review systems.

**Key insight:** Compatibility is implemented at command registration, before parsing and state
mutation, so the alias inherits the complete modern review pipeline.
