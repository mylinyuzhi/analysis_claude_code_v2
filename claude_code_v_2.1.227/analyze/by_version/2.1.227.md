### Refresh-before-feature-attributes initialization

**What it does:** Ensures that feature evaluation receives the current subscription and rate-limit tier
when a session starts with an expired access token.

**How it works:**
1. Feature-client creation becomes an asynchronous, shared initialization promise.
2. In a trusted workspace it attempts OAuth refresh before resolving feature-evaluation identity.
3. The refresh has a five-second startup bound so an unavailable auth service cannot hang startup.
4. Auth headers are resolved after refresh.
5. User attributes are captured last and include account, organization, subscription type, and
   rate-limit tier from refreshed token/profile state.
6. The feature client records bearer and account identity; later rotation or account change triggers
   controlled reinitialization.
7. Generation checks reject a late initialization result after reset or disposal.

**Why this approach:**
- The 2.1.220 constructor already included tier fields, but captured them before refresh. Adding fields
  again would not fix the ordering bug.
- Refresh-before-snapshot makes the dependency explicit while one shared promise contains its cost.
- Bounded fallback preserves startup availability, with reinitialization available after transient auth
  recovery.

**Key insight:** The fix is temporal rather than structural: tier fields must be read after the expired
credential has been renewed.

### Unicode-safe slash-command matching and presentation

**What it does:** Separates row selection styling from match emphasis and preserves user-visible glyphs
for emoji and accented command names.

**How it works:**
1. Search normalization builds a comparison representation without replacing the original display
   string.
2. Fuzzy matching records positions against stable Unicode-aware units.
3. Rendering slices the original glyph sequence at matched positions.
4. The selected row alone receives the blue selection treatment.
5. Matched characters receive bold emphasis without being recolored.
6. Empty and no-match states preserve deterministic row selection and keyboard navigation.

**Why this approach:**
- Matching directly on transformed ASCII text loses accents and emoji in the rendered result.
- Recoloring every match competes visually with selection state; bold provides an independent channel.
- Keeping normalized and display representations costs extra index bookkeeping but preserves both
  search quality and glyph fidelity.

**Key insight:** Search normalization is an internal comparison tool, not a replacement display value.

### Awaited optional filesystem probes

**What it does:** Removes synchronous directory/stat calls from interactive suggestion and at-mention
validation paths.

**How it works:**
1. A missing-file diagnostic awaits an asynchronous parent-directory listing before calculating similar
   names.
2. At-mention validation awaits asynchronous metadata before deciding whether to inline or summarize a
   file.
3. The enclosing suggestion/attachment functions become async and propagate the decision through their
   existing result contract.
4. Required file reads retain their separate size-aware streaming implementation.
5. Errors remain optional-diagnostic failures and do not turn a missing suggestion into a process-level
   exception.

**Why this approach:**
- These probes improve UI feedback but do not justify blocking the Node.js event loop.
- Worker threads would add coordination overhead for operations already supported by asynchronous
  filesystem APIs.
- The change introduces promise propagation, but confines it to paths that were already preparing
  asynchronous user input.

**Key insight:** The optimization targets optional metadata work around a file operation, not the
correctness-critical read itself.

## Other two fixes

- The GitHub Action path treats `allowed_non_write_users` as subprocess-scrub state rather than a
  blanket Bash denial. This keeps the security setting out of child command evaluation while retaining
  it at the CI host boundary.
- `/tui` persists the empty rewind leaf. Resume therefore distinguishes “no message remains after this
  rewind” from “no rewind choice was recorded,” so it cannot fall back to the pre-rewind conversation.
