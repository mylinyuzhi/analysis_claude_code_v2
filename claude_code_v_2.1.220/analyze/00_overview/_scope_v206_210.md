# Changelog scoping + anchor probe: 2.1.206-2.1.210

**Range**: 5 published releases, **131 changelog bullets** (`.206`=27, `.207`=24, `.208`=46, `.209`=1,
`.210`=33). Bundles compared: TARGET `2.1.220/extract/cli_inner_pretty.js` (872,596 lines) vs BASELINE
`2.1.193/extract/cli_inner_pretty.js` (718,679 lines). Every `220=N / 193=M` pair below is a
`grep -cF` (or `grep -cE`, marked) count I ran myself against **both** files in one invocation; every
`Best 220 line` is a line whose actual text I opened and read in the 2.1.220 bundle. Where I could not
land an anchor I say UNANCHORED and record what I tried, rather than inventing a delta.

**Shape of these releases.** This is the **hardening-and-hygiene** stretch of the window, and it is
front-loaded with *security* work rather than features. Three of the five releases contain a genuine
privilege-boundary fix with a clean one-to-one code anchor: `.207` stops `autoMode` classifier rules
from being read out of repo-resident `settings.local.json` (`:63554-63563`) and stops `pluginConfigs`
from being read out of project settings at all (`a5g = ["userSettings","flagSettings","policySettings"]`,
`:191083`), and rejects `${user_config.*}` interpolation into shell-form plugin hooks / monitors /
`headersHelper` (three separate refusal sites); `.210` stops the `ultracode` keyword from firing on
non-human input (`isHumanTypedPrompt`, `:516671`) and adds an instruction-shaped-pattern scrubber to
subagent output (`:345365-345393`). `.208` is the single largest bullet block in the whole window (46
bullets) and is **overwhelmingly a performance/memory release**: 11 of its 46 bullets are explicitly
about resource use, and they land as real, readable constants — `zCy = 50` (LSP document LRU),
`_Up = 200` (markdown-table row cap), `WU_ = 2` (apiKeyHelper attempts before surfacing), a precomputed
deny-rule array threaded through `WB` (`(r ?? mM(e))`, `:513296`) that fixes both the per-turn
permission-matching cost and the per-tool-call tool-pool cost with the same change. `.209` is a
one-bullet revert whose narrowed guard is directly visible (`unavailable_in_agent_view` + a `/model`
carve-out at `:806776`/`:806788`). The two big traps in this range are `.208`'s *"Added screen reader
mode"* (all three surfaces already exist in 2.1.193 — see `_GROUND_TRUTH` §3) and `.207`'s *"default to
Claude Opus 4.8"* on Bedrock/Vertex, which **2.1.220 has already overwritten with `claude-opus-5`**
(`:14465-14469`) — a value-level supersession that a pure changelog reading gets wrong.

### Notes

- **Richest finding (#17 + #27, one cluster).** `claude rm` and the agent-view Ctrl+X path both feed
  `deleteJob` (`Z3e`, `:681118`), which in 2.1.220 calls the daemon kill with a **new protocol field**:
  `CJe(e, r ?? void 0, { knownGone: t.knownGone, evict: !0 })` at `:681125` (`evict: !0` is 220=1/193=0).
  The field is declared in the daemon IPC zod schema at `:330157` (`evict: v.boolean().optional()`,
  220=1/193=0) and consumed in the daemon's `case "kill":` arm at `:679374-679376`:
  `if ((f.delete(A.short), A.evict)) rIe((T) => { delete T.workers[A.short]; })`. That single
  `delete T.workers[...]` **is** the "row reappears in `claude agents`" fix — before it, the kill removed
  the live worker but left the roster entry. `leftWorktreeDir` (220=3/193=0, `:683241`) and the six
  `run 'claude rm <id>'` remediation strings (220=6/**193=1**) are the surrounding UX.
- **Richest finding (#5).** `EnterWorktree.checkPermissions` at `:406425-406445` is entirely new
  behaviour: `Scs(e.path)` first asks whether the path is a *managed* worktree (allow silently), then
  builds a display path with a Unicode-confusable scrub (`:406430`), a `resolves to "…"` suffix when
  NFC-normalised realpath differs (`:406434`), and a `(path sanitized for display)` marker
  (220=1/193=0). It returns `behavior: "ask"` with `decisionReason.classifierApprovable: !1` — i.e.
  **auto mode cannot approve this**; only a human can. Three new literals in one block.
- **Richest finding (#2 / #22).** `/doctor`'s `description` (`:785862-785865`) is a single ~1,100-word
  string that enumerates every check, and the `.206` bullets map into it phrase-by-phrase: *"trim
  checked-in CLAUDE.md files by cutting content a session could derive from the codebase (directory
  layouts, tech-stack lists, architecture overviews) while keeping gotchas, rationale, and non-standard
  conventions"*. The Homebrew fix lives in the same prompt corpus at `:785799`, and it is unusually
  explicit about *why*: Homebrew installs choose their channel by **cask name**, and the check must read
  the `/Caskroom/<cask-name>/` path segment rather than `autoUpdatesChannel`. `getHomebrewCaskName`
  220=1/193=0. Note the same prompt also contains *"make auto mode the default permission mode"*, which
  is the target of `.210`'s Bedrock/Vertex/Foundry fix.
- **#21 is a clean mechanism, not a flag flip.** `pluginUsageLspGraceAppliedIds` (220=3/193=0,
  `:214905`) is a one-shot **grace list**: `_Cu` collects every plugin with a non-empty `lspServers`
  map (`:215060`) and calls `hCu` (`:214904-214917`), which back-dates `lastUsedAt`/`lastUsedNumStartups`
  for those plugins *once* and records the ids so it never re-applies. `UBt` (the disuse-tip producer,
  `:499391-499416`) then skips them via `mas(s.repository)` (`:499409`). The reason LSP plugins looked
  disused is that they are never *invoked* — the fix grants them credit rather than changing the
  14-day/10-session thresholds (`mL_ = 14, hL_ = 10`, `:499436`).
- **CARRYOVER trap (#7).** *"an expired login failing every model with a misleading 'There's an issue
  with the selected model' error"* — that exact string is **220=1 / 193=1** (`:228674`, read: it already
  has the `Run ${i} to pick a different model.` suffix). The bullet describes a *routing* change
  upstream of the message, not a new message. Do not write this up as a new string.
- **CARRYOVER trap (#24, #11).** `awsCredentialExport` is 220=12/**193=12** — byte-for-byte the same
  surface; the hang fix is a timeout constant, not a new setting. `tengu_mcp_oauth_refresh_failure` is
  220=2/193=1 but the 2.1.220 bundle contains **two near-identical copies of the MCP client module**
  (`:286969…` and `:297016…`, every `tengu_mcp_oauth_*` gate appears twice), so that doubling is a
  bundling artefact and proves nothing. Recorded UNANCHORED for that reason.
- **UNANCHORED list with what I tried.** #8 (`tengu_fleetview_stdin_contention` is the agents-view
  path, not the `--resume` startup path; `isRawModeSupported` is carryover), #14 (`positionAfter` 0/0,
  `insertAfter` 6/4 all in unrelated code, `entitlement` 23/12 too diffuse), #15 (`A turn is in
  progress` is the `.208` SDK-cwd bullet; no desktop-specific "running" literal), #18 (`Unknown
  command` 3/3, all three sites read — `:343373` is the generic thrower; no logged-out remote-control
  string exists), #20 (no `broken install` / `Duplicate installations` literal in either build),

### Notes

- **Richest finding (#20).** `CCe` at `:63551-63564` runs a **source-provenance filter before parsing
  any rule**: it loops `["projectSettings", "localSettings"]`, and if either carries an `autoMode`
  block that *validates*, it logs
  `settings autoMode in ${s} ignored — only user/flag/managed settings may set classifier rules
  (projectSettings and localSettings are repo-controllable)` and emits
  `tengu_settings_auto_mode_rules_untrusted_source_ignored` (220=1/193=0). The `k6l` latch means the
  warning fires once per process. Note the ordering subtlety at `:63555`: `projectSettings` is skipped
  outright when `ynt()` holds — i.e. there is a mode where project settings are not even *inspected*.
  This is the strongest single "trust boundary moved" anchor in `.207`.
- **Richest finding (#23).** The delta is a *scope allow-list replacing a merged read*. 2.1.193 read
  plugin option values from the fully merged settings accessor (`jo().pluginConfigs?.[e]?.options`,
  `:279505 (193)`, plus five sibling sites). 2.1.220 replaces every read with a scope-specific
  `Pr("userSettings")?.pluginConfigs…` (`:191135`, `:214342`, `:214356`) and adds `Yzr` (`:191064-191077`)
  which merges *only* over `a5g = ["userSettings", "flagSettings", "policySettings"]` (`:191083`,
  220=1/193=0) — exactly the changelog's "user, `--settings`, and managed settings". Total
  `pluginConfigs` count actually went **down** (220=11 / 193=13) because read sites were deleted; a
  shrinking count is the signature of this class of fix.
- **Richest finding (#22).** Three independent refusal sites, all 220-only: hooks at `:519967-519971`
  (`Hook from plugin … references ${user_config.*} in a shell-form command. The substituted value would
  be re-parsed by the shell. Use exec …` + telemetry reason string
  `plugin hook references ${user_config.*} in shell-form command`), monitors at `:764147-764148`, and MCP
  `headersHelper` at `:268208`. Each gives a *different* remediation, matching the changelog's split
  advice — hooks get exec-form/`$CLAUDE_PLUGIN_OPTION_<KEY>`, monitors and `headersHelper` are told to
  read the value inside the script. The schema text that motivates it is at `:59406`
  ("Available as `${user_config.KEY}` in MCP/LSP server config, hook commands, and (non-sensitive only)
  skill/agent content").
- **Richest finding (#3).** `pBd` (`:455660-455684`) now has a **four-way outcome** instead of a boolean:
  `no_check_needed`, `deferred_non_interactive` (220=3/193=0, `:455663`, returned when `D$()` says the
  session is non-interactive), `deferred_no_consent_surface` (220=4/193=0, `:455669`, returned when no
  dialog callback was supplied), and only then the real dialog. Both `deferred_*` values are new in
  this build — meaning 2.1.193 fell through to "approved" on those paths, which is precisely the
  reported security bug.
- **The single most important trap in this range (#19).** *"Changed Bedrock, Vertex, and Claude
  Platform on AWS to default to Claude Opus 4.8"* — in the 2.1.220 model catalogue's alias table
  (`:14461-14486`, read) the `opus` alias resolves `bedrock: "claude-opus-5"`, `vertex:
  "claude-opus-5"`, `anthropic_aws: "claude-opus-5"`. Only `foundry` (`claude-opus-4-6`) and `gateway`
  (`claude-opus-4-7`) still lag. So `.207`'s value was **superseded by `.219`** and is no longer
  observable; the *mechanism* (`per_provider` alias resolution) is the durable finding. Anyone writing
  the `.207` model bullet from the changelog alone will state something the bundle contradicts.
- **CARRYOVER traps.** `disableAutoMode` 220=7/**193=7** (already documented in `_GROUND_TRUTH` §3 —
  the kill switch is not the delta; the *default availability* is, and its onboarding surface is the
  four new `tengu_auto_mode_env_onboarding_*` gates, e.g. `:736553`). `[Pasted text #` 220=3/**193=3**
  (#17 — the placeholder existed; only the re-paste collapse logic changed). `sso_region` 220=9/**193=9**

  pre-exists; the `/dev/null` exemption is inside the predicate).
