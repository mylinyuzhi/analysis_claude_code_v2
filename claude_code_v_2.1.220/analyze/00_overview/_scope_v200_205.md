# Changelog scoping + anchor probe: 2.1.200-2.1.205

**Range**: 6 published releases, **97 changelog bullets** (`.200`=17, `.201`=1, `.202`=18, `.203`=37,
`.204`=1, `.205`=23). Bundles compared: TARGET `2.1.220/extract/cli_inner_pretty.js` vs BASELINE
`2.1.193/extract/cli_inner_pretty.js`. All `220=N / 193=M` numbers below are `grep -cF` counts I ran
myself in both files; every `Best 220 line` is a line I opened and read in the 2.1.220 bundle.

**Shape of these releases.** This is the *background-agent hardening* stretch of the window. Of the 97
bullets, **44 are background-agent / daemon bullets** and they cluster into three genuinely deep
subsystems that all land here: (1) the **daemon lock + handover** protocol (`procStart` pid-reuse
verification, `-dev.YYYYMMDD.tHHMMSS` embedded-build-timestamp recency, roster `parseFailed`
quarantine, socket auth re-key), (2) **turn resumption** (`CLAUDE_CODE_RESUME_INTERRUPTED_TURN` grows
a `MAX_AGE_MS` staleness cut-off plus a stale-turn suppression path), and (3) **worktree isolation
enforcement** (`tengu_agent_worktree_cwd_escape_blocked` with three distinct refusal reasons). Around
that core sit three smaller but very substantial deltas: `.200`'s permission-mode rename
(`default` → **"Manual"** with a `manual`→`default` alias preprocessor and a grey ⏸ footer badge),
`.200`'s screen-reader markdown path (tables rendered as `Header: value.` sentences), and `.205`'s
updater rewrite from `responseType:"arraybuffer"` to a streaming `pipeline` + `createWriteStream`
(the "~400 MB" claim is real and directly readable). `.201` is a single model-gating bullet that
**2.1.220 has since reverted** — the single most important trap in this range. `.202` and `.203` also
carry an unusually high number of Remote-Control / mobile bullets whose client-side literals are
identical in both bundles; those are recorded UNANCHORED rather than dressed up as deltas.

### Notes

- **Richest finding (#1).** `askUserQuestionTimeout` is a full new settings key: `v.enum(["60s","5m","10m","never"])`
  with `.catch(void 0)` at `cli_inner_pretty.js:61218`, described as *"Defaults to never — auto-continue only runs
  when explicitly set to 60s/5m/10m."* The `/config` row (`label: "Question auto-continue timeout"`) is at
  451892 and emits `tengu_ask_user_question_timeout_changed` (220=1/193=0, line 451902). Two more gates in the
  same family, `tengu_ask_user_question_afk_auto_advance` (767111) and `tengu_ask_user_question_skipped`
  (766944), are also 220=1/193=0 — this is a whole subsystem, not a flag flip.
- **Richest finding (#2).** The permission-mode descriptor table changed in place: 2.1.193:54284 reads
  `default: { title: "Default", shortTitle: "Default", symbol: "", color: "text", external: "default" }`;
  2.1.220:58497-58503 reads `title: "Manual", shortTitle: "Manual", indicator: "manual mode", symbol: X4r,
  color: "inactive"`, where `X4r = "⏸"` (⏸) is declared at 58419. The alias is a *preprocessor*, not an
  enum member: `fL(e) { return e === "manual" ? "default" : e }` at 58323, wired into both zod schemas at
  58492-58493 via `tc.preprocess(fL, tc.enum(...))`. The enum `Yye`/`J5` at 58362 still lists only
  `acceptEdits, auto, bypassPermissions, default, dontAsk, plan` — `manual` never becomes a real mode. Note
  60599 documents this: *"('manual' is accepted as an alias for 'default')"*.
- **#3 is a narrow but clean delta.** 2.1.193:280996 used `(t.disabledMcpServers || []).includes(e)` — a
  non-array truthy value (object, number) reaches `.includes` and throws. 2.1.220 adds
  `y_o(e) { return Array.isArray(e) ? e : [] }` at 282778 and routes every read/write through it (282783-282805),
  including a write-side guard `if (c === l && (a === void 0 || Array.isArray(a))) return n`.
- **#4/#5 share one function.** `Y0s` at 320174 is the transcript deserializer. `CLAUDE_CODE_RESUME_INTERRUPTED_TURN`
  is a **carryover env var** (220=18/193=8) but 2.1.220 wraps it in two new guards: `znd()` at 320146 reads
  the new `CLAUDE_CODE_RESUME_INTERRUPTED_TURN_MAX_AGE_MS` (220=6/193=0, default 3 600 000 ms) and walks the
  transcript backwards past `system`/`progress` entries to find the last real timestamp; and the `g` check at
  320238 suppresses resumption when the caller's last-seen uuid still matches the tail (the Esc case).
  `tengu_resume_stale_turn_suppressed` fires at 320211.
- **#6 pid-reuse trap.** `daemon.lock` is 220=4/193=2, so the literal is *not* new. The real delta is the lock
  payload gaining `procStart`: `Y0r(e) { return e.procStart !== void 0 }` at 664792, verified by `cAa` at
  664778 (retries `_L(pid)` with `skipCache` on retry) and by `VAn` at 664769 which reads
  `/proc/${pid}/cmdline` and requires `claude daemon`. `QH()` at 664798 now returns `null` unless kill(0),
  cmdline, **and** proc-start all agree. `mYo` writes through `daemon.lock.tmp.${pid}.${startedAt}` (664741).
- **#7 is the most self-contained security delta in the range.** `rUt(e)` at 552455 parses
  `-dev.YYYYMMDD.tHHMMSS` / `-engine.…` out of a version string into an epoch, round-tripping the format to
  reject bogus matches; `hhp(e,t)` at 552469 is `isOlderBuild`. The supervisor uses it at 870696:

### Notes

- **This is the single most important trap in the whole range.** 2.1.193:150519 hard-codes the true-list:
  `if (n === "claude-fable-5" || n === "claude-mythos-5" || n === "claude-opus-4-8") return !0;` —
  `claude-fable-5` was the pre-launch id for Sonnet 5. 2.1.220:150524 replaces it with a capability lookup:
  `if (M$(r, "mid_conv_system") || r === "claude-mythos-5") return !0;`, where `M$` (14517) resolves the model
  registry entry and tests `capabilities.includes(t)`.
- **But `claude-sonnet-5` *declares* `mid_conv_system`** in its capability array at 14205-14207. So in
  2.1.220 Sonnet 5 **does** use the mid-conversation system role again. The `.201` change was real (the
  `claude-fable-5` special case is gone, 220=0 for that id) but its stated effect has been undone later in
  the window. `claude-sonnet-5` is 220=35 / 193=0; `mid_conv_system` is 220=6 / 193=1.
- Any later doc that claims "Sonnet 5 does not use the mid-conversation system role" from this bullet alone
  will be wrong for 2.1.220. The refactor from id-list to capability flag is the durable delta; the
  behavioural claim is not.
- `CLAUDE_CODE_FORCE_MID_CONVERSATION_SYSTEM` still short-circuits the whole check (220:150507).
