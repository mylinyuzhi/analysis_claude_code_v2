## a) What this release was for

`2.1.201` is a **single-bullet launch hotfix**, and its position in the calendar is the whole story.
`2.1.197` — four releases earlier and itself a single-bullet release — launched **Claude Sonnet 5** as
the new default model, with a native 1M-token context and promotional pricing. `.198`, `.199` and `.200`
then spent 74 bullets stabilising the *autonomy* work that had landed alongside it. `.201` spends its
one bullet stabilising the *prompt transport* for the model that had just become everybody's default.

A one-bullet release means one of three things in this window: a model launch (`.197`, `.219`), a revert
(`.209`), or a hotfix urgent enough not to wait for the next batch. `.201` is the third kind. The bullet
is about the **mid-conversation `role: "system"` channel** — an entry in `messages` with
`role: "system"` appearing after the conversation has started, which the Anthropic Messages API accepts
only on models that support it, and which Claude Code uses to carry harness reminders out-of-band
instead of stuffing them into user turns. The bundle's own `claude-api` skill documents the contract at
`cli_inner_pretty.js:793005`, including the failure mode: *"Unsupported models return a 400
(`role 'system' is not supported on this model`)."*

Between `.197` and `.201`, Sonnet 5 was on that channel. `.201` took it off. **In `2.1.220` it is back
on** — Sonnet 5's catalogue entry declares the capability at `cli_inner_pretty.js:14207`, the capability
resolver returns `true` for it at `:150524`, and the beta header is pushed onto its requests at
`:150547`. That is the reversion. What did *not* come back is the *presentation*: a dedicated predicate
`mro` (`:150395-150397`) — the only place in the entire bundle that tests for `claude-sonnet-5` by
itself — keeps Sonnet 5 out of the new framing sentence and keeps each reminder individually wrapped in
`<system-reminder>` tags. So the bytes Sonnet 5 sees are, tag for tag, what it saw before `.197`. Only
the envelope changed.

That is why a naive reading of this release goes wrong in both directions. Read the changelog alone and
you conclude Sonnet 5 avoids the system role — false for `2.1.220`. Read
[`../_GROUND_TRUTH_verified_anchors.md`](../_GROUND_TRUTH_verified_anchors.md) §6.3's headline sentence
alone and you conclude the hotfix was simply undone — also false, and it would lead you to describe
Sonnet 5's prompt as containing a sentence it never receives. The correct statement is the one in the
callout above, and §c derives it line by line.

The deeper reason the fix had to be re-shaped is visible in `.211` and `.212`, ten and eleven releases
later: by then the `role: "system"` turn was no longer *just* where reminders go. It carries the
conversation's **prompt-cache breakpoint** (`.211`) and a **per-turn reasoning-effort directive**
(`per-turn-control-2026-07-01`, `:109215`, **220=1 / 193=0**). Branching the capability resolver for
Sonnet 5 — which is exactly what `.201` did — would have cut the *default model* out of both, as
collateral damage, because both are gated on the same `Ser(model)` boolean. Moving the carve-out down to
the serialization layer buys the uniform transport and keeps the familiar presentation. `.201` is
therefore best read not as a fix that was reverted, but as **the first attempt at a carve-out that later
had to move layers** to stop costing the default model two unrelated features.

## c) Deep dive — the reversion, the shim, and the three framing states

[40_system_prompt/mid_conversation_system_role.md](../40_system_prompt/mid_conversation_system_role.md)
derives the whole subsystem (§2 the resolver, §3 the shim, §4 placement, §5–6 caching, §7 the effort
channel). This section does the one job that belongs to a per-release document: **establish exactly what
`.201` claimed, what survives of it in `2.1.220`, and how a reader can tell the two apart.**

### c.1 The role-level exclusion is gone — three independent proofs

`effort`, `max_effort`, `xhigh_effort`, `adaptive_thinking`, `context_management`.

question they answer is *"has this text already been wrapped upstream?"*, and for Sonnet 5 the answer is
yes.

### c.3 The three framing states, enumerated from the catalogue

Exactly four catalogue entries declare `mid_conv_system`, and every line was read:

| model | capability line | `Ser` | framing sentence (`Jep`) | per-reminder wrapping (`mro`) |
|---|---|---|---|---|
| `claude-sonnet-5` | `:14207` | true | **no** — `lO_` suppressed by `mro` | **yes** |
| `claude-opus-4-8` | `:14355` | true | **no** — suppressed by `$Fc` | no |
| `claude-opus-5` | `:14390` | true | **yes** (`lO_`) | no |
| `claude-fable-5` | `:14428` | true | **yes** (`lO_`) | no |
| `claude-mythos-5` | *(none — `capabilities: []` at `:14439`)* | true, by the `\|\| r === "claude-mythos-5"` clause at `:150524` | **yes** | no |

Everything else — the ten denied ids at `:150512-150521`, plus anything the optimistic default at
`:150525` happens to admit — never mints an `api_system` message at all, because `T` is only appended to
inside `if (o)` branches and `H()` (`:531516-531529`) is a no-op when it is empty.

**So the three states are:** Sonnet 5 (channel on, old framing sentence, old per-reminder tags) · Opus
4.8 (channel on, old framing sentence, new aggregate shape) · Opus 5 / Fable 5 / Mythos 5 (channel on,
new framing sentence, new aggregate shape). A fourth, baseline state — channel off entirely — covers
every other model.

**Why is Opus 4.8 in the middle?** Because the two carve-outs answer different questions. `$Fc` only
touches `Jep`, i.e. *what the system prompt tells the model about where reminders come from*. `mro`
touches `Jep` **and** `NN`, i.e. the prompt sentence *and* the payload shape. Opus 4.8 was on the channel
in 2.1.193 already (it is one of the three ids in `:135302 (193)`), so it has been receiving un-wrapped
reminders in system turns the whole time and does not need the tag shim — it only needs to be spared a
new sentence describing a mechanism it has always used. Sonnet 5 needs both.

**Why not simply revert `.201` cleanly?** Two forces pull opposite ways, and the code resolves them by
choosing *where* to branch:

- The **transport** wants to be uniform. One code path, one beta header, one cache-breakpoint rule, one
  placement validator. Every special case in the transport multiplies against the API's placement
  constraints (must follow a user message; must be last or followed by an assistant turn) and against
  the four-rung fallback ladder that handles gateway rejections.
- The **model** is a fixed artefact. Sonnet 5 was trained and evaluated against
  `<system-reminder>`-tagged reminders. Feeding it bare text inside a `role: "system"` turn is an
  unvalidated prompt change on the model that is, as of `.197`, everyone's default.

Branching `Ser` — `.201`'s approach — satisfies the model and breaks the transport, and by `.211`/`.212`
it would additionally have cost the default model the prompt-cache promotion and the per-turn effort
channel, since both are gated on `o = Ser(r)` at `:531421`. Branching at serialization satisfies both,
at the cost of one boolean threaded through four call sites. **That is the whole engineering content of
this release's afterlife.**

**Key insight:** the bullet's *claim* is false for `2.1.220` and the bullet's *intent* is still
satisfied. Those are different facts about different layers, and the only way to hold both is to name
the layer every time you make a statement about this bullet.

## d) What the changelog does not say

**1. The single most important thing: this bullet cannot be verified by counting.** `mid_conv_system` is
**220=6 / 193=1**, which reads as a 6× delta. Four of the six 220 hits (`:14207`, `:14355`, `:14390`,
`:14428`) are **catalogue data rows**, not logic; the fifth is the one resolver test at `:150524`; the
sixth is a telemetry payload at `:509912`. Meanwhile the beta header
`mid-conversation-system-2026-04-07` is **1/1** and the fallback event
`tengu_mid_conv_system_fallback_retry` is **1/1** — both pure carryover. Every count in this bullet's
neighbourhood points the wrong way.

**2. `.201`'s durable artefact is not the exclusion — it is the shape of the test.** The lasting change
between the two builds at step 5 is `hardcoded three-id allow-list` → `catalogue capability lookup`.
That is a subordinate clause of the undocumented model-registry rewrite recorded in
[`../_GROUND_TRUTH_verified_anchors.md`](../_GROUND_TRUTH_verified_anchors.md) §1: per-model data moved
out of imperative branch-on-id code into a declarative catalogue at `:14028-14496`. Whether Sonnet 5 is
on or off the channel became a **data** question. That refactor is why the reversion could happen
without touching `Ser` at all — someone added one string to one array at `:14207`.

**3. A correction to the scoping pass.** [`../00_overview/_scope_v200_205.md`](../00_overview/_scope_v200_205.md)
states that "`claude-fable-5` was the pre-launch id for Sonnet 5", which would make 193's
`:135302 (193)` allow-list already cover Sonnet 5 under its codename. **The 2.1.220 bundle contradicts
that**: `claude-fable-5` and `claude-sonnet-5` are two separate catalogue entries with different
`display_name`s (`"Fable 5"` `:14404` vs `"Sonnet 5"` `:14179`), different pricing tiers
(`tier_10_50` vs `tier_3_15` `:14201`) and different `advisor_rank`s, and `claude-fable-5` is still
**220=27** hits. Per `_CONVENTIONS.md`, scope-file anchors are leads, not conclusions; this one is
**unconfirmed and probably wrong**, and nothing in §c depends on it.

**4. `.201` was never a hard block.** `CLAUDE_CODE_FORCE_MID_CONVERSATION_SYSTEM` (**220=2 / 193=1**)
short-circuits the entire resolver at `:150507`, *before* the deny list and before the catalogue lookup.
So even during `.201`'s window an operator could put Sonnet 5 back on the channel with an env var. There
is also a per-model escape hatch one line lower — `Ede(e, "mid_conversation_system")` at `:150508`,
returning an explicit `true`/`false` from a custom-model option — which beats both the deny list and the
catalogue.

**5. The carve-out covers the 1M-context variant, and one of the two predicates is belt-and-braces.**
`mro` tests `lo(e) === "claude-sonnet-5"`, and `lo`'s normalizer `YO` (`:111109-111140`) matches by
substring at `:111128` (`if (e.includes("claude-sonnet-5")) return "claude-sonnet-5";`), so
`claude-sonnet-5[1m]` and the provider-prefixed forms (`us.anthropic.claude-sonnet-5`, `:14183`) all
collapse to the canonical id and are carved out too. `$Fc` then applies `Qs`'s `[1m]` strip *again* on an
already-normalized input at `:508117` (`$Fc(lo(e))`) — redundant here, and a sign that `$Fc` is also
called on raw ids elsewhere.

**6. The memo key is `() => "latch"`, which is a deliberate single-model assumption.** `Jep`
(`:508116-508119`) caches **one** value regardless of its argument, with an invalidator registered
through `nvi`. The framing sentence is baked into a system prompt that is itself cached per session, so a
mid-session model switch has to invalidate both together rather than returning a per-model answer. A
reader who expects `Jep` to behave like a pure function of `modelId` will misread it.

**7. What actually replaced the exclusion, and when, is not recoverable from this bundle.** The
`2.1.220` build proves the end state; it cannot date the change. No bullet between `.202` and `.220`
mentions the mid-conversation system role for Sonnet 5, so the reversion shipped **silently** somewhere
in that range. The two bullets that *do* touch this subsystem — `.211`'s prompt-caching regression fix
and `.212`'s "works behind LLM gateways" — are about the cache breakpoint on the trailing system block,
and are derived in
[40_system_prompt/mid_conversation_system_role.md](../40_system_prompt/mid_conversation_system_role.md)
§5 and §6. Their existence is the strongest available circumstantial evidence for *why* the reversion
happened: both features are gated on `Ser(model)`, and neither is worth having if the default model is
excluded from it.

**8. The system turn stopped being only about reminders, and no bullet says so.**
`perTurnEffort`/`per_turn_effort` is **220=12 / 193=0**, `output_config` on an `api_system` message
(`:511943`) has no 193 counterpart, and `per-turn-control-2026-07-01` (`lW`, `:109215`) is **220=1 /
193=0**. Three independent features now ride the channel `.201` tried to take Sonnet 5 off. That is the
context in which this one-line bullet has to be read, and it is entirely absent from the changelog.
