## a) Release narrative

**2.1.206 is the fix-up release for `.205`, and its centre of gravity is `/doctor`.** `.205` promoted
`/doctor` from a version check to a ten-check setup prompt; `.206` fills that prompt in (the
checked-in-`CLAUDE.md` trimming check, #2, and the Homebrew-cask channel rule, #22) and repairs the
seam the promotion opened (`/status` printing the same install warning twice, #20). Two adjacent
releases, one surface: read `.205 #21`, `.206 #2`, `.206 #20` and `.206 #22` as a single change and the
diagnostic story of this window is complete.

**Its second half is a *provenance* release, and this is the more interesting reading.** Four separate
bullets are about a value arriving from the wrong place, or not arriving at all:
`CLAUDE_CODE_EXTRA_BODY` set in your shell but lost by the background worker (#10), a per-server
`request_timeout_ms` present in the MCP config but never reaching the transport (#9), a `/model` row
printing the price of a *different* model (#13), and a server-supplied model row landing in the wrong
place because the row it was positioned against was dropped by an entitlement (#14). All four are
"the value existed but the wrong one was used", and all four are fixed the same way: **thread the
identity of the thing through the call instead of re-deriving it at the destination.** `Goe(modelId,…)`
takes the row's model, `$Qt` computes the anchor row's family, `X5n` folds `request_timeout_ms` into
the per-request options, and the job-spawn env block copies the dispatching shell's variable verbatim.

**Third: a hardening pair with an unusual property — one of them cannot be auto-approved.**
`EnterWorktree` now asks before entering a worktree outside `.claude/worktrees/` (#5), and its
`checkPermissions` returns `decisionReason.classifierApprovable: !1` — i.e. auto mode is *structurally
forbidden* from approving it. `/commit-push-pr` moves the opposite way (#3): it *widens* an auto-allow
from hard-coded `origin` to the repo's configured push remote. Together they show the `.206` posture
on permissions: widen where the user's own git config already expresses intent, narrow where the model
supplies the path.

Around that: the agent-view/daemon cleanup pair (#17 `claude rm` leaving a roster row, #27 `Ctrl+X`
permanently removing a completed session) which share one new protocol field; the background-agent
upgrade moving off the attach path (#6); Windows stdin contention in the agents view (#16); and three
UI bullets that turn out to be a single width/binding problem (#19 the `←` guard, #23 the
jump-to-bottom pill, #26 the status column — the last of which the code contradicts).

### C.1 `#12` — `--permission-prompt-tool` on a cold MCP server: a second, much longer wait phase

**This bullet has no owning module doc.** `39_mcp/README.md` routes it to `38_permissions`;
`38_permissions/README.md` routes it back to `39_mcp`. Here is the mechanism.

**What it does:** headless runs pre-wait for pending MCP clients before the first turn. If the server
hosting your `--permission-prompt-tool` had not finished connecting when that wait expired, the tool
was absent from the registry and the turn died. `.206` gives that one server its own qualification
rule *and* its own, much larger, timeout.

**How it works.**

The 2.1.193 twin `K9o` (`:708358-708390 (193)`) has **three** parameters, **one** predicate and **one**

1. **Qualification.** In 193 a *remote* permission-prompt server under `remote_baku`, or any server

*necessity* is the whole design: optional servers get a best-effort 2 s, the permission gate gets as
long as it takes. The instrumentation is built to prove exactly that split —
`waitedMs` (phase 1) and `permissionPromptWaitedMs` (phase 2, computed as
`Date.now() - y - g` at `:849291`, i.e. *excluding* phase 1 so the two never double-count) are
reported separately in `tengu_headless_mcp_prewait`, alongside
`permissionPromptServerPendingBefore` / `…After`. All three fields are **220=1 / 193=0**.

identity, and the name arrives from `d.permissionPromptToolServerName` at both call sites
(`:846265`, `:846633` — the literal is **220=3 / 193=0**). That is the whole delta in one word: 193
never told the pre-wait *which* server mattered.

### C.2 `#10` — `CLAUDE_CODE_EXTRA_BODY` and the four places an env var has to be handled

**What it does:** `CLAUDE_CODE_EXTRA_BODY` (a JSON object merged into every API request body) is read
from `process.env` at `:508863`. A background worker is spawned by a long-lived daemon, so it inherits
the *daemon's* environment, not the shell you typed `claude --bg` in. `.206` makes the variable follow
the dispatching session.

**How it works — four sites, and each one is a different requirement.** The literal is
**220=9 / 193=5**; the four new sites are the fix, and they are not four copies of one change:

| Site | Code | Requirement |
|---|---|---|
| `:682552` | `...(Z.CLAUDE_CODE_EXTRA_BODY && { CLAUDE_CODE_EXTRA_BODY: Z.CLAUDE_CODE_EXTRA_BODY })` inside the spawn descriptor's `env` block | **Forward** the dispatching process's value into the job |
| `:553984` | `if (s.toUpperCase() === "PATH" \|\| s === "CLAUDE_CODE_EXTRA_BODY") delete t.dispatch.env[s]` | **Scrub** a stale value out of an *adopted* dispatch record, so a reattach does not resurrect an old shell's override |
| `:554224` | a key skipped by `cappedDispatch()`'s `JSON.stringify` replacer, alongside `PATH` and `CLAUDE_CODE_HOST_CREDS_FILE` | **Never persist/telemeter** it — the capped dispatch snapshot is what gets written to the roster |
| `:554889` | a member of the sensitive-env list `m7s`, between `CLAUDE_CODE_HOST_CREDS_FILE` and `ANTHROPIC_CUSTOM_HEADERS` | **Classify** it as credential-adjacent for every other consumer of that list |

Note `:682553` is the line immediately after the forward: `...(Z.PATH && { PATH: Z.PATH })` — that is
`.203`'s "background agents inheriting a stale `PATH` from the daemon" fix. The two bullets are one
line apart in the source and one release apart in the changelog, which tells you the second was found
by re-reading the first.

**Why this approach:** the naive fix is "copy the whole `process.env` into the job". The code
deliberately does not: it starts from `I` (a curated provider-env object) and adds back exactly three
things — host creds when the provider is host-managed, `CLAUDE_CODE_EXTRA_BODY`, and `PATH`. An
allow-list, not a copy. The `cappedDispatch` exclusion at `:554224` is the corollary: a value worth
forwarding at spawn time is exactly a value **not** worth writing to disk, because the roster file is
long-lived and the shell that set it is not.

**Key insight:** the count alone (9/5) is a weak signal — `_GROUND_TRUTH` §3's method would ask which
of the nine are new. Two of the four (`:554224`, `:554889`) are *exclusions*, i.e. code whose entire
purpose is to make the variable **not** propagate. A bullet that says "the override now follows the
dispatching session" is describing one of four sites; the other three exist to bound how far it follows.


**Half 1 — "a price for a different model than the row named".** Every price lookup now starts from
the **model id passed in** (`YO(t)` / `YO(e)`), and the picker calls `Goe("claude-sonnet-5", !1)` per
row (`:120057`). In 2.1.193 the equivalent formatter `o7s(e)` (`:102591-102596 (193)`) existed but was
called from exactly **one** place (`:350733 (193)`, the *server-supplied* rows transform); the
first-party rows built their descriptions from static strings, so a promo or price attached to one row
could not be re-derived per row. The one-line proof: the 220 picker row builder returns
`...(n !== void 0 && { promoListPrice: n })` (`:120062`) — the promo price is now **row-scoped state**,
not a module constant.

**Half 2 — "stopped quoting first-party list prices on providers that don't bill them".** `_5r`'s
first statement is `if (!uGr()) return ""`, and `uGr()` → `Dc()` → `Hn() === "firstParty"`. On Bedrock,
Vertex, Foundry, Mantle, the gateway or Claude Platform on AWS, **every** row's suffix is the empty
string. The 193 formatter had no such gate — `o7s` looked the price up in `TRt` and returned it
regardless of provider.

**Why this approach:** the gate lives in the *suffix builder*, not at the call sites. That is the
cheap way to guarantee the invariant holds for surfaces added later (the `/model` picker, the model
descriptions, `/config`, the subagent picker — 17 `pricingSuffix` sites) without each one remembering
to ask "am I on Bedrock?".

**Key insight and a caveat:** the promo branch only fires for `claude-sonnet-5`, which ties this fix
directly to `.197`'s Sonnet 5 launch — the promo suffix was the *reason* per-row pricing became
observable, and therefore the reason its absence became a bug. But note what the gate does **not**
cover: per `_GROUND_TRUTH` §6.5 the catalogue has no fast-mode tier, so a fast-mode turn is still
priced at the standard tier. `.206` fixed *which model's* price is shown, not *which mode's*.

### C.4 `#5` — `EnterWorktree` asks, and auto mode is structurally forbidden from answering

**What it does:** `EnterWorktree` relocates the session's working directory, write permission root, and
project configuration (`CLAUDE.md`, settings) to another directory. When the model supplies a path
outside `.claude/worktrees/`, that is a permission-root relocation chosen by the model — so `.206`
makes it a human decision.

**How it works** (`:406425-406446`), in the order the checks run — the ordering is the design:

1. `if (!e.path) return { behavior: "allow", … }` — no path means "the worktree this session already
   created", which is managed and uncontroversial.
2. `let t = await Scs(e.path); if (t?.managed) return { behavior: "allow", updatedInput: { ...e, path: t.targetReal } }`
   — a *managed* worktree (under `.claude/worktrees/`) is allowed silently, **and the input is rewritten
   to the resolved real path**, so the allow decision and the executed path cannot diverge.
3. Otherwise build a display path with two independent safety transforms:
   - `n = (l) => GTd(l).replace(czy, "�")` (`:406430`) — Unicode-confusable scrub, replacing
     dangerous code points with U+FFFD;
   - `a = i !== null && i.normalize("NFC") !== o.normalize("NFC") ? ` (resolves to "${i}")` : ""`
     (`:406434`) — if the NFC-normalised realpath differs from the displayed path, **show both**;
   - `s = … ? " (path sanitized for display)" : ""` (`:406433`) — and say so when the display was altered.
4. Return `behavior: "ask"` with the prompt at `:406437`, which spells out all three consequences
   ("moves the session's working directory **and write access** there, and loads project configuration
   (CLAUDE.md, settings) from that location"), and
   `decisionReason: { type: "safetyCheck", reason: "…a model-supplied worktree outside .claude/worktrees/", classifierApprovable: !1 }`.

**Why this approach:** `classifierApprovable: !1` is the load-bearing field. Everything else in the
block is presentation; this one flag removes the decision from auto mode's reach entirely, so no
classifier rule — however permissive the user's `autoMode` config — can approve it. Compare with the
`.205 #16` deletion rule, which auto mode *can* clear once the target is named: there, the risk is a
value the classifier cannot see; here, the risk is that **the classifier's own trust root moves**,
because the new directory supplies the `CLAUDE.md` and settings the classifier will read afterwards.
A classifier cannot safely adjudicate a change to its own inputs, so it is not asked.

**Key insight:** the confusable scrub and the `resolves to "…"` suffix exist because the *prompt text*
is the security boundary. If the model can supply a path that renders as `/home/user/project` but
resolves elsewhere, an "ask" prompt is worse than no prompt — it manufactures informed consent. Three
new literals in one 20-line block (`a model-supplied worktree outside` **1/0**, `(path sanitized for
display)` **1/0**, `resolves to "` ) all serve that one requirement.

## d) What the changelog does not say

**1. `#12` is the release's best security-adjacent fix and no module doc owns it.** Both
[`../39_mcp/README.md`](../39_mcp/README.md) and [`../38_permissions/README.md`](../38_permissions/README.md)
mark it `OTHER-MODULE` and point at each other. §C.1 above closes it: `permissionPromptToolServerName`
is **220=3 / 193=0**, the second wait phase is `:849288-849292`, and the ceiling is
`MCP_TIMEOUT ?? 30000` (`:285811-285814`). Worth noting *why* this is more than a UX bug: a headless
run whose permission-prompt tool is missing does not fail closed to "ask" — it fails to a crash, and
the operator's next move is usually to remove `--permission-prompt-tool`.

**2. `#26` is contradicted by the code, and the number in the bullet does not exist.** *"status column
now uses full terminal width instead of truncating at 64 characters"* — there is no `64` in the agent
view's width arithmetic in **either** build. The status column is computed as *leftover* width
(`a = Math.max(8, n - (i + 2) - 2 - (s + 2) - (o + 2) - 2)`, `:802792`) after the age, label and
artifact columns are measured, and the detail *text* is separately clamped to
`Math.max(24, Math.min(72, Math.floor(cols * 0.55)))` (`:807250`) — i.e. between 24 and 72 characters,
proportional to terminal width, with `1/0` (unbounded) under screen-reader mode (`kL()`).
See [`../36_background_agents/agent_view_and_status.md`](../36_background_agents/agent_view_and_status.md) §5.

**3. `#8` was routed and then dropped.** [`../43_slash_commands/README.md`](../43_slash_commands/README.md)
lists *"`claude --resume`/`--continue` not responding to keyboard on startup"* as owned by
`48_accessibility_ui`, but no `48_accessibility_ui` doc analyses it. The scoping candidate
`tengu_fleetview_stdin_contention` (`:804439`) is the **agents-view** listener-count probe — a 1500 ms
debounced `_.listenerCount("readable") > 1` check — and belongs to `#16`, not `#8`. Using it for `#8`
would be a false anchor.

**4. `#11`'s 2:1 count is a dual-runtime artefact, not a delta — and the general rule is stronger than
the ledger says.** `tengu_mcp_oauth_refresh_failure` is 220=2 / 193=1, which reads as a change. Per
`_GROUND_TRUTH` §6.7 (superseded/corrected) the 2.1.220 bundle ships **two complete MCP runtime trees**
(`v1` default, `v2` opt-in via `MCP_SDK_GENERATION`), so every MCP-client literal can double. The
practical consequence for anyone re-verifying this release: for `#9` and `#11`, read **both** 220 sites
before concluding anything, and remember the *default* path is the higher line range.

**5. `#7` and `#24` are both "the fix is a constant" bullets with fully carryover surfaces.**
`There's an issue with the selected model` is **1/1** at `:228674` and already carries its
`Run ${i} to pick a different model.` suffix in 193 — the `.206` change is upstream *routing* (an
expired login must not be reported as a model problem), not a new message. `awsCredentialExport` is
**12/12**. Neither can be evidenced by a string grep; both would be false deltas if written up as new.

**6. Two bullets in this release are one change.** `#17` (`claude rm` leaving a roster row) and `#27`
(`Ctrl+X` permanently removing a session) both call `deleteJob` (`Z3e`, `:681118`), which passes the
new IPC field `evict: !0` at `:681125`; the daemon's `case "kill":` arm at `:679374-679377` does
`f.delete(A.short)` **and** `delete T.workers[A.short]`. Before that second delete, the kill removed the
live worker but left the roster entry — which is literally "the row reappears in `claude agents`". The
zod declaration `evict: v.boolean().optional()` (`:330157`) is **220=1 / 193=0**.

**7. An undocumented adjacency worth recording.** `#6`'s background upgrade path scrubs the child's
environment before respawning: `for (let E of R9r) delete _[E]`, `delete _.CLAUDE_JOB_DIR`, and
`for (let E of Object.keys(_)) if (E.startsWith("CLAUDE_BG_")) delete _[E]` (`:501967-501970`), *then*
emits `tengu_update_bg_respawn` (`:501971`). No bullet mentions that an upgrade respawn drops all
`CLAUDE_BG_*` state, but it is the reason the upgraded worker re-derives its isolation, permission-rule
and memory-toggle flags from the roster instead of inheriting stale ones — and it is the same env-hygiene
instinct as `#10`.
