## a) Release narrative

**2.1.196 has one feature and twenty-six repairs.** The feature is *organization default models*, and
it is architecturally larger than its one-line bullet: it inserts a **fourth precedence level** above
the three that already governed model resolution (enforced allow-list → entitlement step-down → plan
tier), and it short-circuits all of them. Everything else in the release is a fix or a tuning change,
spread across background agents (7 bullets), accessibility/voice (3), MCP (1), plugins (2), code
review (2), Remote Control (2), permissions, telemetry, performance, compaction, tools and workflow.

The interesting property of the release is **how many of its bullets are behaviour changes disguised
as fixes.** Three of them are policy flips whose implementation is a *deletion*:

- **Bullet 25** — the streaming idle watchdog "is now on by default". In code this is a **gate
  removal**: `CLAUDE_ENABLE_STREAM_WATCHDOG` falls **220=2 / 193=4** and the GrowthBook gate
  `tengu_event_watchdog_default_on` falls **220=0 / 193=1**. A default-on flip *removes* the opt-in
  branch and, here, also removes two hand-placed forced-on env injections. Framing this as an
  addition would be exactly backwards (§c.1).
- **Bullet 26** — Remote Control "is now disabled when `ANTHROPIC_BASE_URL` points at a non-Anthropic
  host". The 2.1.193 code returned one fixed sentence; 2.1.220 has a per-provider reason builder and
  a new eligibility predicate. The bullet reads like a restriction; the code is mostly a diagnostics
  upgrade.
- **Bullet 27** — the agents view needs a single `←` instead of two. The gate
  `tengu_left_arrow_gesture` (193=2) is **gone**; `tengu_left_arrow_editing_guard` (`:559928`, 220=1 /
  193=0) replaces it. Same pattern: the change is visible as a *disappearance*.

Its second property is **anchor scarcity in the bug half**. Nine of the twenty-seven bullets have no
distinguishing literal in this bundle, and three more are traps where the headline literal is
byte-identical between builds (`Pending approval` 3/3; `plugin validate` 7/7; the two-word session
name generator 4/4). Two scoping-pass leads collapse under reading: the `--bg with bypassPermissions`
disclaimer string is **1/1 carryover** (193 at `:577592`), and `tengu_resume_unchained_transcript`
(`:525013`) turns out to be a *parent-UUID chain* diagnostic, not the `/cd` resume-list fix (§c.4).
Both are corrections this file contributes back.

Read against `.195`, the through-line is clear: `.195` opened the background-agent hardening campaign
and `.196` widens it to the *fleet's* edges — the daemon restarting under a live worker (bullet 22),
Windows shells surviving a process handoff (bullet 21), a transcript probe that used to delete the
conversation it misread (bullet 5). Read against `.197`, which is a single-bullet Sonnet 5 launch,
`.196` looks like the last broad clean-up before a model release: you ship the reliability batch, then
you ship the model.

### c.1 Bullet 25 — a default-on flip is a DELETION, and three counts prove it

**What it does:** the event-level streaming idle watchdog (abort + retry when a response stream
produces no events for five minutes) stops being a gated opt-in and becomes the unconditional
default, with `CLAUDE_ENABLE_STREAM_WATCHDOG=0` as the only escape.

**How it works:**

```javascript
// ============================================
// streamIdleWatchdogEnabled - the .196 default-on flip, in both builds
// Location: cli_inner_pretty.js:510479  (baseline: :595164 (193))
// ============================================

// ORIGINAL (for source lookup):
//   2.1.193:
Ln = Be.CLAUDE_ENABLE_STREAM_WATCHDOG ?? it("tengu_event_watchdog_default_on", !1),
//   2.1.220:
St = Z.CLAUDE_ENABLE_STREAM_WATCHDOG ?? !0,
Jt = a7i(),
bn = Jt / 2,
Kn = Math.min(l7i(Hn()), St ? Jt : 1 / 0),

// READABLE (for understanding):
//   2.1.193: env override, else ask GrowthBook, else OFF
const watchdogEnabled = env.CLAUDE_ENABLE_STREAM_WATCHDOG ?? featureGate("tengu_event_watchdog_default_on", false);
//   2.1.220: env override, else ON
const watchdogEnabled = env.CLAUDE_ENABLE_STREAM_WATCHDOG ?? true;
const idleBudgetMs   = streamIdleTimeoutMs();
const halfBudgetMs   = idleBudgetMs / 2;
const effectiveIdle  = Math.min(providerIdleCap(currentProvider()), watchdogEnabled ? idleBudgetMs : Infinity);

// Mapping: Ln/St→watchdogEnabled, Be/Z→env, it/featureGate→getFeatureValue,
//          a7i→streamIdleTimeoutMs, l7i→providerIdleCap, Kn→effectiveIdle
```

1. The gate read is **deleted**, not inverted. `tengu_event_watchdog_default_on` is 220=0 / 193=1 —
   the flag no longer exists in the client, so it can never be turned back off remotely.
2. Two *forced-on* env injections are also deleted. In 2.1.193, `CLAUDE_ENABLE_STREAM_WATCHDOG: "1"`
   was written into two child-process environments (`:606918 (193)`, `:715178 (193)`) so that
   background workers got the watchdog even while the gate was off for everyone else. Once the
   default is `true`, those overrides are dead code and go. **That is the whole of the 4 → 2 drop:**
   accessor + read-site survive; gate read and two injections vanish.
3. `Infinity` is the off-state. When disabled the effective idle budget becomes
   `Math.min(providerCap, Infinity)` — i.e. the provider cap alone. The watchdog is not a separate
   timer being started or stopped; it is a *clamp* on an existing budget.

**Why this approach:** flipping a default by deleting the gate rather than by changing its default
value is a one-way door, and that is the point. A remote gate that could still turn the watchdog off
would be a foot-gun for exactly the failure it protects against (a hung stream is unobservable to the
gate service). Keeping the env var means an operator with a genuinely long-idle proxy still has an
out, without a server round trip.

**Key insight — and the reason this bullet is a trap:** *a literal count going **down** is evidence of
a behaviour change, not evidence of no change.* `_GROUND_TRUTH` §3 and `_false_delta_ledger` both flag
this row; the correct verdict is **GATE_REMOVAL**, and the correct place to look for the delta is the
set of *deleted* sites in 2.1.193, not the surviving sites in 2.1.220.

There is an undocumented rider: `tengu_watchdog_skip_nonstreaming_fallback` (`:511183`, 220=1 /
193=0) defaults to `!0` and, when the watchdog aborted the stream, **suppresses the fall-back to the
non-streaming endpoint**. Without it, every watchdog abort would silently re-issue the request in
non-streaming mode — turning a five-minute stall into a five-minute stall plus a full blocking retry.
No bullet mentions it. Full treatment (including the *other* watchdog, the byte-level one, which is
carryover and which the bullet's wording conflates with this one) in
[`../57_api_reliability/streaming_and_watchdog.md`](../57_api_reliability/streaming_and_watchdog.md).

### c.2 Bullet 1 — a fourth precedence level, and a label that does not exist

**What it does:** it lets an organization set a default model that applies when the user has not
picked one, and it labels that state in `/model`.

**How it works:**

```javascript
// ============================================
// resolveModelWithAttribution - the four-level model attribution ladder
// Location: cli_inner_pretty.js:110736-110751
// ============================================

// ORIGINAL (for source lookup):
function iQt() {
  let e = wSi(), t;
  if (e === void 0) { if (((t = U6e()), t !== null)) l0t(t); }
  else if (e === null) t = null;
  else t = lRc(e);
  if (t !== null) return { setting: t, attribution: "org" };
  let { setting: r, envFamily: n, concreteBaseline: o } = cRc(),
    i = E7n(r, n, o), s = i ?? r, a = S7n(s);
  if (i !== null) return { setting: a ?? i, attribution: "enforced" };
  if (a !== null) return { setting: a, attribution: "entitlement" };
  return { setting: s, attribution: "tier" };
}

// READABLE (for understanding):
function resolveModelWithAttribution() {
  let cached = readOrgModelDefaultCache(), orgDefault;
  if (cached === undefined) {                       // cache cold: fetch and memoise
    orgDefault = fetchOrgModelDefault();
    if (orgDefault !== null) writeOrgModelDefaultCache(orgDefault);
  } else if (cached === null) orgDefault = null;    // cached "org has none"
  else orgDefault = validateOrgModelDefault(cached);

  if (orgDefault !== null) return { setting: orgDefault, attribution: "org" };   // LEVEL 1 (new in .196)

  const { setting, envFamily, concreteBaseline } = resolveUserModelSetting();
  const enforced   = applyEnforcedAllowList(setting, envFamily, concreteBaseline);
  const effective  = enforced ?? setting;
  const steppedDown = applyEntitlementStepDown(effective);

  if (enforced    !== null) return { setting: steppedDown ?? enforced, attribution: "enforced" };    // LEVEL 2
  if (steppedDown !== null) return { setting: steppedDown,             attribution: "entitlement" }; // LEVEL 3
  return { setting: effective, attribution: "tier" };                                                // LEVEL 4
}

// Mapping: iQt→resolveModelWithAttribution, wSi→readOrgModelDefaultCache,
//          U6e→fetchOrgModelDefault, l0t→writeOrgModelDefaultCache,
//          lRc→validateOrgModelDefault, cRc→resolveUserModelSetting,
//          E7n→applyEnforcedAllowList, S7n→applyEntitlementStepDown
```

1. **Level 1 short-circuits everything.** If an org default resolves, the function returns immediately
   — the enforced allow-list, the entitlement step-down and the plan tier are never consulted.
2. The tri-state cache (`undefined` = cold, `null` = "org has no default", value = a default) means a
   negative answer is memoised too, so a user in an org without a default does not re-fetch each turn.
3. `Z$()` (`:110733`) is the thin accessor everyone else calls; it throws away `attribution` and
   returns only `setting`. The attribution string exists solely to drive rendering.
4. The label is built by two tiny functions at `:119999-120005`: `" · Set by your organization"` when
   a *restriction* is active, else `" · Org default"` when `attribution === "org"`, else nothing. The
   picker row at `:111167` inlines the same ternary.

**Why this approach:** ordering org-default *above* the enforced allow-list looks wrong at first — an
allow-list is a restriction and a default is a preference, so you would expect the restriction to
win. It does not, because the two are set by the same principal (the org console) and the org default
is already required to be inside the allow-list. Checking the allow-list again would be redundant work
on the hot path of every `/model` render. The trade-off is that a *stale cached* org default could in
principle survive an allow-list tightening until the cache refreshes — which is why the cached value
goes through `validateOrgModelDefault` rather than being trusted verbatim.

**Key insight — the bullet is half unimplemented.** `Org default` is 220=2 / 193=0, but
**`Role default` is 220=0 / 193=0**: the string does not exist in either bundle. The changelog's
"(or 'Role default')" describes a server-side or console-side concept with no client rendering path.
Do not look for it. Cache validation, the server-data trio, and the `.206` follow-up fixes are in
[`../47_models/org_default_models_and_picker.md`](../47_models/org_default_models_and_picker.md).

### c.3 Bullet 7 — the duplicate-recap fix, and why nothing anchors it

**No module doc owns this bullet.** `42_workflow`'s ledger routes it to `04_tools` / `51_headless_sdk`,
and neither picks it up. This section is the record of what I checked and eliminated.

The bullet: *"Fixed duplicate recap lines after a background session's turn: a schema-rejected
`StructuredOutput` attempt no longer renders alongside its retry."*

**Candidate 1 — the away-summary recap suppressor. ELIMINATED (carryover).** The recap generator has
a guard chain of seven `[awaySummary] skipped: …` early-returns, and one of them is precisely on
topic:

```javascript
if (ngm(l.current)) return;
if (ogm(l.current)) {
  w("[awaySummary] skipped: StructuredOutput recap present");   // :816372
  return;
}
```

`StructuredOutput recap present` is **220=1 / 193=1**, and the whole guard family is
`[awaySummary] skipped` **220=7 / 193=7**. No guard was added in this window. The suppressor that
would produce exactly this bullet's behaviour **already shipped before 2.1.193**.

**Candidate 2 — the strict-schema compiler. ELIMINATED as an attribution (but genuinely new code).**
The scoping pass and `42_workflow` both point at `fty` (`:231103-231136`) and its telemetry
`tengu_structured_output_strict_schema` (`:231113`). That machinery *is* net-new in this window —
`strictInputJSONSchema` is **220=3 / 193=0**, and the tool-payload site at `:508172-508180` sets
`strict: true` on the wire when the schema converts, logging *"Tool `<name>` has strict: true but its
schema is not strict-compatible (…); sending non-strict"* when it does not. But that is a **schema
strictness feature**, not a *transcript de-duplication* fix: it changes what is sent to the API, not
what is rendered after a rejection. Attributing it to bullet 7 would be the false-delta pattern
`_CONVENTIONS.md` §4.7 warns about — a real net-new mechanism bolted onto the nearest plausible
bullet.

**Candidate 3 — a rendering-side dedup.** `StructuredOutput` is **220=33 / 193=33**;
`requiresStructuredOutput` is **8/8**; `MAX_STRUCTURED_OUTPUT_RETRIES` is 4/3 (the extra site is the
settings-env allow-list at `:58170`, not a retry-count change). No new literal exists on the render
path.

## d) What the changelog does not say

1. **`Role default` is fiction, client-side.** 220=0 / 193=0. Bullet 1 promises a second label that
   has no rendering path in this bundle. Only `" · Org default"` (`:120004`) and the pre-existing
   `" · Set by your organization"` (`:120000`) exist.

2. **Bullet 25's count fell for two reasons, not one.** Besides the deleted gate, 2.1.193 hand-injected
   `CLAUDE_ENABLE_STREAM_WATCHDOG: "1"` into two child-process environments (`:606918 (193)`,
   `:715178 (193)`) — a staged rollout that force-enabled the watchdog for background workers ahead of
   everyone else. Both injections are gone. So the release simultaneously *generalised* the feature
   and *deleted its staging scaffolding*, and the changelog mentions neither.

3. **An undocumented sibling gate rides along with bullet 25.**
   `tengu_watchdog_skip_nonstreaming_fallback` (`:511183`, 220=1 / 193=0, default `true`): when the
   watchdog fires, do **not** fall back to the non-streaming endpoint. Turning the watchdog on by
   default without this would have doubled the worst-case latency of every stalled stream.

4. **Bullet 11 ships a user-tunable env var that no bullet names.**
   `CLAUDE_CODE_RESUME_INTERRUPTED_TURN_MAX_AGE_MS` is 220=6 / 193=0. `znd` (`:320146-320158`) treats
   it as an **opt-in with a sanity floor**: absent or `0` disables interrupted-turn resume entirely,
   a non-finite or non-positive value falls back to `3600000` (one hour), and the age is measured from
   the last non-`system`/non-`progress` record's timestamp. An empty transcript returns `true` (resume
   it). Two of its six sites are worker plumbing rather than policy: `:554381` injects a default into
   the child environment on a respawn retry (`??= String(fq_)`), and `:869245` lists the variable
   among the env names forwarded across the process boundary — so background workers inherit the
   behaviour without the operator setting anything.

5. **Bullet 22 has a user-visible sentence the bullet does not quote.** `:682963-682966` distinguishes
   *"Session `<id>` was interrupted while unattended — resuming it…"* from the ordinary
   *"Waking session `<id>`…"*, keyed on `reapedMidWorkAt` (220=6 / 193=0). The state that makes the
   distinction possible — recording *when* a worker was reaped mid-work — is the actual change; the
   auto-resume is the consequence.

6. **Bullet 23's "~25% fewer tokens" is not a budget cut.** The merged cleanup finder is capped at
   `${aRd.length} * P.perAngle` (`:424281`) — *cleanup-angle count × per-angle budget*, i.e. exactly
   the total the five separate finders had — and `LEVEL_PARAMS` (`:424063-424067`) is identical to its
   193 twin. The code even says so in a comment at `:424057-424059`. The saving comes from **fan-out
   shape** (one agent invocation instead of five, so one prompt prefix instead of five), not from
   asking for less work. Worth knowing before anyone tries to reproduce the 25% from budget numbers.

7. **Bullet 19's "Needs attention" label is carryover, and its one site is the wrong screen.**
   `Needs attention` is 220=1 / 193=1 and its single occurrence is a skills/favourites picker section
   header — not the agents list. `_false_delta_ledger` register 1 lists this; the anchorable half of
   the bullet is the PR-status hint (`gh auth login for PR status`, `:316038`, 220=1 / 193=0) and the
   PR-URL regex at `:316033`.

8. **Bullet 10's disclaimer sentence is byte-identical to 2.1.193.** The scoping pass graded it
   NET_NEW on `:683507`; the same sentence is at `:577592 (193)`, and the surrounding `--bg`
   combination validator has the same three arms in both builds. The bullet describes a real
   behaviour change (falling back to auto mode instead of showing the disclaimer) whose fix is in the
   *caller* that decides whether to run the validator — not isolable here.

9. **Nothing in `.196` mentions the MCP runtime duplication.** `_GROUND_TRUTH` §6.7 (as corrected)
   establishes that 2.1.220 ships **two complete MCP runtime trees** selected by `MCP_SDK_GENERATION`.
   Bullet 4 and bullet 15 both touch MCP, and neither hints at it. When reading MCP literals for this
   release, remember the *default* path is the higher line range — see
   [`../39_mcp/dual_mcp_runtime_trees.md`](../39_mcp/dual_mcp_runtime_trees.md).
