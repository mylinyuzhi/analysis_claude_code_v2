# 2.1.209 — the one-bullet revert

**Bullets: 1.** **Centre of gravity: undoing `.208`.**

```
- Fixed /model and other dialogs being blocked in `claude agents` background sessions (reverts an overly broad guard)
```

---

## 1. Release narrative

`2.1.209` is one of five single-item releases in this window (`.201 .204 .209 .215 .220`), and it is the
only one that is explicitly a **revert**. The others are a model launch (`.197`), a hotfix that changes
behaviour forward (`.201`, `.204`), a scope restriction (`.215`) and a catch-all (`.220`). A one-bullet
revert release means exactly one thing: **the release immediately before it shipped a regression severe
enough that shipping a whole new build to take one change back was cheaper than waiting for the next
scheduled release.** `2.1.208` was the largest engineering release in the window (46 bullets), so the
odds of exactly this happening were high.

The regression it takes back belongs to `.208` bullet #43 — *"Fixed `/install-github-app` and the `/mcp`
settings menu no longer open in bg sessions."* That change introduced a new predicate for "this is a
detached background session, so no dialog can be shown", and it was applied more widely than the two
commands the bullet names. `/model` — which in the agent view is not a dialog at all but an inline
`/model <name>` text command — got caught by it, and so did other dialog-opening surfaces. `.209` narrows
the application back down.

**The methodological point of this file.** A completed revert is *invisible in a `2.1.193 → 2.1.220`
diff by construction.* If `.208` added code at line X and `.209` removed it, the 2.1.220 bundle looks
exactly like 2.1.193 at line X, and every count-based technique reports "no change". This is the
mirror image of `_GROUND_TRUTH` §6.3's finding for `.201` (where the hotfix was reverted *after* the
release that introduced it, so the changelog is what looks wrong). Here the changelog is right and the
diff is silent. The only way to say anything is to (a) prove the restored site is byte-equivalent to the
baseline and (b) characterise the *surviving* half of `.208`'s change — which is what §3 and §4 do.

There is no `2.1.208` bundle available in this tree (`/lyz/codespace/claude-code-bomb/versions/` holds
`2.1.132 2.1.142 2.1.156 2.1.183 2.1.193 2.1.220` only), so the intermediate state cannot be read
directly. Every claim below is therefore framed as *"what 2.1.220 shows"*, never as *"what `.208`
did"*.

## 3. Deep dive A — proving the revert landed, from the restored code

**What it does:** The agent-view composer decides, for every `/`-prefixed line the user types inside
`claude agents`, whether the command can run there at all. `.208` widened the "cannot run here" branch;
`.209` narrowed it back.

**How it works:**

1. The composer intercepts `return` and splits the input into `name` + `args` (`:806716-806719`).
2. `Cv(name, aqs())` resolves the command descriptor; `yk(...)` asks whether it is enabled and
   `k_r(...)` whether the current *surface* (claude-ai / console / …) is in its `availability` list.
3. A command with a `fleetHostCall` implementation runs directly in the fleet host (`:806722-806736`) —
   these are the commands written to work *without* a session.
4. Everything else hits the guard head at `:806739`:
   `if (Tl.type !== "prompt" && Tl.name !== "model")`. **`model` is exempted here, before the guard body
   is even entered.**
5. Inside, the block only fires when the command is *not* in the fleet-view allow-list
   (`f5e.some((ic) => ic.kind !== "command" && …)`) **and** the currently-open overlay, if any, is not
   this command's own overlay (`!Xa || Xa.name === Tl.name`).
6. When it does fire, 2.1.220 emits telemetry and prints
   `/${name} isn't available in agent view — attach to a session to run it`.
7. Because step 4 skipped `model` entirely, control falls through to `:806788`, an inline `/model <name>`
   handler that resolves an exact/prefix match against the session model list and sets the model
   session-scoped.


The two predicates that gate the whole block are byte-identical carryover as well:
`yk` (`:326536`) ≡ `Zx` (`:396945 (193)`) — `return e.isEnabled?.() ?? !0;` — and `k_r` (`:506679`) ≡
`sEt` (`:580928 (193)`), the `availability` switch over `claude-ai` / `console`. The refusal string
itself is **220=1 (`:806782`) / 193=1 (`:677512`)**.

**Why this is proof and not a coincidence.** Three independent structural features survive the round trip
with identical semantics and identical *ordering*: the `name !== "model"` exemption, the two-clause
allow-list test, and the fall-through to an inline `/model <name>` handler immediately below the block
(`:806788` ≡ `:677518 (193)`). A guard that had merely been *tightened* would not restore all three; a
guard that was reverted to its pre-`.208` form restores exactly all three. The only textual difference in
the whole block is the telemetry emission, which is additive.

**Why this approach (a revert rather than a fix-forward).** The regression was in the *predicate's blast
radius*, not in its logic. Fix-forward would have meant enumerating every dialog surface and deciding
which ones legitimately need a terminal — that is `.208` #43's own job, and it is what §4 shows the code
now does. Reverting the composer-level application and keeping the per-command applications is the
minimal change that restores `/model` without giving up the `/install-github-app` and `/mcp` fixes.

**Key insight:** *the revert is provable only from what stayed the same.* When your baseline predates the
regression, a correct revert is indistinguishable from "nothing happened" — so the finding has to be
stated as an equivalence, and the interesting material is the part of the release that **did not** get
reverted.

## 4. Deep dive B — what survived: `eN()` and its thirteen sites

**What it does:** `eN` answers *"is this process a background session with no terminal attached right
now?"*. It is the predicate `.208` introduced, and in 2.1.220 it is the only mechanism that blocks a
dialog for being in a background session.

```javascript
// ============================================
// isDetachedBackgroundSession - background session AND no attacher currently connected
// Location: cli_inner_pretty.js:112712-112714
// ============================================

// ORIGINAL (for source lookup):
function eN() {
  return rs() && !AS();
}

// READABLE (for understanding):
function isDetachedBackgroundSession() {
  return isBackgroundSession() && !hasAttachedTerminal();
}

// Mapping: eN→isDetachedBackgroundSession, rs→isBackgroundSession, AS→hasAttachedTerminal
```

`eN()` is **220=13 / 193=0**. Both conjuncts matter: a background session that *is* attached can show a
dialog perfectly well, so the guard is about the **absence of a viewer**, not about the session's kind.
That distinction is the whole reason `/model` should never have been caught: `/model <name>` in the agent
view renders no dialog at all, it just sets a string.

The thirteen call sites, all read in the 2.1.220 bundle:

| Line | Surface | What it does when detached |
|---|---|---|
| `:700562` | `u5t` park helper itself | bails out unless detached |
| `:700577` | `xvf` un-park watcher | re-checks on every attacher change |
| `:701071` | `/install-github-app`, repo step | `tengu_install_github_app_error` `reason: unattended_bg_session` |
| `:701342` | `/install-github-app`, api-key step | same gate, different step |
| `:701700` | `/install-github-app` entry | parks the session, prints one of two messages |
| `:703740` | a confirmation dialog's `return` handler | swaps the dialog for a static message |
| `:704196` | MCP auth option menu (`auth`/`reauth`/`clear-auth`/`claudeai-auth`/`claudeai-clear-auth`) | refuses only these five options |
| `:704308` | MCP OAuth confirm callback | same |
| `:705878` | `${server} requires authentication` reconnect path | parks with `authenticate <server> — open this session and run /mcp` |
| `:714204` | `/mcp` subcommand router | after `enable`/`disable`/`reconnect` are routed |
| `:714210` | `/mcp` panel open | parks |
| `:725193` | `skill-doctor` (`:735783`) | returns the text report instead of the UI |

**None of them is `/model`, and none of them is a generic composer-level gate.** Every one is attached to
a specific surface that genuinely cannot function without a terminal: an OAuth browser hand-off, a
multi-step wizard, a confirmation prompt, or a full-screen panel. `:704196` is the sharpest illustration —
it does not block the whole menu, it blocks exactly the five *authentication* options and lets the rest
through.

**Why the design converged here.** The alternative shape — one check at the composer, keyed on "does this
command open a dialog?" — requires a reliable `opensADialog` bit on every command descriptor, and no such
field exists. `/model` is precisely the case where the answer differs by *argument*: `/model` with no
argument opens a picker, `/model sonnet` does not. A per-surface guard placed at the point where the
dialog is actually constructed cannot get that wrong, because it runs after the branch. The cost is 13
call sites instead of 1, and the benefit is that each one can also do something better than refuse —
`/mcp` offers the text subcommands, `skill-doctor` returns the text report, `/install-github-app` parks
the session so the user is *routed back to it*.

**Key insight:** `.209` is not "the guard was wrong", it is "the guard was in the wrong *place*". Moving a
capability check from the dispatcher to the leaf lets each leaf degrade gracefully instead of failing.

## 5. What the changelog does not say

**5.1 — Correction to `_false_delta_ledger.md` register 2.** That register lists, under release `2.1.209`:

> `tengu_slash_command_unavailable + reason unavailable_in_agent_view (/model carve-out at :806788)` —
> `cli_inner_pretty.js:806776` — 220=2 / 193=0

The *anchor* is correct and re-verified: `tengu_slash_command_unavailable` is **220=2 (`:806776`,
`:593858`) / 193=0** and `unavailable_in_agent_view` is **220=1 / 193=0**. Two refinements are needed:

- **The `/model` carve-out is not new.** `:806788` is the inline `/model <name>` handler, and it has a
  byte-equivalent twin at `:677518 (193)`; the actual exemption is one line higher in logical order, at
  `:806739` (`Tl.name !== "model"`), whose twin is `:677505 (193)`. Neither is a `.209` addition.
  This matches [`command_and_flag_deltas.md`](../43_slash_commands/command_and_flag_deltas.md) §2.3,
  which reached the same conclusion independently.
- **The telemetry most plausibly belongs to `.208`, not `.209`.** The emission sits *inside* the refusal
  branch — i.e. it instruments the guard rather than the revert — and the sibling emission at `:593858`
  covers Remote Control with `reason: "unavailable_over_remote_control"` and `surface: "bridge"`, a
  surface `.209` says nothing about. Attributing the gate to `.209` reads the revert as an addition.
  The defensible statement is: **`.209` is the release in which this telemetry became observable in its
  final, narrowed form.**

**5.2 — the guard has a second clause nobody documents.** `(!Xa || Xa.name === Tl.name)` at `:806744`
means the refusal is *suppressed while some other overlay is open*. Typing `/mcp` while the model picker
is up does not print "isn't available in agent view"; it falls through to the generic dispatch path.
This is present in 193 too, so it is not a delta — but it is why the refusal can look intermittent, and
no bullet in the window mentions it.

**5.3 — `fleetHostCall` grew a `login` capability, undocumented here.** At `:806728` the host-call
context passed to fleet-native commands now includes
`login: () => e({ type: "login", collapsed: [...], groupMode: On, sessionModel: ib.current })`; 193's
context (`:677499`) had only `exit`, `relaunch`, `setError`, `setInfo`. That is the plumbing behind
`.198`'s *"`/login` from the agent view"*, and it is the *positive* half of the same design question
`.209` answers negatively: commands that must work without a session get a host-call implementation;
commands that must not are guarded at their leaf.

**5.4 — the surface enum is three-valued.** `surface: as.current === "remote" ? "fleet-cloud" :
"fleet-local"` (`:806779`) plus `surface: "bridge"` (`:593861`) means unavailability telemetry
distinguishes a local agent view, a cloud-hosted agent view, and Remote Control. A single-bullet release
is an odd place to find a three-surface taxonomy; it exists because `.208`/`.209` were fighting a bug
whose symptom differed per surface.

**5.5 — what cannot be established from this bundle.** Which *specific* call sites `.208` added and
`.209` removed is unknowable without a `2.1.208` build. The honest ceiling on this analysis is: the
composer-level application is gone (proved by equivalence with 193), and 13 leaf-level applications
remain (proved by direct reading). Anything more specific would be invention.
