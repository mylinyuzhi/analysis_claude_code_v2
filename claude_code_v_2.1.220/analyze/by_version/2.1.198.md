## 1. Release narrative

`.198` is the release where Claude Code stopped asking permission to be autonomous. Four of its first
eight bullets flip a default in the same direction:

- **subagents run in the background by default** (was a gradual rollout);
- **background agents ship their own work** — commit, push, open a draft PR — instead of stopping to
  ask;
- **the built-in Explore agent inherits the session model** instead of being pinned to haiku;
- **subagents and compaction inherit the session's extended-thinking configuration** instead of
  running with thinking disabled unless a remote allow-table said otherwise.

Read together, those are one decision made four times: *stop degrading delegated work, and stop
blocking on the user.* The supporting cast is what you need once agents run unattended — the
`Notification` hook gains `agent_needs_input` / `agent_completed` so a finished or blocked background
agent can page you (bullet 3); focus mode folds completed background notifications into a single
count (27); `--bg` with `--print` is rejected up front instead of producing an unattachable session
(20); and the `/agents` wizard is deleted outright (33) on the theory that you should ask Claude to
manage subagents rather than walk a form.

The second theme is **removing the last hand-holding surfaces around the browser and the sandbox**:
Claude in Chrome goes generally available (2), plan mode finally auto-allows read-only tool calls in
sessions that were *born* in plan mode rather than switched into it (25), and the sandbox network
classifier stops re-asking about a host it already judged (10).

Everything else is a long reliability tail — 17 of the 33 bullets are `Fixed …`, spread across
background agents, AWS/Mantle auth, workflow progress, terminal selection, and the API retry path.
That tail is where most of the false deltas live: `anthropicAws`, `awsAuthRefresh`, `Reconnecting…`
and the API-retry-UX bullet all name literals that already existed in 2.1.193, and one of them
(`anthropicAws`) has a 2.1.220 count that is *lower* than 2.1.193's.

**Position in the window.** `.198` immediately follows the single-bullet Sonnet 5 launch
([`2.1.197.md`](2.1.197.md)) and immediately precedes `.199`, which is almost entirely bugfixes on
the machinery `.198` just switched on — partial-result recovery when a background subagent is cut off
(`.199` #4/#5), a respawn that honours `claude stop` (#8), and the *second half* of the plan-mode
browser work (#21). Several `.198` bullets are only properly understandable next to their `.199`
twin, and the ledger says so where that is the case.

## 3. Deep-dive A — how "background by default" is actually implemented (bullet 1)

> `53_subagent_limits/README.md` records this bullet as NET_NEW and hands it to
> `36_background_agents`, which analyses the *notification* half. Neither analyses the flip itself.
> This section fills that gap.

**What it does:** makes `run_in_background` default to `true` for subagent spawns, and tells the
model — in prose, in the system prompt — that it must not invent a pending agent's results.

**How it works.** There is no boolean named "backgroundByDefault" to grep. The flip is expressed in
**two coordinated pieces of English**, one in the system prompt and one in the tool schema:

```javascript
// ============================================
// buildSubagentBackgroundClause - the three-way prompt fork that encodes the default
// Location: cli_inner_pretty.js:397980-397993
// ============================================

          : "\n- Subagents run in the background by default; you'll be notified when one completes. Pass `run_in_background: false` for a synchronous run when you need the result before continuing. Never fabricate or predict a pending agent's results — …"
        : "",
    A = oZ()

      : oy()

```

and the tool-schema description that the model sees on every call:

```javascript
// 220 :398204-398209
run_in_background: v.boolean().optional().describe(
  "Agents run in the background by default; you will be notified when one completes. " +
  "Set to false to run this agent synchronously when you need its result before continuing.")
// 193 :430376 (193) — "Set to true to run this agent in the background."
```

`Set to false to run this agent synchronously` is **220=1 / 193=0**, and the 193 description is the
exact logical inverse. That pair is the cleanest proof of the flip in the whole bundle.

**Why this approach.** Three decisions worth naming:

1. **The default is carried by the prompt, not by a schema default.** `run_in_background` is
   `.optional()` with no `.default(true)`. The *runtime* still has to decide what "absent" means, but
   the model is told the answer in two places, so an explicit `false` is a deliberate act rather than
   an accident of omission. Encoding a policy default in a zod `.default()` would have made it
   invisible to the model; encoding it in prose makes the model able to *reason* about when to opt
   out ("when you need the result before continuing").
2. **There are three states, not two.** `backgroundIsForced` (the `n` branch, `:397985`) drops the
   opt-out sentence entirely — some contexts have no synchronous path at all. Meanwhile `oZ()`
   (running *as* a subagent) removes `run_in_background` from the vocabulary completely. So the same
   tool presents three different contracts depending on who is calling it. A reader who greps only
   `:397986` will conclude the opt-out is always available; it is not.
3. **The anti-fabrication clause is attached to the default, not to the notification.** Both
   background branches end with *"Never fabricate or predict a pending agent's results — the
   notification is never something you write yourself."* Making background the default means the
   model routinely holds a turn with an outstanding result it does not have, and the failure mode is
   hallucinating that result. The mitigation ships in the same string as the capability.

**Edge case / failure mode.** `isolation: "remote"` is *always* background (`:397993`), so a model
that passes `run_in_background: false` alongside `isolation: "remote"` is asking for something the
runtime cannot give. The prompt states the constraint; nothing in the schema enforces it.

**Key insight:** the "gradual rollout" the bullet mentions left no gate behind in 2.1.220 — there is
no `tengu_*` flag guarding background subagents in this build. The rollout ended by *deleting* the
conditional, which is why the delta shows up as an inverted English sentence rather than a boolean.

## 4. Deep-dive B — bullet 5 is a RENAME, and the code says so out loud

> ⚠ The changelog reads *"Gateway: added Claude Platform on AWS (`anthropicAws`) as an upstream

**Why the count fell.** In 2.1.193 every model carried its own hand-written camelCase provider map, so

## 6. Deep-dive D — bullet 28, the highlight.js bump, pinned exactly

> `48_accessibility_ui/terminal_rendering.md` §10 records this as *"real but a vendored-dependency
> bump, not analysed"*. It is trivially pinnable, so here it is.

The bundle carries the highlighter's own version constant, assigned to the public `versionString`
export:

| | 2.1.193 | 2.1.220 |
|---|---|---|
| version constant | `var kep = "10.7.3";` `:268584 (193)` | `var wmb = "11.11.1";` **`:633630`** |
| assignment | `(e.versionString = kep)` `:269145 (193)` | `(e.versionString = wmb)` **`:634077`** |
| `hljs` occurrences | 5 | **60** |

So the bullet's "highlight.js 11" is precisely **10.7.3 → 11.11.1** — a *major* version jump that
skipped the entire 11.0–11.10 line at once. The 5→60 jump in `hljs` occurrences is the surface
signature: highlight.js 11 restructured its language definitions so that far more of the library's
internal identifier appears in the emitted bundle.

**Why it matters beyond syntax colours.** The bullet says the improvement covers *"code blocks, diffs,
and file previews"* — three different renderers sharing one highlighter. A major-version bump of a
shared dependency is the cheapest possible way to improve all three at once, and the riskiest, because
10.x→11.x removed deprecated APIs. That is the trade this bullet is quietly reporting.

**Key insight:** "vendored dependency bump" is not a reason to stop — vendored libraries carry their
own version strings, and those strings are the single most citable anchors in a minified bundle.
