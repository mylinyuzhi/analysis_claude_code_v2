the analysis method changes: almost nothing here is a new mechanism. Ten of the 47 bullets patch the
Bash/PowerShell permission analyzer, and every one of those patches is a **single line, a single

## 1. Release narrative

**What this release was for.** `.212` was the feature release — `/fork` became a background session,
`/subtask` took over in-session delegation, four session budgets landed. `.214` is its
counterweight: a **hardening and correctness sweep** with exactly one new capability
(`EndConversation`) and forty-six repairs. The centre of gravity is the *permission analyzer* — the
component that decides whether a shell command may run without asking the user. Bullets 1–7, 14, 44 and
45 all land in it, and together they close five distinct classes of bypass: path-anchoring
(`Edit(src/**)` matching `deep/nested/src`), tokenizer divergence (fd redirects, zsh subscripts,
over-length commands), read-only flag-allowlist over-permissiveness (`help`, `man`, `file`), a
daemon-redirect blind spot (`docker --url`), and a Windows compound-command sandbox escape.

**The method this release forces.** Every one of those bullets reads like an introduction, and none of
them is. `_GROUND_TRUTH_verified_anchors.md` §6.4 is the worked example, written against this exact
release: the "commands over 10,000 characters" bullet has a decoy constant (`10000` is 220=36 / 193=34),
a decoy literal (`10,000 characters` at `:205495` is the *Windows sandbox argv* message), and a real
delta of **one line** at `:392119` — while the named constant, the six-regex divergence predicate and
the other eight over-length guards are byte-equivalent carryover. The same shape repeats through the
whole batch: bullet 5's zsh refusal has a **sibling that is 1/1 carryover** (`:211212`); bullet 40's fix
is a six-character conjunct that adds no literal at all; bullet 46's fix is a *deleted* feature gate.
Reporting the carryover is the finding here, and it is more useful than an invented introduction.

**The second theme is the background daemon.** Bullets 26–30 are five consecutive lifecycle repairs —
a displaced daemon deleting its successor's control socket, parked sessions pinning a daemon and a
worker forever, completed sessions that `claude rm` could not remove once the service went idle,
sessions dispatched from a non-git folder that the agent view could not delete, and a stopped session
that reopened without its conversation. Four of the five are anchored only by new `tengu_*` gates;
the roster/handoff machinery they patch is documented in
[`../36_background_agents/`](../36_background_agents/).

**The third is OpenTelemetry.** Five bullets (11, 12, 15, 34, 38, 41) touch the telemetry stack, and
two of them share an eighty-line span: `V1g()`/`q1g = 61440` at `:167272-167289` (the content
truncation limit) and `X1g()` at `:167346-167352` (trace-context resolution). The remaining PowerShell
cluster (21–25) is one JavaScript object — the tool descriptor at `:169515-169576` — whose new command
prologue `P$g` (`:169565`) and environment `O$g` (`:169575`) fix four separate changelog bullets at once.

**Relation to its neighbours.** `.214` inherits `.212`'s `/ultrareview` precondition state machine and
adds the fifth branch to it (bullet 35, the git-empty-tree fallback). It sets up `.216`, which continues
the Windows permission work (`.216` #22, invisible-Unicode validation in the PowerShell tool) and adds
`sandbox.filesystem.disabled`. And `EndConversation` — a tool whose availability is gated four ways,
including a *model version floor* — anticipates `.219`'s Opus 5 launch: the floor is the mechanism that
keeps the tool away from models that were never trained on it.

### 3.1 The one-line delta pattern — bullets 4 and 5

**What it does:** two bullets that read as new refusal categories are, in the source, one added `if` and
one added `reason` string inside pre-existing walkers.

**How it works.**

Bullet 4's guard sits at the head of `classifyReadOnlyCommand` — the fast path that decides whether a
command can skip the permission prompt entirely:

// Location: cli_inner_pretty.js:392117-392124
// ============================================

Bullet 5 is even narrower. The `[[ ]]` operand walker `L0u` (`:210357-210378`) already existed; `.214`
added one refusal arm to it (`:210369-210374`) whose `reason` string differs from an existing sibling by
five words:

| refusal | 2.1.220 | 2.1.193 |
|---|---|---|
| `zsh $name[expr] / $name:mod in **[[ ]] operand** — recursive eval` | `:210371` | **absent** |
| `zsh $name[expr] / $name:mod in **bare concatenation** — recursive eval` | `:211212` | `:225032 (193)` |

So the *class* of refusal — zsh's `$name[expr]` subscript and `$name:mod` modifier syntax, which bash
treats as literal text but zsh re-evaluates — was already understood by the analyzer. What `.214` adds
is that it is now also detected **inside `[[ ]]` comparison operands**, where the walker previously
descended without checking. A count-only grep of `zsh $name[expr]` returns 220=2 / 193=1, which is
correct but tells you nothing; only reading both sites reveals that one is a move-in and the other is a
byte-for-byte survivor.

**Why this approach.** The whole shell-permission subsystem is built on an admission of defeat: the
analyzer's tokenizer is *not* bash and is *not* zsh, and every place the three can disagree is a
potential bypass. Rather than trying to become a correct shell, the design catalogues divergences and
refuses them by name — 13 `bashMissKind` categories, a six-regex divergence predicate `Fsn`
(`:512253`), and a growing table of `too-complex` reasons. `.214` adds four entries to that table
(fd-variable assignment, close-fd word-swallowing, multi-target redirects, `[[ ]]` zsh subscripts) plus
one length bound. Each is cheap, individually auditable, and can only ever *reduce* the auto-approved
set.

**Trade-off.** `AIe = 1e4` is a hard, ungated, un-overridable constant. There is no env var and no
GrowthBook flag for it — contrast `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`, whose default is gate-backed
precisely because Anthropic expected to tune it. A security threshold that nobody should be able to
raise remotely is the right call, but it means a legitimate 10,001-character command prompts forever.

**Key insight:** the strongest evidence that this is a mature subsystem is the **absence** of new
literals. Nine of the ten over-length guard sites, the named constant, and the divergence predicate are
byte-equivalent between builds (`_GROUND_TRUTH_verified_anchors.md` §6.4 lists all of them). When a
release patches mature machinery, "what did not change" carries more information than "what did".

### 3.2 `yap` — one six-line function, two bullets, and a deliberate asymmetry

**What it does:** `yap` decides how a glob pattern ending in `/**` is anchored. Bullets 1 and 44 are the
same function seen from two call sites.

```javascript
// ============================================
// anchorSingleSegmentGlob - anchors `dir/**` at the cwd for allow rules and hook `if:` conditions
// Location: cli_inner_pretty.js:528456-528462
// ============================================

// ORIGINAL (for source lookup):
function yap(e, t) {
  if (e.endsWith("/**")) {
    let r = e.slice(0, -3);
    return /[^/]/.test(r) ? (r.includes("/") || !t || /^[!#]/.test(r) ? r : "/" + r) : "/**";
  }
  return e;
}

// READABLE (for understanding):
function anchorSingleSegmentGlob(pattern, anchorAtRoot) {
  if (pattern.endsWith("/**")) {
    let stem = pattern.slice(0, -3);                 // "src/**" -> "src"
    if (!/[^/]/.test(stem)) return "/**";            // pattern was just "/**" (or "//**") -> match everything
    if (stem.includes("/")) return stem;             // already multi-segment ("a/b") -> gitignore already anchors it
    if (!anchorAtRoot) return stem;                  // deny/ask: keep any-depth (gitignore) semantics
    if (/^[!#]/.test(stem)) return stem;             // "!"/"#" are gitignore metacharacters - do not prefix
    return "/" + stem;                               // "src" -> "/src": anchored at the match root
  }
  return pattern;
}

// Mapping: yap→anchorSingleSegmentGlob, e→pattern, t→anchorAtRoot, r→stem
```

**Call sites, and the asymmetry they encode:**

| site | argument | consumer | resulting semantics |
|---|---|---|---|
| `:528493` | `t = (r === "allow")` | permission rule compilation | **allow** rules anchor; **deny**/**ask** rules keep any-depth |
| `:528541` | `t = !0` (unconditional) | hook `if:` conditions | always anchored |

This is the whole of bullets 1 and 44. `Edit(src/**)` used to compile to a gitignore pattern `src`,
which gitignore semantics match at **any depth** — so `vendor/thirdparty/src/x.ts` was auto-approved by
a rule the user wrote meaning "my project's `src`". Prefixing `/` pins it to the match root.

**Why the asymmetry is deliberate and correct.** The two rule families have opposite failure
directions:

- An over-broad **allow** rule is a security bug: it grants writes the user never intended.
- An over-broad **deny**/**ask** rule is merely inconvenient: it prompts more than necessary.

So the fix narrows `allow` and leaves `deny`/`ask` wide — and the changelog says so explicitly
("`deny`/`ask` permission rules keep their any-depth match"). Hook `if:` conditions go with `allow`
because an `if:` that matches too widely causes a hook to *fire* on files it should not see, which is
the security-relevant direction.

**The `[!#]` clause is the non-obvious part.** In gitignore syntax `!` negates and `#` comments. If a
user writes a rule whose stem begins with either character, prefixing `/` would produce `/!foo` — a
pattern gitignore parses differently from both `!foo` and `/!foo` as the user intended. The code opts
out rather than mangling it, accepting that such a rule keeps the old any-depth behaviour.

**Key insight:** this is the highest-leverage six lines in the release. One function, two changelog
bullets, three distinct rule families, and a security/UX trade-off resolved by a single boolean
parameter.

command runs under the sandbox, and on Windows under an enterprise mandatory-sandboxing policy, a
command that escapes the sandbox escapes the check.

## 4. What the changelog does not say

### 4.1 A flag that never existed

Bullet 45 says `file` commands using "`-m`/`--magic-file` or `-f`/`--files-from`" now require
permission. The 2.1.193 read-only table (`:305906-305945 (193)`) contained `-f: "string"`,
`--magic-file: "string"` and `-m: "string"` — **three** entries, and **no `--files-from`**. GNU `file`
has no `--files-from`; the long form of `-f` is `--files-from` in some *other* tools, and the changelog
appears to have back-filled it. The 2.1.220 table (`:392409-392446`) simply lacks all three. So the
bullet over-specifies by one flag and under-counts by one deletion.

### 4.2 Bullet 4 has an undocumented second half

The over-length work has two independent halves and the changelog describes only one. Besides the new
`passthrough` guard, the **dangerous-pattern scanner** changed direction: 2.1.193's `kki(e)` returned
`null` — i.e. *skipped pattern matching entirely* — when `e.length > 1e4` (`:150813 (193)`), whereas
2.1.220 truncates to `1e4` and still runs the patterns (`:223566`, `:315070`, `:442700`). The 193
behaviour meant an attacker could *pad* a command past 10,000 characters to make the destructive-command
scanner ignore it. That is arguably the more serious of the two fixes, and it has no bullet.

### 4.3 Bullet 5's sibling is carryover

`zsh $name[expr] / $name:mod in **bare concatenation** — recursive eval` exists identically in both
bundles (`:211212` vs `:225032 (193)`). A reader who takes the bullet at face value will conclude that
zsh subscript handling arrived in `.214`; it did not. Only the `[[ ]]` operand position is new.

### 4.4 `EndConversation` ships with a kill-switch stub and a fork-specific prompt

Bullet 8 announces the tool. It does not mention that:

- The rollout dial is a GrowthBook flag with an opaque codename — `qus = "tengu_umber_kestrel"` at
  `:231370` (220=1 / 193=0) — whose payload is parsed three ways by `Fxd` and carries an **entrypoint
  allow-list regex**, so the tool can be enabled per surface.
- There is a **model version floor** (`$xd`, a dotted-version compare at `:412940-412949`), which means
  switching models mid-session with `/model` can add or remove the tool from the tool set.
- A **separate reflection prompt exists for the fork path** (`Z1s`,
  `END_CONVERSATION_FORK_REFLECTION_PROMPT`, in the export table at `:412952-412962`).
- The whole effect is suppressible by a build-variant stub: `zoo()` at `:162794` is literally
  `function zoo() { return !1 }`.

Four independent gates guard one tool. Full analysis in
[`../04_tools/end_conversation_tool.md`](../04_tools/end_conversation_tool.md).

### 4.5 Bullet 10's anchor in the scoping pass is a decoy, and the writer does more than dating

`modified: new Date(` is **220=3 / 193=3** — all three sites (`:526781`, `:527058`, `:527327`) are
`/resume` session-list builders reading file mtimes, and they exist unchanged in 193

### 4.8 Bullet 24 is not anchorable as written

### 4.9 The `.214` PowerShell prologue silently opts some commands out

requires to be first in a script, where prepending anything is a hard parse error. Those commands

changelog presents 22/23/25 as unconditional.

`Needs attention` is **220=1 / 193=1** carryover, and its single 220 site (`:712396`) is a
skills/favorites picker section header, not the agents list. The delta, wherever it is cited, is the
state machine that assigns the label — see
[`../36_background_agents/agent_view_and_status.md`](../36_background_agents/agent_view_and_status.md) §2.
