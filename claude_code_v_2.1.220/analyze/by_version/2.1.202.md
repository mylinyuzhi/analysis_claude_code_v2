## a) Release narrative

**2.1.202 is the release where the Workflow feature got its first user-facing dial and its first
telemetry identity — and where a long tail of "the thing worked but the plumbing around it leaked"
bugs got cleared.** Two of its eighteen bullets are additions, both about workflows: a `/config` row
called **Dynamic workflow size** that tells the model roughly how many `agent()` calls a dynamic
workflow should contain, and the OTel attributes **`workflow.run_id` / `workflow.name`**, which for
the first time make a workflow run reconstructible from an observability backend. Everything else is
repair.

The centre of gravity of that repair is **"the message survived, the wrapper did not."** Look at the
shapes: a workflow script whose unicode escapes were mangled by a generic un-escaping pass *before*
the parser ever saw it (#10); a skill whose instructions were appended a second time because the
re-invocation path did not recognise its own earlier output (#15); an installer download that failed
permanently because a mid-stream socket close was classified as a user abort (#14); a sign-in URL
that was correct but line-wrapped by SSH into three unclickable fragments (#8); a history search that
crashed because a cancel path nulled the generator the scan loop was still awaiting (#3). In each
case the payload was fine and the transport, framing or lifecycle around it was not. That is the
signature of a codebase whose features have outrun their edges — and it is exactly the pattern the
next release, [`2.1.203`](2.1.203.md), scales up by 2× against the background-agent daemon.

The third thread is **Remote Control**, which contributes three bullets (#6, #7, #12). Two of the
three are unanchorable at the literal level because the
mobile/web halves live outside this bundle; the one that *is* anchorable — the permission mode a
remote client displays — turns out to be two fixes wearing one bullet: a second bridge host learned
to answer `initialize`, and the mode joined the periodic `system/init` frame so a change after connect
reaches an already-attached phone. See
[`../54_remote_control/security_and_enablement.md`](../54_remote_control/security_and_enablement.md) §5.

Finally, `.202` contains a quiet **retreat**: `/review <pr>` is put back to a single-pass prose review
and the multi-agent path is fenced behind an explicit `/code-review <level> <pr#>`. This is the second
of a four-step oscillation (`.196` → `.202` → `.215` → `.218`) over how much fan-out a review command
may do on its own initiative; [`../52_code_review/manual_invocation_gating.md`](../52_code_review/manual_invocation_gating.md)
tracks the whole sequence. It is worth noticing that `.202` ships an *advisory* size guideline for
workflows in the same release that it *removes* a command's licence to fan out — the same tension,
solved two different ways, twelve bullets apart.

## c) Deep dives

The four richest bullets in this release (#1, #2, #10, #18) all have a module doc that derives them
end-to-end, so this section deliberately spends its depth on **the one bullet no module owns (#11)**
and on **the two places where the by-version view sees something the module view could not**: the

### c.1 `#11` — the voice recorder's "ended without ever producing audio" case (NEW ANALYSIS)

> *"Fixed voice dictation retrying in an unbounded loop when the microphone or audio recorder fails —
> repeated capture failures now pause voice input."*

Scoping filed this UNANCHORED on `silentDropRetried` (1/1). Both the scope file and
[`../48_accessibility_ui/README.md`](../48_accessibility_ui/README.md) route it to "OTHER THEME" with
no owner. It is anchorable, and the reason it looked unanchorable is instructive.

**What it does:** the voice subsystem already had a circuit breaker. `.202` did not add one — it added
the *one failure mode the breaker could not see*, so that the breaker finally trips on it.

**How it works, step by step:**

1. `YLn()` (`:759556-759558`) is the failure recorder: `ZAt.push(Date.now())`. `ZAt` is a plain
   array of failure timestamps.
2. `oFS()` (`:759559-759561`) is the success reset: `ZAt.length = 0; $ui = !1`.
3. The breaker itself lives at the top of the start-recording handler `oe()`
   (`:759832-759847`): evict timestamps older than `NKf`, and if `ZAt.length >= FKf`, refuse to start
   a new session, emit `tengu_voice_circuit_breaker_tripped`, and show
   *"Voice input is failing repeatedly and has been paused. Check your microphone and try again in a
   moment."*
4. The constants are `NKf = 1e4` and `FKf = 3` (`:760117-760118`) — **three early failures inside a
   10-second window**.

**The carryover trap, stated plainly.** Every one of steps 1–4 exists in 2.1.193: `qOe.push(Date.now())`
at `:649439 (193)`, the reset at `:649442 (193)`, the identical breaker block at `:649705-649716 (193)`
including the byte-identical log line, and `rmc = 1e4, omc = 3` at `:649983-649984 (193)`. `grep -c
'circuit breaker'` is **6/6**. Anyone anchoring this bullet on the breaker writes a false delta.

**The actual delta is one boolean and one `if`.** In 2.1.193 the recorder's *end* callback was:

```javascript
// ============================================
// onRecorderEnd - what happens when the audio recorder stops (2.1.193 shape)
// Location: cli_inner_pretty.js:649765-649767 (193)
// ============================================

// ORIGINAL (for source lookup):
() => {
  if (a.current === "recording") J();
},
```

`J()` is the finish-and-transcribe path. If the recorder process died *immediately* — no capture
device, a permission denial, a SoX/`ffmpeg` spawn that exits at once — the end callback fired having
delivered **zero** data chunks, and 193 treated that identically to a normal stop: finish the session,
return to idle, and let the user press the key again. No failure was recorded, so `qOe` stayed empty,
so the breaker never counted past zero, so the user could retry forever against a broken device. That
is the "unbounded loop" in the bullet.

2.1.220 threads a *did-any-audio-arrive* flag through the two callbacks:

```javascript
// ============================================
// startVoiceRecordingSession - the recorder's data/end callbacks, with the new no-audio detector
// Location: cli_inner_pretty.js:759878-759901
// ============================================

// ORIGINAL (for source lookup):
let ae = !1;
if (
  !(await xZe.startRecording(
    (Ne) => {
      ae = !0;
      let ge = Buffer.from(Ne);
      ...
    },
    () => {
      if (a.current === "recording") {
        if (!ae && I.current === ee) YLn();
        V();
      }
    },
    { silenceDetection: !1 },
  ))
) { ... }

// READABLE (for understanding):
let receivedAnyAudio = false;
const started = await voiceModule.startRecording(
  (chunk) => {                                   // onData
    receivedAnyAudio = true;                     // NEW in .202
    const buf = Buffer.from(chunk);
    ...
  },
  () => {                                        // onEnd
    if (recordingState.current === "recording") {
      if (!receivedAnyAudio && sessionSeq.current === mySessionSeq)
        recordEarlyVoiceFailure();               // NEW in .202 -> feeds the 3-in-10s breaker
      finishRecording();
    }
  },
  { silenceDetection: false },
);

// Mapping: ae→receivedAnyAudio, xZe→voiceModule, YLn→recordEarlyVoiceFailure, V→finishRecording,
//          I.current→sessionSeq, ee→mySessionSeq, a.current→recordingState
```

**Why this approach.** The alternative — count *every* `finishRecording` with an empty transcript as a
failure — would trip the breaker on a user who pressed the key and said nothing, which `.200` had just
spent a bullet distinguishing (*"No audio detected from microphone"*, `:759581`, itself 1/1 carryover;
see [`../00_overview/_false_delta_ledger.md`](../00_overview/_false_delta_ledger.md) register 1).
Keying on "the *recorder* ended and never handed us a single byte" separates a **device/tooling
failure** from a **silent user**, and it is observable at exactly one place — the boundary between the
native capture module and the JS layer.

The `I.current === ee` guard is the second half of the correctness argument: `I.current` is a
monotonic session sequence number bumped by `let ee = ++I.current` at `:759860`. Without it, a *stale*
recorder's end callback arriving after the user already started session N+1 would charge a failure to
the wrong session and could trip the breaker on a healthy device. **Ordering matters**: the flag is
checked before `V()` (finish) runs, because `V()` transitions the state machine out of `"recording"`
and would make the outer `a.current === "recording"` test unreliable for any later reader.

**Key insight:** the bullet says "repeated capture failures now pause voice input", which reads like a
new pause mechanism. The pause mechanism is a year old. What `.202` shipped is the *sensor* — and the
reason the fix took the shape of one boolean is that the breaker was already there, waiting for a
signal that no code path was producing.

### c.2 `#2` — `workflow.run_id` / `workflow.name`, and a correction to ground truth §3

[`../_GROUND_TRUTH_verified_anchors.md`](../_GROUND_TRUTH_verified_anchors.md) §3 files this bullet as
a partial carryover: *"220=3 / 193=2. Partially pre-existing. Find the one new emission site."* That
count is an artefact of an unescaped `.` in the grep pattern, and it is worth spelling out because the
same mistake is available on dozens of attribute names in this window.

```
grep -c  'workflow.run_id'   # regex: '.' matches any char  -> 220=3 / 193=2
grep -cF 'workflow.run_id'   # fixed string                 -> 220=1 / 193=0
grep -cF 'workflow.name'     # fixed string                 -> 220=1 / 193=0
```

The two 2.1.193 "hits" are `workflow_run_id` at `:424852 (193)` and `:424892 (193)` — the **snake_case
workflow transcript-event fields**, a completely different namespace from the **dotted OTel attribute
keys**. In 2.1.220 the snake_case fields still exist (`:446796`, `:700153`) *alongside* the new dotted
ones, so the bullet is not partially pre-existing at all: it is fully net-new, and the pre-existing
literal it collides with belongs to another subsystem.

Both attributes are produced by a single function and a single `return`:

```javascript
// ============================================
// buildWorkflowOtelAttributes - the whole of .202's OTel addition
// Location: cli_inner_pretty.js:111459-111462
// ============================================

// ORIGINAL (for source lookup):
function D5r(e) {
  if (!e || !mde(e) || !e.workflowRunId) return {};
  return { "workflow.run_id": e.workflowRunId, ...(e.workflowName && { "workflow.name": e.workflowName }) };
}

// READABLE (for understanding):
function buildWorkflowOtelAttributes(agentContext) {
  if (!agentContext || !isSubagentContext(agentContext) || !agentContext.workflowRunId) return {};
  return {
    "workflow.run_id": agentContext.workflowRunId,
    ...(agentContext.workflowName && { "workflow.name": agentContext.workflowName }),
  };
}

// Mapping: D5r→buildWorkflowOtelAttributes, mde→isSubagentContext, e→agentContext
```

Three design decisions are visible in four lines. **First**, the guard `!mde(e)` scopes the attributes
to *subagent* contexts only — the main thread never carries them, so a workflow run's OTel trace
contains exactly the spawned agents and nothing else. **Second**, `run_id` is mandatory and `name` is
conditional: a run always has an id (it is the join key), but a script invoked by path has no `meta.name`,
and emitting `workflow.name: undefined` would poison group-bys in the backend. **Third**, the sibling
`nZ` immediately below (`:111463-111466`) returns the *same two values in camelCase* — `{workflowRunId,
workflowName}` — for the internal event stream. Keeping two formatters instead of one mapping layer is
the cheap way to let the OTel naming convention (dotted, snake) and the internal convention (camel)
evolve independently. The full emission path is in
[`../44_telemetry/otel_attributes_and_correlation.md`](../44_telemetry/otel_attributes_and_correlation.md) §2.

### c.3 `#18` — the `/review` revert, proved by an absence

The interesting thing about this bullet is that **no string was added**. `single-pass` goes 2 → 9, which
looks like the anchor and is not: six of the nine 2.1.220 hits are the per-effort `/code-review` prompt
variants and two are the bundled `claude-api` skill. The proof is a deletion, and it is visible by
reading the same prompt in both bundles:

```javascript
// ORIGINAL 2.1.193 (for source lookup) - :538527-538531 (193):

  ${Hzn}
  ## Present the review
  After the final phase, do not reply with the raw JSON findings array. Present a readable review: ...
// ... descriptor :538537-538545 (193):
  oRf = { type: "prompt", name: "review", ..., effort: "medium", progressMessage: "reviewing pull request", ... }

// ORIGINAL 2.1.220 (for source lookup) - :497606, :497621-497628, :497636-497641:
  The PR's diff is the only review scope \u2014 local working-tree changes are out of scope. When you need surrounding code, Read the files in this checkout ...
  Analyze the changes and provide a thorough code review that includes:
  - An overview of what the PR does
  - Analysis of code quality and style
  - Specific suggestions for improvements
  - Any potential issues or risks
// ... descriptor :497635-497641:
  nR_ = { type: "prompt", name: "review", description: "Review a GitHub pull request; for your working diff use /code-review",
          argumentHint: "[pr number]", progressMessage: "reviewing pull request", contentLength: 0, source: "builtin", ... }

// Mapping: rRf→rR_ (prompt builder), oRf→nR_ (command descriptor), Hzn→multiAgentReviewPhasePrompt (193 only)
```

Three removals, one word change:

1. **`${Hzn}` is gone.** In 2.1.193 that interpolation injected the multi-phase, multi-angle fan-out
   instructions (`Ktm.medium`, `:650897 (193)`). Its absence is the entire bullet.
2. **`effort: "medium"` is gone from the descriptor.** The field is what let the command request an
   effort tier at all; without it there is no tier to fan out at.
3. **The "Present the review" JSON-findings epilogue is gone**, replaced by four plain prose bullets —
   because there is no findings array any more.
4. **"When an *angle* needs surrounding code" → "When *you* need surrounding code."** "Angle" is the
   multi-agent review's vocabulary for a reviewer persona. Its disappearance from a sentence that was
   otherwise left untouched is the tell that this was a deliberate de-multi-agenting of one command,
   not an accidental prompt rewrite.

**Why revert rather than make it cheaper?** [`../52_code_review/manual_invocation_gating.md`](../52_code_review/manual_invocation_gating.md)
§1 shows they had already tried cheaper in `.196`. The trade-off `.202` settles on is **discoverability
of cost**: `/review <pr>` is the reflexive command, typed dozens of times a day, and a user typing it
does not expect to pay for N subagents; `/code-review <level> <pr#>` makes the level an argument the
user must type, so the cost is opted into rather than defaulted into. The same instinct — *give the
model a target, not a licence* — is what makes `.202`'s workflow size guideline **advisory** rather
than an enforced cap.

### c.4 `#1` — Dynamic workflow size (summary; module owns the derivation)

Fully derived in [`../42_workflow/workflow_size_guideline.md`](../42_workflow/workflow_size_guideline.md);
what belongs here is the shape and one caveat.

The setting is an enum with four members (`:60915`
`v.enum(["unrestricted","small","medium","large"])`) whose `.describe()` at `:60918` carries the
thresholds *in prose*: small `< 5` agents, medium `< 15`, large `< 50`, unrestricted sends nothing. The
same numbers exist as data at `:389147` (`tko = { small: 5, medium: 15, large: 50 }`), and the prose
generators `dEd` / `fEd` / `pEd` (`:389124-389137`) turn a size into a sentence that is appended to the
session's instructions. Nothing consults `tko` to *refuse* an `agent()` call — the guideline is
delivered as text to the model and nowhere enforced, which is why the changelog says *"an advisory
guideline, not an enforced cap"* and why `pEd()` ends with *"This is a guideline, not a hard limit."*

The `/config` row (`:451501-451520`) is gated on `E` = `workflowSizeGuidelineToggleable` (`:451231`),
and `Q$t()` (`:389149-389151`) is the predicate that turns the row off when a settings file supplies the
key — the exact behaviour `.219`'s bullet later describes. Resolution order is settings → `/config`
value → `cEd = "medium"` (`:389143`), memoised once per process by `Nsn` (`:389156-389159`).

> **Caveat, carried from the module doc so it is not lost:** 2.1.193 predates the entire feature
> (`workflowSizeGuideline` **21/0**), so the two available bundles **cannot separate what `.202` shipped
> from what `.219` added**. The `medium` default is filed under `.219` on internal evidence (the
> "(default)" suffix machinery in `rko`, `:389118-389120`), not on a bundle diff. Treat the `.202`/`.219`
> split as an inference.

## d) What the changelog does not say

**1. `.202`'s biggest workflow change may not be in `.202` at all.** Per the caveat above, the bundle
cannot attribute the `medium` *default* to a release. The changelog gives `.202` the `/config` row and
`.219` the settings key + default; the code is consistent with that but does not prove it.

**2. The unicode-escape bullet hides a Windows-path landmine that the changelog never mentions.** #10
reads as one fix. It is two, and the first one contains a subtlety worth stating: the repair regex
(`:508587`) matches surrogate pairs *first* and then the BMP form, and `vqs` (`:508482-508490`) carries
an explicit **Windows-path skip** (`UO_.test(e)` → `t.windowsPathSkips++`) so that a literal
`C:\users\…` is not "repaired" into a Unicode escape. The telemetry event
`tengu_repair_double_escaped_unicode` (`:508476`) reports `{repaired_strings, windows_path_skips}` as
two separate counters — i.e. Anthropic instrumented the *skip* as carefully as the repair, which is
what you do when you have already been burned by over-eager unescaping. None of that is in the bullet.

**3. The `.202` breaker/sensor split (§c.1) is invisible from the changelog and inverted by it.** The
bullet's phrasing — *"repeated capture failures now pause voice input"* — attributes the pause to this
release. The pause shipped before 2.1.193. Reading the bullet as written produces a false delta on a
100 %-carryover mechanism; this is the same class of error as `_GROUND_TRUTH` §6.6 (the retracted
compaction circuit breaker, which is **1/1 carryover** — see
[`../07_compact/dispatcher_and_failure_breakers.md`](../07_compact/dispatcher_and_failure_breakers.md)).
Two circuit breakers in this tree, two changelog bullets that read as introductions, two carryovers.

**4. Three Remote-Control bullets in one release, and the bundle can only see one of them.** #6, #7 and
#12 all describe mobile/web symptoms. Only #12 has a client-side site; #6's literal is 3/3 and #7's is
pure noise. A reader counting "Remote Control fixes shipped in `.202`" from this bundle will find one,
not three — the other two live in apps that are not in this artefact. That is not a gap in the analysis;
it is a boundary of the artefact, and it should be stated rather than papered over with a plausible
nearby anchor.

**5. `.202` is the release that made `/review` and `/code-review` mean different things, and the
changelog frames it as a *revert* rather than as the product decision it is.** *"Changed `/review <pr>`
back to…"* reads as undoing a mistake. What actually shipped is a permanent two-command split — a cheap
reflexive command and an explicit expensive one — that survives through `.220` and gets extended in
`.215` (self-invocation blocked) and `.218` (`/code-review` as a background subagent). See
[`../52_code_review/README.md`](../52_code_review/README.md) for the four-step oscillation table.

**6. Nothing in `.202` mentions the model registry.** The single largest structural change in the whole
`.193 → .220` window — the model catalogue rewrite at `:14009-14496` — is undocumented in every release
of this window, `.202` included. See [`../47_models/model_catalogue_rewrite.md`](../47_models/model_catalogue_rewrite.md).
