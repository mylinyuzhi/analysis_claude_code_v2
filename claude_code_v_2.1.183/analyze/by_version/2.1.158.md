# v2.1.158 — Source Diff Analysis

**Theme:** **Auto mode escapes first-party.** 2.1.158 is a single-bullet release that opens up *auto mode* (the autonomous-execution permission mode) to the third-party model providers — **Bedrock, Vertex, and Foundry** — but only for the two newest Opus models, **Opus 4.7 and Opus 4.8**, and only when the user explicitly opts in with `CLAUDE_CODE_ENABLE_AUTO_MODE=1`. Before this, auto mode was hard-gated to first-party providers (Anthropic API / `anthropicAws`): the model-support predicate began with a blunt `if (provider !== "firstParty" && provider !== "anthropicAws") return false`, so a Bedrock/Vertex/Foundry user could never enter auto mode regardless of model. 2.1.158 replaces that hard wall with a two-part gate: an env-var opt-in *and* a model allowlist that, on third-party providers, admits only Opus 4.7/4.8 and explicitly rejects Opus 4.6, all Sonnet, and all Haiku. The change is small in surface area (a handful of predicates) but meaningful in policy: it extends the highest-trust permission mode to the cloud-hosted deployments enterprises actually run on, while keeping the blast radius narrow (newest Opus only, opt-in only).

> Auto mode is the permission mode where Claude executes actions without per-action confirmation, gated by an LLM "auto-mode classifier" and a circuit breaker. This file covers only the *provider/model availability* change; the broader auto-mode machinery is unchanged in 2.1.158.

## 1. Auto mode available on Bedrock / Vertex / Foundry for Opus 4.7 & 4.8 (opt-in)

**Type:** feature (provider/model availability) · **Modules:** Auto mode, Model selection, Permissions

### TL;DR

Setting `CLAUDE_CODE_ENABLE_AUTO_MODE=1` now lets a user on a third-party provider (Bedrock / Vertex / Foundry, anything `Ir()` resolves to other than `firstParty`/`anthropicAws`) enter auto mode — *provided* the active model is Opus 4.7 or Opus 4.8. The opt-in is required because, unlike first-party where Anthropic controls the full stack, third-party deployments are a less-validated surface for autonomous execution. The model allowlist is the second guardrail: on third-party providers the gate explicitly rejects `claude-opus-4-6`, every `sonnet`, and every `haiku`, so only the two newest Opus models qualify.

### How it works

Three small predicates carry the whole change, all in the same neighborhood of the bundle:

**Step 1 — the provider opt-in predicate `providerAllowsAutoMode` (`yxt`, cli_inner_pretty.js:134546-134549).** First-party and `anthropicAws` always pass. Any other provider passes *only* if `CLAUDE_CODE_ENABLE_AUTO_MODE` parses truthy (`st`, the boolean parser, accepts `1/true/yes/on`, cli_inner_pretty.js:163-168).

```javascript
function yxt(e) {
  if (e === "firstParty" || e === "anthropicAws") return !0;
  return st(process.env.CLAUDE_CODE_ENABLE_AUTO_MODE);
}
```

**Step 2 — the model-support gate `isAutoModeModelSupported` (`Yve`, cli_inner_pretty.js:134560-134584).** This is where the before/after diff is sharpest. It calls `providerAllowsAutoMode` first (so a non-opted-in third-party provider short-circuits to `false`), then applies a *base* model rejection list (legacy 3.x, Opus 4.0/4.1/4.5, Sonnet 4.0/4.5, Haiku 4.5 are never auto-eligible on any provider), and then a *third-party-only* rejection: on a non-first-party provider it additionally rejects `claude-opus-4-6` and anything containing `sonnet` or `haiku`. What survives on third-party is exactly Opus 4.7 (`claude-opus-4-7`) and Opus 4.8 (`claude-opus-4-8`) — the only two Opus ids not in either list (cli_inner_pretty.js:837-836 confirm those ids exist in this build).

**Step 3 — the reason string + the carousel gate.** When the gate denies, the reason→message mapper `autoModeDenialMessage` (`Gne`, cli_inner_pretty.js:586569-586585) now has a fourth case, `"provider"` → **"auto mode requires CLAUDE_CODE_ENABLE_AUTO_MODE=1"**, and the gate-evaluation flow (`verifyAutoModeGateAccess`, cli_inner_pretty.js:586586+) emits that reason when `!providerAllowsAutoMode(Ir())` (cli_inner_pretty.js:586615, log: `auto mode disabled: provider ${Ir()} requires the CLAUDE_CODE_ENABLE_AUTO_MODE opt-in`). The "can this provider/model show the auto carousel at all" helper `autoModeAvailableForProvider` (`tgn`, cli_inner_pretty.js:134550-134556) — third-party-and-opted-in — feeds `bRr` (cli_inner_pretty.js:134557-134559), which in turn drives the third-party afk-mode beta header path (cli_inner_pretty.js:582628, 582674-582675; log: `auto-mode 3P: sending afk-mode beta '...' to ${provider} via betas header`).

```javascript
// ============================================
// isAutoModeModelSupported - Auto-mode model/provider gate (now admits Opus 4.7/4.8 on 3P)
// Location: cli_inner_pretty.js:134560-134584 (v2.1.183 bundle)
// ============================================

// ORIGINAL (v2.1.183):
function Yve(e) {
  {
    let t = Bo(e),
      n = Ir();
    if (!yxt(n)) return !1;
    if (
      t.includes("claude-3-") ||
      t === "claude-opus-4-0" || t === "claude-opus-4-1" || t === "claude-opus-4-5" ||
      t === "claude-sonnet-4-0" || t === "claude-sonnet-4-5" || t === "claude-haiku-4-5"
    )
      return !1;
    if (
      n !== "firstParty" && n !== "anthropicAws" &&
      (t === "claude-opus-4-6" || t.includes("sonnet") || t.includes("haiku"))
    )
      return !1;
    return !0;
  }
  return !1;
}

// READABLE:
function isAutoModeModelSupported(modelArg) {
  let modelId = resolveModelId(modelArg),       // Bo
    provider = resolveProvider();               // Ir: firstParty | bedrock | vertex | foundry | anthropicAws | mantle | gateway
  if (!providerAllowsAutoMode(provider)) return false;   // yxt: 3P requires CLAUDE_CODE_ENABLE_AUTO_MODE=1
  // Base rejection list (no provider ever auto-modes these):
  if (
    modelId.includes("claude-3-") ||
    modelId === "claude-opus-4-0" || modelId === "claude-opus-4-1" || modelId === "claude-opus-4-5" ||
    modelId === "claude-sonnet-4-0" || modelId === "claude-sonnet-4-5" || modelId === "claude-haiku-4-5"
  )
    return false;
  // Third-party-ONLY rejection: only the two newest Opus models qualify off first-party.
  if (
    provider !== "firstParty" && provider !== "anthropicAws" &&
    (modelId === "claude-opus-4-6" || modelId.includes("sonnet") || modelId.includes("haiku"))
  )
    return false;
  return true;   // => on 3P, survives only for claude-opus-4-7 / claude-opus-4-8
}

// Mapping: Yve→isAutoModeModelSupported, Bo→resolveModelId, Ir→resolveProvider, yxt→providerAllowsAutoMode, st→parseBoolean
```

**Key insight:** The change is a *substitution of one guard for two*, not new machinery. The old code's single `return !1` for third-party providers conflated two separate questions — "is this provider allowed?" and "is this model allowed?". 2.1.158 splits them: `providerAllowsAutoMode` answers the first (and makes it opt-in-able), and the model allowlist answers the second with a provider-aware twist (stricter off first-party). Because both new predicates sit *inside* the existing `verifyAutoModeGateAccess` flow, no caller changed — the auto-mode carousel, the `isAutoModeAvailable` context flag, and the kick-out-of-auto fallback all keep working; they just now evaluate to `available` for opted-in 3P Opus-4.7/4.8 users instead of always `false`.

## Summary

2.1.158 is a one-line release that does exactly what its changelog says: it makes auto mode reachable on third-party providers. The implementation is a precise two-guard substitution for a single hard-coded wall. v2.1.156 denied auto mode to every non-first-party provider with `if (provider !== "firstParty" && provider !== "anthropicAws") return false` (and had no env var and no "provider" denial reason). v2.1.183 replaces that with `providerAllowsAutoMode` — an env-var opt-in (`CLAUDE_CODE_ENABLE_AUTO_MODE=1`) for third-party providers — plus a model allowlist that, off first-party, admits only Opus 4.7 and Opus 4.8 (explicitly rejecting Opus 4.6, Sonnet, and Haiku). The new `"provider"` denial reason ("auto mode requires CLAUDE_CODE_ENABLE_AUTO_MODE=1") makes the opt-in discoverable, and the same predicate gates the third-party afk-mode beta header. The double gate (opt-in + newest-Opus-only) is the through-line: it extends the highest-trust permission mode to the cloud deployments enterprises use while keeping the autonomous-execution surface conservative on the less-validated third-party path.
