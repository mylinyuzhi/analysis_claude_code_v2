# v2.1.170 — Source Diff Analysis

**Theme:** **The Claude Fable 5 (Mythos-class) launch.** 2.1.170 is a model-registration release: `claude-fable-5` (and its un-gated sibling `claude-mythos-5`) join the model registry across every provider, get a `"Fable 5"` display label, a dedicated `fable`/`fable[1m]` shorthand, a Mythos-class system-prompt identity block, a launch-notice telemetry event, and — the genuinely new subsystem — a **usage-credits consent gate** (`fable_overage_consent_prompt`) that intercepts the first send on Fable 5 and either runs it on usage credits or swaps the session to a fallback model. Alongside the launch sits one pointed correctness fix: **sessions launched from the VS Code integrated terminal (or any shell that inherited Claude Code's env vars) silently stopped saving transcripts** — because a newly-introduced "nested interactive Claude session" detector mistook inherited `CLAUDE_CODE_CHILD_SESSION` env for a real parent session and disabled session persistence. The fix is a tmux ambient-marker probe plus a `CLAUDE_CODE_FORCE_SESSION_PERSISTENCE` escape hatch.

Both pieces are **entirely new vs. the 2.1.156 before-picture** — neither `fable`/`mythos` nor `CLAUDE_CODE_CHILD_SESSION`/nested-session detection exist in that bundle at all. This reads as the **"ship the new flagship tier and harden the env-inheritance edge that the new child-session plumbing exposed"** release.

> Fable 5 is not one of the five focus features, so it gets primary analysis here. There is no model module dir in this tree; model-registry symbols live in `../00_overview/symbol_index_infra_platform.md`.

## 2. Fable 5 usage-credits consent gate (`fable_overage_consent_prompt`) (NEW)

**Type:** feature · **Modules:** Model, Permissions/consent, Usage credits, `/usage-credits`

### TL;DR

Because Fable 5 *"uses usage credits,"* sending a request on it is intercepted by a pre-send **consent gate**. The first time a session would send on Fable 5, a dialog (`fable_overage_consent_prompt`) asks the user to either **continue on usage credits**, **switch the default to a fallback model**, or **cancel** — and if consent is declined/dismissed (or given without the entitlement actually provisioning), the session is *swapped off* Fable 5 for the rest of the session. A swarm of error strings cover the credit states (out of funds, monthly limit reached, org turned credits off, not available for account).

### How it works

**Step 1 — The consent prompt declaration.** `nge` (cli_inner_pretty.js:230192-230197) registers a dialog of kind `"fable_overage_consent_prompt"`, payload `{ overagesEnabled: boolean }`, result enum `["consent", "switch_default", "cancelled"]`, default `"cancelled"`:

```javascript

// Location: cli_inner_pretty.js:230192-230197
// ============================================

  kind: "fable_overage_consent_prompt",
  payload: we(() => H.object({ overagesEnabled: H.boolean() })),
  result: we(() => H.enum(["consent", "switch_default", "cancelled"])),
  default: "cancelled",
});

// READABLE (for understanding):
const fableOverageConsentPrompt = defineDialog({
  kind: "fable_overage_consent_prompt",
  payload: () => z.object({ overagesEnabled: z.boolean() }),
  result: () => z.enum(["consent", "switch_default", "cancelled"]),  // continue / switch model / cancel
  default: "cancelled",
});

// Mapping: nge→fableOverageConsentPrompt, Kh→defineDialog, we→lazySchema, H→zod
```

The choice is surfaced to the user as *"choose: continue Fable 5 on usage credits or switch models"* (cli_inner_pretty.js:605807).

**Step 2 — The swap is a session-scoped model change.** The gate is documented as an `@internal` SDK message (cli_inner_pretty.js:365187): *"Emitted when a pre-send model consent gate swaps the session off the requested model (consent declined, dismissed, or given without the required entitlement ending up provisioned). Currently emitted by the Fable 5 usage-credit gate (`fable_overage_consent_prompt`). Session-scoped — the swap persists for the session, and additionally as the saved default when `persisted_as_default` is true."* So a "switch_default" or a declined consent doesn't just block the send — it changes the session's effective model (optionally persisting as the user's default).

**Step 3 — Credit-state error copy.** When credits are unavailable, the gate resolves to one of several model-specific messages (cli_inner_pretty.js:229585-229603), e.g.:
- *"Fable 5 uses usage credits and you're out · run /usage-credits to add funds, or /model to switch models"*
- *"Fable 5 uses usage credits and your monthly limit is reached · run /usage-credits to adjust it, or /model to switch models"* (admin variant: *"ask your admin to raise it"*)
- *"Fable 5 uses usage credits, which your organization has turned off · /model to switch models"*
- *"Fable 5 now uses usage credits · run /model to continue with Fable 5 or switch models"*

Compaction and the model-policy path carry the same guard (*"Compaction unavailable: your model policy only allows Fable 5, which requires usage credits · /model to set it up"*, cli_inner_pretty.js:461183; *"Your model policy only allows Fable 5, which requires usage credits…"*, cli_inner_pretty.js:457924). The `/extra-usage` command was renamed `/usage-credits` (cli_inner_pretty.js:376337, 376387) — a related surface the gate routes users to.

**Step 4 — Team/SDK propagation.** When a teammate's default is Fable 5 without consent, the team setup surfaces *"(Fable 5 needs usage-credits consent — /model to set up)"* (cli_inner_pretty.js:483706), and the SDK send path errors with `needs usage-credits consent — run /model first` (cli_inner_pretty.js:479606, 479698) rather than silently failing.

| **Before (2.1.156)** | No model used usage credits in this way; there was no pre-send model-consent gate and no `fable_overage_consent_prompt`. |

Declining/dismissing swaps the session off Fable 5 (optionally persisting). Out-of-credit, limit-reached, org-disabled, and not-available states each get tailored copy pointing at `/usage-credits` or `/model`. |
| **Why** | Fable 5 is a credit-metered tier — running it without explicit consent could spend a user's (or org's) credits unexpectedly. A *pre-send* gate (rather than a post-hoc bill) makes the cost decision an explicit, one-time-per-session choice, and the session-scoped swap guarantees that a user who declines never accidentally lands back on the metered model. Tailoring the copy to the precise credit state (out / capped / org-off / unavailable) turns a generic "payment required" into an actionable next step. |

**Key insight:** The gate is implemented as a *model swap*, not a request blocker. The enum `["consent", "switch_default", "cancelled"]` and the `@internal` doc make this explicit — the gate's job is to leave the session on a model the user has agreed to pay for, even if that means demoting from Fable 5 to a fallback for the rest of the session. This is what lets the rest of the agent loop stay model-agnostic: by the time a request is sent, the model has already been reconciled with consent.

**Confidence: high** for the dialog declaration, the result enum, the `@internal` swap semantics, and the credit-state copy (all read directly). **Medium** for the exact call-site that *invokes* `nge` per turn — it sits in the pre-send model-reconciliation path and the surrounding React/Ink dialog wiring doesn't carry a single distinctive grep string beyond the strings cited.

## 3. Transcript-save fix: inherited Claude Code env no longer disables session persistence (FIX)

**Type:** fix (regression in the 2.1.157→2.1.170 child-session work) · **Modules:** Session persistence, Transcripts, `--resume`, tmux

### TL;DR

A session launched from the **VS Code integrated terminal**, or from **any shell that inherited Claude Code's environment variables** (notably `CLAUDE_CODE_CHILD_SESSION=1`, which Claude Code exports into the shells/subprocesses it spawns), stopped saving its transcript and stopped appearing in `--resume`. The cause: a new "nested interactive Claude session" detector (`isNestedInteractiveClaudeSession`) treated the inherited env as evidence of a real parent session and turned **session persistence off**. The fix adds a **tmux ambient-marker probe** that distinguishes a *truly inherited* marker from a genuine parent process, plus a `CLAUDE_CODE_FORCE_SESSION_PERSISTENCE` escape hatch.

### How it works

**The persistence-skip gate.** `shouldSkipSessionPersistence` (`dV`, cli_inner_pretty.js:570534-570536) returns true (skip) when the test env disables it, or `CLAUDE_CODE_SKIP_PROMPT_HISTORY` is set, or — the bug — `isNestedInteractiveClaudeSession()` is true:

```javascript

// Location: cli_inner_pretty.js:570534-570536
// ============================================

// ORIGINAL (for source lookup):

  return (XRl() === "test" && !e) || y3() || st(process.env.CLAUDE_CODE_SKIP_PROMPT_HISTORY) || u1e();
}

// READABLE (for understanding):
function shouldSkipSessionPersistence() {
  let testForcePersist = parseBool(process.env.TEST_ENABLE_SESSION_PERSISTENCE);
  return (environment() === "test" && !testForcePersist)
      || isHeadless()
      || parseBool(process.env.CLAUDE_CODE_SKIP_PROMPT_HISTORY)
      || isNestedInteractiveClaudeSession();        // <-- the load-bearing term for this bug
}

// Mapping: dV→shouldSkipSessionPersistence, u1e→isNestedInteractiveClaudeSession, st→parseBool
```

**The detector — and the fix.** `isNestedInteractiveClaudeSession` (`u1e`, cli_inner_pretty.js:103473-103477):

`CLAUDE_CODE_CHILD_SESSION=1` is exported into every subprocess Claude Code spawns (cli_inner_pretty.js:291863, `Uot`). So a VS Code integrated terminal (which inherits the editor process's env) or any shell launched under Claude Code carries that marker — and a *fresh, top-level* `claude` started in that shell would have looked nested. The fix's ambient-marker probe asks tmux whether the marker lives at the **global** environment level (i.e. it was inherited/ambient rather than set by an actual parent `claude` in this pane); if so, `isAmbientChildMarker()` is true → `isNestedInteractiveClaudeSession()` returns false → persistence stays **on**. `CLAUDE_CODE_FORCE_SESSION_PERSISTENCE` is the unconditional override for users whose setup the probe can't disambiguate.

**Key insight:** The bug is a classic env-inheritance over-match: a marker meant to say "you were spawned by Claude Code" leaks transitively to *grandchild* processes that are themselves fresh top-level sessions. ## Summary

v2.1.170 is the **Claude Fable 5 launch**. The model machinery is wide but conventional: `claude-fable-5` (and the approved-org-only `claude-mythos-5`) register across all seven providers, gain a `"Fable 5"` label, a `fable`/`fable[1m]` shorthand, a `/model` picker entry that advertises its credits/plan status, an overload message, a launch toast (`tengu_fable5_launch_shown`), and a Mythos-class system identity block that tells Claude it's *"the first model in Anthropic's new Claude 5 family … a new Mythos-class model tier that sits above Claude Opus."* The genuinely novel subsystem is the **usage-credits consent gate** (`fable_overage_consent_prompt`): because Fable 5 is credit-metered, the first send routes through a `consent / switch_default / cancelled` dialog that, when declined, *swaps the session off Fable 5* — implemented as a session-scoped model change rather than a request blocker, with tailored copy for every credit state.

The lone fix carries real weight: a **session-persistence regression** that silently stopped transcripts from saving (and `--resume` from listing them) whenever a fresh `claude` was launched in a shell that had inherited `CLAUDE_CODE_CHILD_SESSION` — the VS Code integrated terminal being the headline case. The new `isNestedInteractiveClaudeSession` detector over-matched on the inherited marker; the fix adds a `tmux show-environment -g` ambient-marker probe to tell a *real* parent session from an inherited env var, plus a `CLAUDE_CODE_FORCE_SESSION_PERSISTENCE` override. Together: ship the new top-tier model, and harden the env-inheritance edge that the surrounding child-session plumbing had exposed.
