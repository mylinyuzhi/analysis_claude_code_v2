# v2.1.161 — Source Diff Analysis

**Theme:** **A telemetry-correctness + secret-hygiene release, wrapped around a parallel-tool-call isolation fix and a `claude agents` fan-out display upgrade.** Three sub-themes carry the weight. (1) **OpenTelemetry hardening:** custom `OTEL_RESOURCE_ATTRIBUTES` now ride onto *every metric datapoint* as labels (gated by the new `OTEL_METRICS_INCLUDE_RESOURCE_ATTRIBUTES`, default on) so you can slice usage by team/repo; and OTel *log* events (`user_prompt`/`api_request`/`tool_result`/`tool_decision`) emitted before the event-logger finishes initializing are now **buffered and replayed** instead of silently dropped. (2) **Secret hygiene:** `claude mcp` list/get/add stop printing secrets — `${VAR}` references are no longer expanded for display (`expandVars:!1`), credential headers are masked (`[REDACTED]`), and URL userinfo/query secrets are stripped — and managed-settings `forceLoginOrgUUID`/`forceLoginMethod` org pins stop blocking genuine third-party-provider sessions (Bedrock/Vertex/Foundry/Mantle), a regression from 2.1.146. (3) **Parallel-tool robustness:** a failed Bash command in a parallel batch no longer cancels its siblings — each tool returns its own result independently. On top sit the **`claude agents` `done/total` fan-out column** with a longest-running peek, the **`/mcp` "Show unused connectors" fold** that collapses never-signed-in claude.ai connectors, the **Linux fullscreen clipboard** rework (`wl-copy`/`xclip`/`xsel` + PRIMARY selection), the **Reduce-motion** fix for `/effort`/workflow animations/keyword shimmer, and two **focus-feature** background fixes (the workflow `isolation:"worktree"` bg-edit fix and the bg-subagent `claude -p` stdout-corruption fix) that link to their module docs.

> Every citation is `cli_inner_pretty.js:<line>` in the **2.1.183** bundle (`VERSION:"2.1.183"`, cli_inner_pretty.js:848) unless tagged **(v2.1.156 before)**, which refers to `/lyz/codespace/claude-code-bomb/versions/2.1.156/extract/cli_inner_pretty.js`. ## 1. `OTEL_RESOURCE_ATTRIBUTES` become metric-datapoint labels (NEW)

**Type:** feature · **Modules:** Telemetry (OpenTelemetry metrics)

### TL;DR

The attributes you set in `OTEL_RESOURCE_ATTRIBUTES` (e.g. `team=payments,repo=monorepo`) are now copied onto *every metric datapoint* as labels, so usage metrics can be sliced by your own custom dimensions. Before, those attributes only described the OTel *resource* (the exporter-level identity) and never reached the per-datapoint label set. A new toggle `OTEL_METRICS_INCLUDE_RESOURCE_ATTRIBUTES` (default **on**) gates it.

### How it works

Claude Code builds a shared "common attributes" object once per process — `buildMetricCommonAttributes` (`VFe`, cli_inner_pretty.js:193808-193853) — and stamps it onto each metric datapoint. v2.1.183 prepends a new loop at the top of that builder: when `OTEL_METRICS_INCLUDE_RESOURCE_ATTRIBUTES` is enabled (`mDt(...)`, cli_inner_pretty.js:193816), it parses `OTEL_RESOURCE_ATTRIBUTES` via `parseResourceAttributes` (`ngd`, cli_inner_pretty.js:193893-193910) and merges each `key=value` into the attribute object `o` (193817-193821). The parser is a percent-decoding, RFC-baggage-style `key=value,key=value` splitter with a validator `isValidBaggageChar` (`RLi`, cli_inner_pretty.js:193805-193812) and a length cap (`$Li`), matching the OTel spec for `OTEL_RESOURCE_ATTRIBUTES`.

One guard matters: when the session has an authenticated identity (`r = Object.keys(VHn()).length > 0`), any custom key starting with `user.` or `identity.` is **skipped** (193818: `if (r && (i.startsWith("user.") || i.startsWith("identity."))) continue;`) so a user can't spoof the trusted `user.id`/`user.email`/`organization.id` labels that Claude Code sets itself further down (193822, 193842-193844).

## 2. OTel log events emitted before telemetry init are buffered, not dropped (FIX)

**Type:** fix · **Modules:** Telemetry (OpenTelemetry logs/events)

### TL;DR

OTel *log* events (`user_prompt`, `api_request`, `tool_result`, `tool_decision`, and friends) fired during the window between process start and the event-logger finishing async initialization were **silently dropped** with a one-line warning. They are now **queued in a pending buffer (cap 100) and replayed** the moment the logger is installed.

### How it works

The event emitter `emitTelemetryEvent` (`Mu`, cli_inner_pretty.js:193918-193935) builds the event record, then: if the logger exists (`rnr()`, cli_inner_pretty.js:3109-3111) it emits immediately; otherwise it calls `bufferPendingEvent` (`onr`, cli_inner_pretty.js:3117-3120), which pushes the event onto `Ot.pendingOTelEvents` (capacity `MAc = 100`, cli_inner_pretty.js:3746) and returns true. Only when *that* also fails (buffer full, or already drained to `null`) does it warn-and-drop once (193933-193934, guarded by the `OLi` latch). When the event logger is later installed, `setEventLogger` (`$Kt`, cli_inner_pretty.js:3113-3116) drains the buffer into it: `for (let n of t) e.emit(n)`.

```javascript
// ============================================

// ============================================

// ORIGINAL (for source lookup):
```

|---|---|
| **Before (v2.1.156)** | The emitter (`j1`, v2.1.156:222547-222552) had **no buffer**: `if (!q) { if (!tz7) (tz7 = !0, warn("Event dropped (no event logger initialized)")); return; }`. The most interesting early events — the *first* `user_prompt` and its `api_request` — fire during exactly that window, so the old behavior reliably lost the start-of-session record. A bounded buffer (100) replays them without risking unbounded memory if the logger never initializes. |

## 3. Parallel tool calls: a failed Bash no longer cancels its siblings (FIX)

**Type:** fix · **Modules:** Tool execution (concurrent batch runner), Bash tool

### TL;DR

When the model issues several tool calls in one turn and they run concurrently, a Bash command that fails (non-zero exit or thrown error) no longer aborts the *other* tool calls in the same batch. Each tool now resolves into its own `tool_result` (success or `is_error`) independently.

### How it works

The concurrency machinery itself is **unchanged** from v2.1.156 and is not the fix. The tool batch is partitioned into runs of concurrency-safe vs unsafe tools by `partitionByConcurrencySafety` (`V$p`, cli_inner_pretty.js:438061-438078); the safe runs are fanned out by `runToolsConcurrently` (`K$p`, cli_inner_pretty.js:438099-438113) through the merge primitive `mergeAsyncGenerators` (`iUn`, cli_inner_pretty.js:385483-385503). Both `iUn` and the grouped runner `jfo` (cli_inner_pretty.js:438028) are byte-for-byte identical between the two builds.

The isolation lives in the **per-tool generator** `runSingleTool` (`U3t`, cli_inner_pretty.js:436975) — specifically its trailing `catch (X)` (cli_inner_pretty.js:437845). That catch distinguishes an **abort** (`isAbortError(X)` = `F3t`, cli_inner_pretty.js:436859; or `isSignalAborted(signal)` = `zCe`, cli_inner_pretty.js:227026) from a **genuine tool error**. On a genuine error it does **not** touch the shared `r.abortController` — it emits a `tool_result` with `is_error:!0` and *returns normally* (cli_inner_pretty.js:437918: `content: [{ type: "tool_result", content: ce, is_error: !0, tool_use_id: t }]`). Because the generator returns a value rather than throwing, `Promise.race(o)` inside `iUn` resolves cleanly and the *sibling* generators keep running. The Bash tool's non-zero exit flows through this same path: it surfaces as that Bash call's own `is_error` result, never as a thrown rejection that would propagate out of `iUn` and starve the batch.

| | |
|---|---|
| **Before** | A failed Bash command in a parallel batch could surface as a thrown error / shared abort, taking its sibling tool calls down with it — the user lost the results of unrelated, already-running tools. |
| **After** | Each tool's error is caught inside `runSingleTool` and converted to that tool's own `is_error` result; the shared abort controller is only tripped on a *real* cancellation (Esc / interrupt), so siblings complete independently. |
| **Why** | Parallel tool calls exist to overlap independent work. One command's failure being independent of the others is the whole contract; letting a Bash non-zero exit cascade into sibling cancellation broke the "each tool returns its own result" guarantee. The fix keeps the (unchanged) concurrency engine and tightens error/abort classification at the per-tool boundary. |

**Confidence:** medium. The merge primitive and grouped runner are *verified identical* 156↔183, so the change is necessarily inside the per-tool generator's error/abort handling; the `catch (X)` at cli_inner_pretty.js:437845 with its `F3t`/`zCe` abort-vs-error split and `is_error` tool_result emission (cli_inner_pretty.js:437918) is the mechanism. The exact 2.1.160→2.1.161 line delta within that ~900-line generator can't be diffed from a single build, so the precise patch site is attributed by structure (abort-classification + non-throwing error path), not a captured before/after.

## 4b. `/mcp` collapses never-signed-in claude.ai connectors behind "Show unused connectors" (NEW)

**Type:** UX · **Modules:** MCP UI (`/mcp` connector list)

### TL;DR

In the interactive `/mcp` panel, claude.ai connectors you've never signed in to are now hidden under a collapsed **"Show unused connectors (N)"** row instead of cluttering the main list. Expanding the row reveals them; everything else (connectors you've used / authed) stays visible at the top.

### How it works

The `/mcp` list component partitions claude.ai proxy servers into *used* vs *unused* in a `useMemo` (cli_inner_pretty.js:500702-500716). A `claudeai-proxy` server is "unused" when its client is in a `needs-auth`/`failed` state **and** its name is not in the previously-signed-in set returned by `Lxn()`; those go into `unusedClaudeAiServers` (`q`), the rest into `claudeAiServers` (`W`), each sorted by name. When building the row list, the unused bucket is gated behind a `unused-connectors-fold` row: `F.push({ type: "unused-connectors-fold" })`, and the actual unused-server rows are only pushed *if the fold is expanded* (`if ((F.push({ type: "unused-connectors-fold" }), a)) for (let W of g) F.push({ type: "server", server: W })`, cli_inner_pretty.js:500726). Selecting the fold row toggles it open (cli_inner_pretty.js:500740: `else if (F.type === "unused-connectors-fold") l()`). The fold row renders as `"Show unused connectors"` with a dimmed `(N)` count of `g.length` (cli_inner_pretty.js:500796).

| | |
|---|---|
| **Before** | Every claude.ai connector — including ones you'd never authenticated — was listed inline in `/mcp`, so the panel was crowded with connectors you weren't using. |
| **After** | Never-signed-in connectors (`needs-auth`/`failed` and absent from the signed-in set) collapse under a single `Show unused connectors (N)` fold that expands on selection. |
| **Why** | A user typically signs into a handful of connectors but the catalog of available claude.ai connectors is large; surfacing all of them every time buries the relevant ones. Folding the never-used set keeps the default view focused on what you actually use while leaving discovery one keystroke away. The "unused" predicate keys off *auth state* (`needs-auth`/`failed`) plus a persisted signed-in set, so a connector you've authed once stays in the main list even if a later refresh transiently fails. |

## 5. `claude mcp` list/get/add stop printing secrets (FIX — security)

**Type:** fix (security) · **Modules:** MCP CLI commands, Secret redaction

### TL;DR

`claude mcp list`, `claude mcp get`, and `claude mcp add` no longer leak secrets to the terminal: (a) `${VAR}` references in MCP config are **no longer expanded** for display (so the literal `${API_KEY}` is shown, not its value), (b) credential **headers** are redacted to `[REDACTED]`, and (c) **URL secrets** (userinfo and query string) are stripped.

### How it works

Three mechanisms, all in the MCP CLI path:

**(a) `${VAR}` not expanded.** The MCP config loader `loadMcpServers` (`hH`, cli_inner_pretty.js:272189: `function hH(e, { expandVars: t = !0 } = {})`) takes an `expandVars` flag that, when true, substitutes `${VAR}` env references with their resolved values. The `claude mcp` display path now loads each scope with `expandVars:!1` — see `loadServersUnexpandedByScope` (`MUl`, cli_inner_pretty.js:599234-599243: `hH(o.scope, { expandVars: !1 }).servers`), consumed by the `tengu_mcp_list` display (`tTf`, cli_inner_pretty.js:599285+). In v2.1.156 the loader (`hP$`/`yP$`) was called **only** with `expandVars: !0` everywhere (v2.1.156:275406-275432) — the CLI display resolved `${VAR}` to its secret.

**(b) Header redaction.** `redactHeaders` (`Kor`, cli_inner_pretty.js:10300-10304) maps every header whose *name* matches the secret regex `SECRET_KEY_RE` (`f3o`, cli_inner_pretty.js: `api[_-]?key|secret|token|password|...|authorization|cookie|...|client[_-]?secret`) to `"[REDACTED]"`. The `mcp add` print now writes `Headers: ${Re(Kor(p), null, 2)}` (cli_inner_pretty.js:597556, 597580).

**(c) URL secret stripping.** `redactUrlSecrets` (`Qde`, cli_inner_pretty.js:10305-10316) parses the URL and clears `username`, `password`, `search` (query), and `hash` before printing. The `mcp add` print uses `with URL: ${Qde(s)}` (cli_inner_pretty.js:597552, 597576).

```javascript

// Location: cli_inner_pretty.js:10300-10316
// ============================================

function Qde(e) {
  if (!e) return e;
  try { let t = new URL(e); if (!t.host) throw TypeError("opaque");
    return ((t.username = ""), (t.password = ""), (t.search = ""), (t.hash = ""), t.toString().replace(/\/$/, "")); }
  catch { let t = Di(Di(e, "?"), "#"), n = t.lastIndexOf("@"); return n >= 0 ? t.slice(n + 1) : t; }
}

// READABLE (for understanding):
function redactHeaders(headers) {
  let out = {};
  for (let [name, value] of Object.entries(headers)) out[name] = SECRET_KEY_RE.test(name) ? "[REDACTED]" : value;
  return out;
}
function redactUrlSecrets(url) {
  if (!url) return url;
  try {
    let u = new URL(url);
    if (!u.host) throw TypeError("opaque");
    u.username = ""; u.password = ""; u.search = ""; u.hash = "";   // strip userinfo + query + fragment
    return u.toString().replace(/\/$/, "");
  } catch {                                                          // not a parseable URL: strip ?…/#… and user@
    let bare = stripAfter(stripAfter(url, "?"), "#"), at = bare.lastIndexOf("@");
    return at >= 0 ? bare.slice(at + 1) : bare;
  }
}

```

| | |
|---|---|
| **Before (v2.1.156)** | `mcp add` printed `with URL: ${z}` (raw URL `z`) and `Headers: ${IH(w, null, 2)}` (raw headers `w`) — no redaction (v2.1.156:562657-562685). The list/get display loaded config with `expandVars:!0`, so `${API_KEY}` printed as the resolved secret. |

| **Why** | `claude mcp list/get/add` output routinely ends up in terminal scrollback, screenshots, bug reports, and CI logs. Expanding `${VAR}` or echoing a `Authorization: Bearer …` header or a `https://user:pass@host/?token=…` URL leaks long-lived credentials into all of those. Redacting at the *print* boundary (rather than not storing the values) keeps the config functional while making the display safe to paste. |

## 6. Org-pin (`forceLoginOrgUUID`/`forceLoginMethod`) no longer blocks third-party-provider sessions (FIX)

**Type:** fix (regression from 2.1.146) · **Modules:** Auth, Managed settings (org pin), Providers (Bedrock/Vertex/Foundry/Mantle)

### How it works

The managed-settings org-pin validator `validateForceLoginOrg` (`Cse`, cli_inner_pretty.js:136225) decides whether the current auth satisfies a `forceLoginOrgUUID`/`forceLoginMethod` policy. v2.1.183 makes two changes vs the v2.1.156 validator (`L9H`, v2.1.156:131921):

1. **Host-managed providers short-circuit.** A new early return: `if (Ge.CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST) { ...telemetry...; return { valid: !0 }; }` (cli_inner_pretty.js:136229-136232). A session whose provider is managed by the host harness passes the pin.
2. **The non-first-party branch is gated by an Anthropic-credential check.** The old code returned `valid:false` for *any* non-OAuth method whenever a pin was set. The new code returns invalid only when `n && hasAnthropicIssuedCredential()` (`vVu`, cli_inner_pretty.js:136218-136224): `if (n && vVu()) return { valid:!1, ... }` (cli_inner_pretty.js:136242). `vVu` is true only when there's an Anthropic-issued credential (`ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_API_KEY_FILE_DESCRIPTOR`, an apiKeyHelper key, or `provider === "firstParty"` without a subscription). A pure third-party-provider session (Bedrock/Vertex/Foundry/Mantle) — which carries *none* of those — now passes `valid:true`. The error copy also narrowed: from "a non-OAuth authentication method is active (third-party provider, API key, ...)" to "an Anthropic-issued credential (ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN, or apiKeyHelper) ... cannot satisfy the org pin" (cli_inner_pretty.js:136243-136254).

| | |
|---|---|
| **Before (v2.1.156)** | `L9H`'s `if (!Gj())` branch returned `{ valid:!1 }` whenever the org pin was set (v2.1.156:131936-131951) — **unconditionally** for third-party providers. There was no `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST` early return in this validator and no `vVu` gate. A Bedrock/Vertex/Foundry/Mantle user on a machine with an org pin was hard-blocked. |
| **After** | Host-managed-provider sessions short-circuit to `valid:true`; the not-first-party branch only fails when an Anthropic-issued credential (which *could* satisfy the pin via OAuth but isn't OAuth) is present. Pure third-party sessions pass. |
| **Why** | `forceLoginOrgUUID` targets *first-party Anthropic OAuth* — it pins which Anthropic org may log in. A third-party provider session has no Anthropic OAuth identity to pin, so the pin is simply not applicable; blocking it was a 2.1.146 over-application. Distinguishing "an Anthropic credential is present but isn't OAuth" (genuinely can't satisfy the pin) from "no Anthropic credential at all, just a 3P provider" (pin not applicable) is the crux. |

**Confidence:** high — the early return at 136229, the `vVu` gate at 136242, and the narrowed message at 136243 are verbatim, and the v2.1.156 `L9H` unconditional `if (q) return {valid:!1}` at 131937 is the looser predecessor.

## 7. Linux fullscreen clipboard: `wl-copy`/`xclip`/`xsel` + PRIMARY selection (NEW)

**Type:** feature · **Modules:** Clipboard (Linux), Fullscreen mode

### TL;DR

In fullscreen mode on Linux, copy now uses a native clipboard tool when available — `wl-copy` (Wayland), else `xclip` or `xsel` (X11) — and writes to **both** the clipboard and the **PRIMARY** selection so middle-click paste works. The "hold {key} for native selection" hint also now names the correct key per terminal.

### How it works

The native-clipboard write helper detects the tool at startup: prefer `wl-copy` when `WAYLAND_DISPLAY` is set (cli_inner_pretty.js:155078-155079), else `xclip` (155083-155084), else `xsel` (155087-155088). The write path (cli_inner_pretty.js:155132-155134) fires the chosen tool **twice** — once for the clipboard, once for PRIMARY:

```javascript
// Location: cli_inner_pretty.js:155132-155134
else if (pZ === "wl-copy") (Fn("wl-copy", [], t), Fn("wl-copy", ["--primary"], t));
else if (pZ === "xclip")   (Fn("xclip", ["-selection", "clipboard"], t), Fn("xclip", ["-selection", "primary"], t));
else if (pZ === "xsel")    (Fn("xsel", ["--clipboard", "--input"], t), Fn("xsel", ["--primary", "--input"], t));
```

The unified writer also still emits an OSC 52 escape as a fallback for terminals without a native tool (consistent with the WSL/OSC-52 handling described in [`./2.1.160.md`](./2.1.160.md) §11). The read side mirrors the tool choice (`wl-paste`/`xclip -o`/`xsel --output`, cli_inner_pretty.js:155174-155176).

| | |
|---|---|
| **Before** | Fullscreen Linux copy relied on OSC 52 alone, which many terminals don't honor, and didn't populate the PRIMARY selection, so middle-click paste got nothing. The native-selection hint could show the wrong key. |
| **After** | Native `wl-copy`/`xclip`/`xsel` write both the clipboard and PRIMARY; OSC 52 remains a fallback; the hint shows the per-terminal key. |
| **Why** | On Linux the *clipboard* and the *PRIMARY selection* are two distinct buffers — PRIMARY is what middle-click pastes — so a copy that wants to be usable everywhere must populate both. Shelling to the standard CLI tools (which talk directly to the compositor / X server) is far more reliable than OSC 52, which depends on terminal-emulator support. |

## 8. `/effort` dialog, workflow animations, and keyword shimmer honor "Reduce motion" (FIX)

**Type:** fix · **Modules:** TUI animations, Accessibility (Reduce motion), `/effort`, Workflow

The `/effort` selection dialog, the workflow phase animations, and the prompt-keyword shimmer (the violet "ultracode"-keyword highlight, see [../42_workflow/ultracode_keyword_trigger_delta.md](../42_workflow/ultracode_keyword_trigger_delta.md)) now suppress their animation when the user has "Reduce motion" enabled. These are React/Ink animation components that previously animated unconditionally; the fix gates each on the reduce-motion setting (the same accessibility flag the rest of the TUI already consulted). This is a per-component animation-gating change with no single isolable declaration — each affected component reads the reduce-motion preference and renders a static frame instead of a tween. **(Not isolated to a single decl — three independent animation sites gated on one existing setting.)**

**Why:** "Reduce motion" is an OS-level accessibility request (vestibular sensitivity, focus). Animations that ignore it defeat the setting; the shimmer in particular is a continuous effect that's exactly what reduce-motion users want stilled.

## 9. Focus-feature fixes (Workflow + Background) — LINK

**Type:** fix · **Modules:** Workflow (worktree isolation), Background agents

Two 2.1.161 fixes land in deeply-documented focus subsystems; per the focus-feature rule they're summarized with the verified anchor and a module link, not re-derived:

- **Workflow `isolation:"worktree"` agents in background sessions could not edit files in their own worktree.** A workflow `agent({ isolation:"worktree" })` running inside a background session was blocked from editing files in *its own* worktree — the write-isolation guard fell through to the *session-level* worktree branch because the spawned subagent's `agentWorktree` was never populated. The fix threads `worktreePath: Ce` into the subagent query (cli_inner_pretty.js:417253), so the agent's tool-use context carries `agentWorktree` and the **agent-level** branch of the write guard `Xct` (cli_inner_pretty.js:389676) fires using the *agent's* worktree. Full data-path analysis in **[../42_workflow/runtime_fixes_delta.md](../42_workflow/runtime_fixes_delta.md)** §R2 (the worktree edit fix), which isolates this as exactly one added query field.

- **Background subagent output corrupting `claude -p` stdout under `--output-format text`/`json`.** A background subagent's stdout was bleeding into the parent `claude -p` (headless print) stdout stream when the parent used `--output-format text` or `json`, corrupting the structured/plain output the caller parses. The fix keeps the subagent's output off the parent's stdout channel. This is part of the background-agents worker/stream isolation work; the worker env/stream isolation is covered in **[../36_background_agents/worker_env_isolation_2181.md](../36_background_agents/worker_env_isolation_2181.md)** and the daemon/worker model in **[../36_background_agents/README.md](../36_background_agents/README.md)**. *(The specific `--output-format` stdout-routing guard is a stream-wiring fix in the headless print path and is not isolated to a single distinctive decl in this build.)*

## Summary

v2.1.161 is a **telemetry-correctness + secret-hygiene** release with two pointed robustness fixes. On the OpenTelemetry side, custom `OTEL_RESOURCE_ATTRIBUTES` now ride onto every metric datapoint as labels (new default-on `OTEL_METRICS_INCLUDE_RESOURCE_ATTRIBUTES`, `buildMetricCommonAttributes`/`VFe` at cli_inner_pretty.js:193808), with a `user.`/`identity.` anti-spoof carve-out; and log events fired before the async event-logger initializes are now buffered (cap 100) and replayed on init (`setEventLogger`/`$Kt` at cli_inner_pretty.js:3113) instead of being silently dropped — recovering the start-of-session `user_prompt`/`api_request` that the 2.1.156 emitter discarded.

The secret-hygiene work hardens two surfaces: `claude mcp` list/get/add stop printing secrets — `${VAR}` references are shown literally (`expandVars:!1`, `MUl` at 599234), credential headers are `[REDACTED]` (`Kor`), and URL userinfo/query secrets are stripped (`Qde`) — and the managed-settings org pin stops hard-blocking genuine third-party-provider sessions, gating the not-first-party rejection behind an actual Anthropic-credential check (`vVu` at 136218) plus a host-managed-provider short-circuit, fixing a 2.1.146 regression.

The robustness fixes — a failed Bash no longer cancelling its parallel siblings (per-tool error isolation in `runSingleTool`/`U3t`, over a *byte-identical* concurrency engine) and the Linux fullscreen clipboard rework (`wl-copy`/`xclip`/`xsel` + PRIMARY) — plus the `claude agents` `done/total` fan-out display, the Reduce-motion fix, and the two focus-feature background/workflow fixes (worktree bg-edit, `claude -p` stdout corruption) round out a release that is light on new surfaces but heavy on "make the existing surfaces correct and safe."
