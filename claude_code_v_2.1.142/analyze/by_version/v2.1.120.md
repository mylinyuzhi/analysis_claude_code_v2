# v2.1.120 — Source Diff Analysis

**Theme:** Windows native shell using **PowerShell** (no longer requires Git Bash), **`claude ultrareview`** subcommand for non-interactive runs, `${CLAUDE_EFFORT}` skill placeholder, `AI_AGENT` env for subprocess identification, faster startup with claude.ai connectors, plus a `find`-driven fd-exhaustion fix.

## 1. Windows: PowerShell as shell tool when Git Bash absent

**Type:** Behavior · **Modules:** Windows, Bash tool, Shell

### v2.1.88 baseline

On Windows, Git for Windows (Git Bash) was required — Claude Code refused to start without it. Native Windows users without Git installed couldn't run Claude Code.

### v2.1.120 state

```javascript
// ============================================
// shellSelection - PowerShell fallback when Git Bash missing
// Location: cli_inner_pretty.js:42821, 535349-535355
// ============================================

else N("Git Bash not found; BashTool will be unavailable");

// Schema (chunks 48738):
"Path placeholders like ${CLAUDE_PLUGIN_ROOT} are substituted per-element as plain strings, so paths with quotes, $, or backticks never reach a shell parser. When absent, `command` runs through a shell (bash on POSIX, PowerShell on Windows without Git Bash)."

// Skill frontmatter error:
`Skill ${q} requires bash (\`shell: bash\` in frontmatter) but Git Bash was not found. Install Git for Windows (https://git-scm.com/downloads/win), or change the skill's frontmatter to \`shell: powershell\`.`

// Hook config error:
`Hook "${H.command}" requires bash but Git Bash was not found. Install Git for Windows, or add "shell": "powershell" to this hook's config.`

// Final fallback when both missing:
"Claude Code on Windows requires either Git for Windows (for bash) or PowerShell. Install one of: ..."
```

### Why this approach

**Lower barrier to entry.** Native Windows users (no Git Bash, no WSL) can now `npm i -g @anthropic-ai/claude-code` and start using it. PowerShell is on every Windows install.

**Why still allow Git Bash:** Skills/hooks that *require* bash (e.g. shell script with `#!/bin/bash`) need it. PowerShell can't perfectly emulate bash semantics.

**Why the per-skill / per-hook clear error:** When something requires bash and bash isn't available, the user needs to know *which thing requires it* and what their two options are. The error directs them.

**Trade-off:** Users on PowerShell-only Windows get a slightly different command syntax for tools. The PowerShell tool description (chunks 405187) explicitly addresses this with a "translation guide" for common bash patterns.

## 2. `claude ultrareview [target]` subcommand

**Type:** feature · **Modules:** /ultrareview, CLI

### v2.1.88 baseline

`/ultrareview` was only available as an interactive slash command. Running it from CI required a wrapper script that spawned `claude` interactively and parsed output.

### v2.1.120 change

`claude ultrareview [target]` runs the review non-interactively. Prints findings to stdout (or raw JSON with `--json`) and exits 0 on completion or 1 on failure.

### Why this approach

**CI/automation integration.** Teams want PR-bot-style reviews. `claude ultrareview --json` slot into existing pipelines (GitHub Actions, GitLab CI, etc.) with a single command.

**Why exit 0 on completion, exit 1 on failure:** Standard CI semantics. The exit code conveys "did we successfully review" not "did the review find problems." Findings are in the output.

**Why `--json` opt-in:** Default output is human-readable. JSON is for scripted consumers.

## 3. Skills can reference `${CLAUDE_EFFORT}` in content

**Type:** feature · **Modules:** Skills, Effort

### v2.1.88 baseline

Skills had access to many environment variables in their hook commands but not in their content (the prompt body). They couldn't adapt their prompt based on the current effort level.

### v2.1.120 state

```javascript
// ============================================
// claudeEffortPlaceholder - substituted in skill content
// Location: cli_inner_pretty.js:237710, 399003, 406269, 419635, 520868
// ============================================

// Schema description:
'Active effort level for the current turn (e.g., "low", "medium", "high", "xhigh", "max"), after any silent downgrade for the selected model. Also exposed to hook commands and Bash as the CLAUDE_EFFORT env var.'

// Substitution in skill content:
g = g.replaceAll("${CLAUDE_EFFORT}", aT(E ?? F.options.mainLoopModel, h ?? F.getEffortValue()))

// In Bash environment:
{ CLAUDE_EFFORT: aT($.options.mainLoopModel, $.getEffortValue()) }

// In env-files:
if (typeof YH === "string") R.CLAUDE_EFFORT = YH;

// Mapping: aT→resolveEffort
```

A skill author can now write content like "If `${CLAUDE_EFFORT}` is `max`, use deeper investigation" and have it expanded at invocation time.

### Why this approach

**Skill behavior should adapt to compute budget.** A skill that does deep analysis at `max` effort would burn tokens at `low` — the skill author can choose to behave differently.

**Why a placeholder (not a runtime arg):** Skill content is templated, not called with arguments. The placeholder pattern matches `${CLAUDE_PLUGIN_ROOT}` and other existing substitutions.

**Why also in hook command env and Bash env:** Same value, three consumers (skill prompt, hook command, Bash tool). Single source of truth via the placeholder/env var pair.

## 4. `AI_AGENT` environment variable for subprocesses

**Type:** Observability · **Modules:** Subprocess env

### v2.1.88 baseline

When Claude Code launched subprocesses (e.g. `gh`), the subprocess had no clear way to know it was being invoked by an AI. `gh` couldn't attribute the traffic correctly.

### v2.1.120 state

```javascript
// Location: cli_inner_pretty.js:131, 361227
!process.env.AI_AGENT ||
process.env.AI_AGENT.startsWith("claude-code_") ||
process.env.AI_AGENT.startsWith("claude-code/")

// Set in subprocess env:
process.env.AI_AGENT = CT8("harness");
AI_AGENT: CT8("agent"),

// Mapping: CT8→formatAgentIdentifier
```

The `AI_AGENT` env var follows the de facto convention (e.g. `claude-code/2.1.120`). Tools like `gh` can detect it and attribute traffic.

### Why this approach

**Standard convention.** Tools across the industry are converging on `AI_AGENT` for identification. Following the convention lets the ecosystem benefit without per-tool special-casing.

**Why the format check:** If a user (or another wrapper) already set `AI_AGENT`, Claude Code respects it. The check only updates when the value isn't already a claude-code identifier.

## 5. Fewer spinner tips when relevant feature already present

**Type:** UX · **Modules:** Spinner

Spinner tips that recommend installing the desktop app or creating skills/agents are now suppressed when the user already has them. Reduces tip-fatigue.

The shape: "Try creating a skill!" is helpful for new users, annoying for users with 20 skills. Detection + suppression matches what users want.

## 7. Faster startup with many claude.ai connectors (not yet authorized)

**Type:** Performance · **Modules:** MCP, claude.ai connectors

When many claude.ai connectors are configured but not yet authorized, startup was paying serial OAuth-check round-trips. Now skipped/deferred for unauthorized connectors — they appear in `/mcp` but aren't connected at startup.

## 20. `find` exhausting fds on large directory trees

**Type:** fix · **Modules:** Bash tool, find

```javascript
// Location: cli_inner_pretty.js:98574-98725 (EMFILE handling)
if (g && (g.code === "EMFILE" || g.code === "ENFILE")) RxH([B, [u, S, x], g, F || Date.now(), Date.now()]);
```

`find` in the Bash tool was exhausting open file descriptors on large directory trees, sometimes triggering host-wide crashes on macOS/Linux native builds. Now caps concurrent fd usage and queues over the cap with `EMFILE` / `ENFILE` retry-on-pressure.

### Why this matters

**This was a system-wide crash on tight machines.** A `find /` invocation could starve the rest of the OS's fd budget — affecting other processes, not just Claude. The fix is a critical correctness gate.

## Summary

v2.1.120 is the **"Windows-and-CI parity"** release:

- **Windows-native shell** — PowerShell replaces Git Bash as the required shell, opening Claude Code to non-Git-using Windows users.
- **`claude ultrareview` subcommand** — extends the review feature into CI workflows.
- **`${CLAUDE_EFFORT}`** — skills can now adapt their prompts to the user's compute budget.
- **`AI_AGENT`** — standard convention for AI-agent identification reaches downstream tools (`gh` etc.).

The fix tail focuses on rendering/scrolling artifacts (§13, §16, §17), regressions (§11), and one critical system-wide fix (§20 fd-exhaustion).

The pattern: **expand the surface area of who can use Claude Code and where they can use it** — Windows without Git, CI without interactive, skills with effort awareness, subprocess attribution. Each removes a friction point that previously gated adoption.
