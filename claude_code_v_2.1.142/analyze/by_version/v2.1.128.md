# v2.1.128 — Source Diff Analysis

**Theme:** Big "polish & robustness" release. `/mcp` reconnection summaries, `EnterWorktree` HEAD source, parallel-shell-tool isolation, sub-agent cache, `--channels` for console auth, and roughly two dozen UI/UX fixes touching every visible surface (slash dialogs, fenced code clipboard, OSC 8 fallback, vim space, autocompact for 1M models).

## 1. `/color` random when called bare

**Type:** UX · **Modules:** Slash commands

`/color` (no args) used to show usage. Now it picks a random session color from the supported palette. Pairs with `/rename` (per the spinner tip at `cli_inner_pretty.js:573669`) for users juggling multiple parallel sessions and wanting visual disambiguation.

## 2. `/mcp` shows tool counts; flags 0-tool connected servers

**Type:** UX · **Modules:** MCP, `/mcp`

The `/mcp` panel now displays the tool count next to each connected server. A server that connected successfully but returned 0 tools is flagged separately — distinguishing "configured but unhealthy" from "connected and ready."

### Why this approach

Operators of internal MCP servers were filing bug reports of the form "the server says connected but Claude can't see any tools." The pre-fix display didn't distinguish the two cases. The new counts make the silent-failure mode visible at a glance.

**Type:** feature · **Modules:** Plugins

`--plugin-dir` was directory-only. Now also accepts `.zip` files; the archive is extracted on load. Distribution mechanism for plugins that don't have an npm package or marketplace listing.

## 4. `--channels` works with console (API key) auth

**Type:** feature · **Modules:** Channels, Auth

Previously: `--channels` (which enables MCP servers with the `claude/channel` capability — inbound push messages) was claude.ai-subscription-only. Now also works with console API-key auth, gated by org-managed `channelsEnabled: true`.

```javascript
// ============================================
// channelsEligibility - per-org / per-account opt-in
// Location: cli_inner_pretty.js:50839-50851, 394916-394938
// ============================================

// ORIGINAL (for source lookup):
return ($ === "team" || $ === "enterprise") && H?.channelsEnabled !== !0;
// ...
return H !== null && H.channelsEnabled !== !0;

// READABLE (for understanding):
function isChannelsBlockedByOrgPolicy(managedSettings, orgTier) {
  // Teams/Enterprise: default off. Admin sets channelsEnabled: true to enable.
  if (orgTier === "team" || orgTier === "enterprise") {
    return managedSettings?.channelsEnabled !== true;
  }
  // Console: default on UNLESS managed settings explicitly set channelsEnabled: false.
  if (managedSettings !== null) {
    return managedSettings.channelsEnabled !== true;
  }
  return false;
}

// Mapping: H→managedSettings, $→orgTier
```

### Why this approach

Channels = **inbound** capability: MCP servers can push notifications/messages into a CC session. Default-on for individual console users (low risk for solo use) but **default-off for managed orgs** because security teams must opt in to inbound flows.

## 6. Subprocess `OTEL_*` env scrubbing

**Type:** infra · **Modules:** Subprocesses, OTEL

### Bug

CC sets `OTEL_*` env vars for its own OpenTelemetry export. Subprocesses (Bash tool, hooks, MCP stdio, LSP) **inherited** those vars. If the subprocess was itself OTEL-instrumented (e.g. a TypeScript dev server with OpenTelemetry SDK), it would re-use CC's OTLP endpoint — sending its own spans into CC's observability stack.

### Fix

```javascript
// Stripped from subprocess env before spawn:
const SCRUBBED_OTEL_KEYS = [
  "OTEL_EXPORTER_OTLP_ENDPOINT",
  "OTEL_EXPORTER_OTLP_HEADERS",
  "OTEL_SERVICE_NAME",
  "OTEL_RESOURCE_ATTRIBUTES",
  "OTEL_TRACES_EXPORTER",
  "OTEL_METRICS_EXPORTER",
  "OTEL_LOGS_EXPORTER",
  // ...all OTEL_* prefix vars
];
```

Subprocesses get a clean env w.r.t. observability; they can configure their own if needed.

### Why this approach

The principle: **child processes shouldn't inherit the host's observability configuration**. CC is a *user* of OTEL; the user's Bash command is *not transitively* a child of CC's tracer. Inheritance was a category error.

(Note: TRACEPARENT/TRACESTATE intentionally *are* inheritable for trace linking — those carry per-request context, not endpoint config.)

## 10. `EnterWorktree` creates from local HEAD

**Type:** behavior · **Modules:** Worktree tool

Previously created the new branch from `origin/<default-branch>` — which **dropped unpushed commits**. Now creates from local HEAD by default, matching the documentation. Config:

Schema description at `cli_inner_pretty.js:50517`:

> "Which ref new worktrees branch from. 'fresh' (default) branches from `origin/<default-branch>` for a clean tree. 'head' branches from your current local HEAD so unpushed commits and feature-branch state are present. Applies to `--worktree`, `EnterWorktree`, and agent isolation."

The default mode remains `fresh`. The fix here is that **the `head` mode actually works** — the prior buggy implementation used `origin/<default-branch>` even when `head` was selected.

### Why this approach

Worktree isolation should be **predictable**: if I tell the tool "branch from my HEAD," it must branch from my HEAD, not silently reset to origin. The prior behavior was data loss waiting to happen.

## 13. `/exit` OSC 9 stray "4;0;" in Kitty

**Type:** fix · **Modules:** Terminal escape sequences

`/exit` was emitting an OSC 9 sequence (`ESC ] 9 ; ...`) intended as the terminal-title-clear. ## 23. 1M-context model autocompact false-block

**Type:** fix · **Modules:** Compact, Context window

## 24. Parallel shell tools: failing read-only doesn't cancel siblings

**Type:** behavior · **Modules:** Bash tool, Parallel tool calls

When the model issues a parallel batch of shell commands (`grep`, `git diff`, `ls`, etc.) and one of the read-only commands fails (e.g. `grep` returns exit 1 because no match), the prior behavior canceled all sibling commands in the batch.

That's wrong for read-only-safe commands: their failures are independent. Now sibling read-only commands continue; only the failed one is reported.

### Why this approach

Parallel tool-call cancel-on-first-failure makes sense for **destructive** commands (a failed `rm` shouldn't be followed by `chmod` on the partial state). But read-only commands have no observable side effects on each other. The new isolation matches the model's mental model: "I'm gathering info; one missing piece doesn't invalidate the others."

## 33. MCP stdio + `CLAUDE_CODE_SHELL_PREFIX` argument corruption

**Type:** fix · **Modules:** MCP, Shell prefix

```javascript
// ============================================
// shellPrefixWrap - applies CLAUDE_CODE_SHELL_PREFIX to commands
// Location: cli_inner_pretty.js:360861, 360918, 414305-414306, 520861
// ============================================

// ORIGINAL (for source lookup):
if (process.env.CLAUDE_CODE_SHELL_PREFIX) G = nY8(process.env.CLAUDE_CODE_SHELL_PREFIX, G);
// ...
let u = process.env.CLAUDE_CODE_SHELL_PREFIX || $.command,
  S = process.env.CLAUDE_CODE_SHELL_PREFIX ? [W4([$.command, ...$.args])] : $.args;

// READABLE (for understanding):
const prefix = process.env.CLAUDE_CODE_SHELL_PREFIX;
if (prefix) cmdLine = wrapWithShellPrefix(prefix, cmdLine);
// ...
const program = prefix || invocation.command;
const programArgs = prefix
  ? [shellEscapeArgs([invocation.command, ...invocation.args])]  // single quoted string
  : invocation.args;                                              // raw arg array

// Mapping: nY8→wrapWithShellPrefix, W4→shellEscapeArgs, G→cmdLine,
//          u→program, S→programArgs, $→invocation
```

When `CLAUDE_CODE_SHELL_PREFIX` was set (e.g. `sudo -u serviceuser`), arguments containing spaces or shell metacharacters were being **re-tokenized by the shell**, breaking commands like `--filter "foo bar"`. Fixed by passing args as a single shell-quoted string when the prefix is shell-evaluated.

## Summary

v2.1.128 is a **broad polish release**: ~40 line items, most of them stability/UX fixes that became visible after the rapid 2.1.122–2.1.126 feature rollouts settled. Standout structural changes: parallel-shell isolation (failing reads don't cancel siblings), `OTEL_*` subprocess scrubbing (subprocess observability is sovereign), sub-agent cache (big token savings), and EnterWorktree HEAD-source (no more unpushed-commit data loss).
