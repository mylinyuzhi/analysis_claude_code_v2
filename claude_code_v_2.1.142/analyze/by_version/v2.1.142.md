# v2.1.142 — Source Diff Analysis

**Theme:** `claude agents` configurability for dispatched sessions, **Fast Mode defaults to Opus 4.7**, root-level `SKILL.md` plugin support, `MCP_TOOL_TIMEOUT` finally honored for remote MCP, daemon clock-jump detection, and reactive-compaction seed improvement.

The release is best read as **the closing patches to make `claude agents` (introduced v2.1.139) feel mature**.

**After:** Pre-existing worktrees are recognized — `EnterWorktree` no-ops, `Edit` proceeds.

## 8. Daemon clock-jump detection (sleep/wake)

**Type:** fix · **Modules:** Daemon

**Before:** On macOS sleep/wake, the system clock could jump several hours forward when the laptop resumed. The daemon's idle timeout used elapsed wall-clock time and treated the jump as "user has been idle for 8 hours" — exited, killing background sessions.

**After:** The daemon now detects clock jumps (delta wildly different from monotonic-clock delta) and skips idle-exit on suspected wake events.

**Why this is subtle:** Standard idle-timeout patterns use `Date.now()`, which is wall-clock. Sleep/wake messes that up. The fix uses `process.hrtime()` (monotonic) to cross-check.

## 9. Daemon clean exit after binary upgrade

**Type:** fix · **Modules:** Daemon

**Before:** After `brew upgrade claude` (or any binary replacement), the running daemon kept executing from the deleted-on-disk binary path. The next dispatched agent would try to fork from the same path and crash-loop.

**After:** Daemon detects binary disappearance and exits cleanly; next dispatch spawns a fresh daemon from the new binary.

## 22. Reactive compaction — first summarize seeds from overflow size

**Type:** performance · **Modules:** Compact

### v2.1.142 state

| | |
|---|---|
| **Type** | Performance (algorithm) |
| **Modules touched** | Compact |
| **Before** | Reactive compaction (context-overflow trigger) started its first summarize attempt from the full conversation. If it overflowed the model's context window, retry with a smaller scope — but the retry was near-full-context too. Often a wasted call. |
| **After** | The first summarize attempt now seeds from the original request's overflow size, so the chosen sub-conversation is *already* sized to fit. Eliminates the wasted near-full-context retry. |
| **Why** | Token efficiency. The "overflow size" is a usable signal — the LLM gateway tells us how much we were over, so we can pre-shrink instead of fail-then-shrink. |

## Summary

v2.1.142 closes out the v2.1.139 agent-view feature with both expanded configurability (`claude agents` now accepts all the flags `claude` does) and a long list of daemon/background reliability fixes (clock-jump, binary upgrade, Chrome shim, network-drive deadlock, color bleed). The biggest *behavior* change is Fast Mode adopting Opus 4.7 as its default — a quiet but meaningful capability upgrade for fast-mode users. The reactive-compaction seed improvement is a quiet performance win for users hitting context limits regularly.

The release feels like the end of the "agent view stabilization" arc. Future versions can shift to new feature work.
