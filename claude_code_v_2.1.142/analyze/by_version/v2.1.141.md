## 1. Hook `terminalSequence` JSON field (NEW)

**Type:** feature · **Modules:** Hooks

### v2.1.141 state

```javascript
// ============================================
// terminalSequenceHookField - hook escapes (OSC, BEL) for notifications
// Location: cli_inner_pretty.js:238108, schema at :519030, runtime at :520641-520646
// ============================================

terminalSequence: y
  .string()
  .optional()
  // ... part of hook JSON output schema

// Runtime use (cli_inner_pretty.js:520641-520646):
if (H.terminalSequence) {
  let D = Lm6(H.terminalSequence);
  if (D !== null) M.terminalSequence = D;
  else
    // Rejected (only OSC 0/1/2/9/99/777 and BEL permitted)
    log(`Hook ${q} (${_}) returned a terminalSequence that was rejected by the allowlist (only OSC 0/1/2/9/99/777 and BEL are permitted)`)
}
```

| | |
|---|---|
| **Type** | Feature (hook output) |
| **Modules touched** | Hooks |
| **Before** | Hooks that wanted to set window titles, ring bells, or fire desktop notifications had to write to the controlling terminal directly. v2.1.139 removed hook terminal access (for safety). Net result: hooks lost a useful capability. |
| **After** | Hooks can return a `terminalSequence` JSON field containing escape sequences. CLI applies them to its own controlling terminal under an allowlist (OSC 0/1/2/9/99/777, BEL). |
| **Why** | Restores the notification capability that was lost in v2.1.139, but through a controlled channel — hooks describe intent, CLI executes. The allowlist limits what hooks can do: title (OSC 0/2), notification (OSC 9), bell (BEL) — not arbitrary cursor manipulation. |

**Key insight:** The allowlist values are intentional. OSC 9 (iTerm) and OSC 99 (kitty/wezterm) and OSC 777 (xterm) are *the* notification escape sequences. By restricting to these, the field can't be used as a covert channel for cursor positioning attacks.

## 3. `ANTHROPIC_WORKSPACE_ID` env var (NEW)

**Type:** feature · **Modules:** Auth, Workload Identity Federation

### v2.1.141 state

```javascript
// Location: cli_inner_pretty.js:4167, 91330
workspace_id: wO("ANTHROPIC_WORKSPACE_ID"),

// Without it, the message (cli_inner_pretty.js:4335):
"If your federation rule is scoped to multiple workspaces, set the ANTHROPIC_WORKSPACE_ID environment variable, the 'workspace_id' config key, or the `workspaceId` option."
```

**Why:** Workload identity federation lets services (CI, Kubernetes pods, Lambda) mint tokens without long-lived secrets. When the federation rule covers multiple workspaces, the federated token's "audience" is ambiguous. `ANTHROPIC_WORKSPACE_ID` resolves the ambiguity by binding the minted token to a specific workspace.

## 4. `claude agents --cwd <path>` (NEW)

**Type:** feature · **Modules:** Agent view

`claude agents` lists all sessions. `--cwd <path>` filters to sessions running in (or for) a specific directory. Helps users with many concurrent agents narrow to "what's running for this project."

---

## 5. `/feedback` includes recent sessions

**Type:** UX · **Modules:** /feedback

`/feedback` (the bug-report bundle generator) can now include sessions from the last 24 hours or 7 days. Helps Anthropic reproduce issues that span multiple sessions (auth flow, daemon, multi-session bugs).

---

## 6. Rewind "Summarize up to here"

**Type:** feature · **Modules:** Rewind, Compact

Rewind menu now includes a "Summarize up to here" option — compress the earlier conversation (everything before the rewind point) while keeping recent turns intact. Useful when a session is approaching context limits but recent work is too valuable to lose.

---

## 7. Auto mode permission dialog explains `permissions.ask`

**Type:** UX · **Modules:** Permissions, Auto mode

**Before:** When a `permissions.ask` rule fired in auto mode, the permission dialog appeared but didn't say *why*. Users assumed auto mode was broken.

**After:** The dialog explicitly says "this prompt is from a `permissions.ask` rule." Users understand it's a configured request, not a regression.

---

## 8. Restored "view diff in your IDE" option

**Type:** UX · **Modules:** Permissions, IDE

The "view diff in IDE" option on file-edit permission prompts was missing when an IDE was connected. Now restored. Useful for visualizing the proposed edit before approving.

---

## 9. `/bg` and `←←` preserve current permission mode

**Type:** fix · **Modules:** /bg, Permissions

**Before:** Backgrounding a session via `/bg` or `←←` (the agent-view return chord) reverted permission mode to default. If the user was in `bypassPermissions` or `plan` mode, the backgrounded session lost it.

**After:** Permission mode is preserved across backgrounding.

---

## 10. `claude agents` Completed status for background-shell sessions

**Type:** UX · **Modules:** Agent view

**Before:** An agent that finished its work but left a background shell running (e.g. a long-running `npm run dev`) was shown under Working (because the shell was still running).

**After:** Such agents are now shown under Completed. The shell stays running, but the agent itself is no longer "actively working."

---

## 11. Spinner warming to amber after 10s

**Type:** UX · **Modules:** Spinner

**Before:** During long thinking periods (extended thinking, slow API), the spinner kept its default color. Users wondered "is it stuck?"

**After:** After 10 seconds, the spinner color warms to amber, signaling "still working, just slow."

## Summary

v2.1.141 is the version where the v2.1.139 agent-view feature **gets all the polish it needed to feel ready for non-preview users**. Roughly half the release is `claude agents`/`/bg` adjacent: pre-warm fallback, empty-placeholder cleanup, daemon-pipe error visibility, backgrounded-permission-mode preservation, Completed vs Working classification.

The two notable platform additions:
- **`terminalSequence`** brings back hook notification capability through a controlled escape-allowlist, after v2.1.139 removed direct terminal access.
- **`ANTHROPIC_WORKSPACE_ID`** is the missing piece for workload identity federation in multi-workspace orgs.

The fix sweep includes a 2.1.136 regression (markdown table wrap) and several Windows reliability issues. Notable safety fix: `apiKeyHelper`/`ANTHROPIC_AUTH_TOKEN` no longer inherits from host managed-settings into third-party provider sessions, closing a credential-leakage path.
