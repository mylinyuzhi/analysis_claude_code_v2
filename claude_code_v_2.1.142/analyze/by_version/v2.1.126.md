# v2.1.126 — Source Diff Analysis

**Theme:** Gateway-aware `/model` picker, host-managed analytics & PowerShell as a first-class Windows shell, security fix for `allowManagedDomainsOnly`, big batch of OAuth/credential/network resilience fixes, and assorted UI polish.

> v2.1.124 and v2.1.125 were skipped in the public release stream.

## 1. `/model` lists models from gateway `/v1/models`

**Type:** feature · **Modules:** Model picker, Gateway routing

### v2.1.123 baseline

The `/model` picker showed a hardcoded list of Anthropic-known models. Custom gateways (corporate proxies, `ANTHROPIC_BASE_URL` deployments) were invisible — users had to type the exact model name on the CLI.

### v2.1.126 state — opt-in gateway discovery

When `ANTHROPIC_BASE_URL` points at an Anthropic-compatible gateway, the picker hits `/v1/models` on that gateway and merges the response into the picker.

```javascript
// ============================================
// gatewayModelDiscoveryGate - opt-in flag check
// Location: cli_inner_pretty.js:433813 (and the call site of the model list builder)
// ============================================

// ORIGINAL (for source lookup):
if (!bH(process.env.CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY)) return !1;

// READABLE (for understanding):
function isGatewayModelDiscoveryEnabled() {
  // 2.1.126: discovery defaults on when gateway is present.
  // 2.1.129: turned off by default; this env var is the new opt-in.
  return parseEnvBoolean(process.env.CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY);
}

// Mapping: bH→parseEnvBoolean
```

In 2.1.126–2.1.128 the discovery was automatic on `ANTHROPIC_BASE_URL`; **v2.1.129 reverts it to opt-in** because some gateways respond to `/v1/models` with their own catalogs (or 404s that broke startup).

### Why this approach

- **Discovery beats hardcoding.** A new model deployed on the gateway is immediately pickable — no Claude Code update needed.
- **Why merge, not replace:** Gateways often proxy first-party models verbatim; preserving the known catalog means the picker still works if the gateway lacks `/v1/models`.
- **Why opt-in in 2.1.129:** Operators of internal gateways objected to the unsolicited discovery probe (logs, billing flags, false positives in WAFs).

## 2. `claude project purge [path]` — delete all CC state for a project

**Type:** feature · **Modules:** CLI subcommands, Session storage

A new top-level subcommand. By default, interactive prompt:

```
claude project purge
claude project purge ~/code/old-app --dry-run
claude project purge --all -y         # all projects, no prompt
```

Wipes:
- Transcript dir
- Task history (`/loop` outputs, scheduled-task state)
- File-edit history (the audit log used for undo/redo)
- Config entry for the project (the `projects.<path>` block in `.claude/config.json`)

Flags:
- `--dry-run` — list what would be deleted, change nothing
- `-y` / `--yes` — skip confirmation
- `-i` / `--interactive` — confirm each item
- `--all` — every known project

### Why this approach

- **Why subcommand, not `/purge` slash:** Purging is a *meta-CLI* operation — it cleans state across sessions; the slash command universe is per-session.
- **`--dry-run` is the safety net.** The deletion is irreversible (config entry + transcript dir) so a preview mode is non-negotiable.

## 3. `--dangerously-skip-permissions` covers more sensitive paths

**Type:** safety (controversial) · **Modules:** Permissions

### Before

`--dangerously-skip-permissions` bypassed *most* permission checks but still prompted for: writes to `.claude/`, `.git/`, `.vscode/`, shell config files (`.bashrc`, `.zshrc`, `.profile`), and a few other special paths.

### After

The flag now also bypasses prompts for **those paths**, with one carve-out: catastrophic removal patterns (e.g. `rm -rf /`, `rm -rf ~`, hardcoded fork bomb signatures) still prompt.

### Why this approach

The flag is named `--dangerously-skip-permissions` for a reason — partial enforcement made it confusing ("I said dangerously, why is it still prompting?"). The expansion makes the contract clear: this flag means **trust the model unconditionally for normal writes**, and only the last-resort catastrophic-removal heuristic remains. Users who don't want this surface should not pass the flag.

The catastrophic carve-out exists because those are the operations no one wants the model to perform by accident — not as a permission check, but as a panic stop.

## 4. `claude auth login` accepts pasted OAuth code

**Type:** UX · **Modules:** Auth

When the browser callback to `localhost:54545` can't reach the CLI (WSL2 networking, SSH tunneling, container, restrictive firewalls), the prior login flow stalled forever.

Now after opening the browser, the CLI also prints "Paste the OAuth code below if the browser callback doesn't return" and accepts a code from the manual flow page.

### Why this approach

- **Why two paths in parallel:** The browser callback succeeds for the majority; the paste path is the fallback. Trying paste *first* would force friction on the majority.
- **The OAuth code is short-lived and bound to a PKCE verifier the CLI holds — pasting it is safe even over an untrusted relay.

## 6. Auto-mode red spinner when permission check stalls

**Type:** UX · **Modules:** Auto-mode

In auto-mode, when a permission check (the model's "should I run this?" gate) hangs, the spinner used to look identical to "tool is running" — leading users to wait forever for a tool that wasn't actually running.

Now the spinner turns red after a short stall window, signaling "I'm blocked, not working." A `--debug` hint suggests rerunning with debug logging.

## 7. Host-managed deployments stop disabling analytics

**Type:** infra · **Modules:** Telemetry, Provider config

Setting `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST=1` (the env var that says "this CLI runs inside another product, like a managed agent host") used to auto-disable analytics on Bedrock/Vertex/Foundry, on the assumption that the host already collects telemetry.

That assumption was wrong: some hosts wanted CC's own analytics for their dashboards. Now the host-managed flag *no longer* auto-disables analytics; hosts that want it off can set `DISABLE_TELEMETRY=1` explicitly.

### Why this approach

The principle: **flags should be orthogonal**. `MANAGED_BY_HOST` is about *who configured the model provider*; `DISABLE_TELEMETRY` is about *what telemetry we send*. Coupling them was a category error.

## 8. Windows PowerShell 7 detection from Microsoft Store / MSI / .NET tool

**Type:** infra · **Modules:** Shell detection, Windows

PowerShell 7 (`pwsh.exe`) can be installed via:
- Microsoft Store package (lives under `%LOCALAPPDATA%\Microsoft\WindowsApps`)
- MSI without PATH (a default install option)
- `.NET global tool` install (lives under `%USERPROFILE%\.dotnet\tools`)

Previously only PATH-discoverable `pwsh.exe` was found. Now all three install locations are probed.

## 9. Windows: PowerShell becomes the primary shell

**Type:** infra · **Modules:** Bash tool, Windows

When the PowerShell tool is enabled in `settings.json`, Claude now treats PowerShell — not Bash — as the **primary shell**. The implication: Bash invocations from the model are translated/routed to PowerShell.

### Why this approach

Windows users running CC without Git Bash hit confusion: the model would issue `ls`, `cat`, `grep` and Windows had to fake them. Now if PowerShell is the explicit choice, PowerShell is what runs — no translation layer pretending to be Bash.

## 10. Read tool: removed malware-assessment reminder

**Type:** prompt · **Modules:** Read tool

The Read tool description used to contain a per-file reminder about checking whether the file contained malware. The reminder was leaking into model behavior — Claude would write "this file does not appear to be malware" commentary after innocuous reads, especially on legacy models.

Removed. The remaining safety language is bundled in the system prompt, where it doesn't pollute every Read result.

## 11. Security fix: `allowManagedDomainsOnly` ignored without a `sandbox` block

**Type:** security · **Modules:** Permissions, Sandbox

### Bug

`allowManagedDomainsOnly: true` (a managed-settings flag that says "only enterprise-admin-approved domains can be reached") was silently ignored if a higher-priority managed-settings source loaded *first* and that source had no `sandbox` block.

The merge logic was: "if no sandbox key, leave sandbox alone." But the lower-priority `allowManagedDomainsOnly` was already merged into the running config when the higher-priority source loaded, so the flag stayed on but `sandbox.network.allowedDomains` was empty.

```javascript
// ============================================
// mergeManagedSandboxFlags - resolves allowManagedDomainsOnly across scopes
// Location: cli_inner_pretty.js:52061-52075
// ============================================

// ORIGINAL (for source lookup):
if (A && $.sandbox?.network?.allowManagedDomainsOnly !== !0) _.allow = A;
// ...
if (_.allowManagedDomainsOnly === !0) Y.allowManagedDomainsOnly = !0;

// READABLE (for understanding):
function mergeSandboxNetworkConfig(lowerScope, higherScope, accumulator) {
  // Higher scope's allow list wins UNLESS lower scope said "managed only"
  if (higherScope?.allow && lowerScope.sandbox?.network?.allowManagedDomainsOnly !== true) {
    accumulator.allow = higherScope.allow;
  }
  // The strict flag itself propagates from whichever scope set it
  if (lowerScope.allowManagedDomainsOnly === true) {
    accumulator.allowManagedDomainsOnly = true;
  }
}

// Mapping: A→higherScope.allow, $→lowerScope, _→accumulator, Y→accumulator (outer scope)
```

### Fix

The merge now treats `allowManagedDomainsOnly` as a **veto** that survives across scope merges: once any scope sets it true, the final config cannot include domains from a less-trusted scope. Same logic applies to `allowManagedReadPathsOnly`.

### Why this approach

This is the classic **deny-by-default-with-allowlist** pattern: a veto flag must propagate "up" through merges; allow-lists must not silently bypass a veto. The original bug was a subtle merge-semantics error — the veto bit was retained but its enforcement step was skipped.

## 12. Pasted image >2000px breaks session

**Type:** fix · **Modules:** Image handling

Pasting an oversized image broke subsequent prompts with "image exceeds dimension limit" — and the broken image was already in history, so even retrying failed.

Now:
1. On paste, images >2000px-per-side are downscaled to fit (preserving aspect ratio).
2. On request error "image exceeds dimension limit," CC scans the in-context images, removes the oversize ones, and **retries the request automatically**.

### Why this approach

The downscale-on-paste is **prevention**. The auto-retry on the error is **recovery for already-broken sessions**. Both paths are needed because users with sessions that pre-date the fix still had broken transcripts.

## 30. Windows clipboard writes hidden from EDR

**Type:** security · **Modules:** Clipboard, Windows

The Windows clipboard helper (`clip.exe`) was being invoked with the content passed as a command-line argument — which made the content visible to Endpoint Detection and Response telemetry (EDR/SIEM tooling that logs process command lines). Now the content is piped via stdin, never appearing in process arguments.

Also fixes the >22KB selections-not-reaching-clipboard issue (Windows truncates command-line args around that size).

### Why this approach

This is a **defense-in-depth** fix. EDR isn't an adversary — but copies of user-pasted secrets shouldn't end up in security telemetry feeds. Piping is the canonical way to keep arbitrary content out of argv.

## 31. PowerShell tool: bare `--` is not `--%`

**Type:** fix · **Modules:** PowerShell tool

PowerShell has a special `--%` token that means "stop parsing." CC's PS argument check was over-broadly matching bare `--` (the standard "end of options" separator used by `git diff -- file`). Now distinguishes the two.

## 32. Agent SDK hang on malformed tool name in parallel batch

**Type:** fix · **Modules:** Agent SDK

When the model emitted a parallel-tool-call batch where one of the tool names was malformed (typo, hallucinated), the SDK was waiting on a tool that would never run. Now detects malformed names early and fails the batch fast with a clear error.

## Summary

v2.1.126 is a **big infrastructure release**: gateway-aware model discovery, expanded `--dangerously-skip-permissions`, PowerShell-as-primary on Windows, a security fix for managed-settings merging, and roughly a dozen OAuth/credential/network resilience patches. The recurring theme: **make Claude Code coexist with environments it doesn't fully own** — corporate gateways, Windows installations, IPv6 devcontainers, EDR-instrumented hosts.
