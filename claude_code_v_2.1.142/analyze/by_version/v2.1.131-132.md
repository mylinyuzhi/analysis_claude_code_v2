# v2.1.131

## 1. VSCode extension fails to activate on Windows

**Type:** fix · **Modules:** VSCode extension, SDK bundling

### Bug

The bundled SDK in the VSCode extension contained a `createRequire("/")` call.

```javascript
// ============================================
// createRequireUsage - bundler emits absolute path
// Location: cli_inner_pretty.js:223754
// ============================================

// ORIGINAL (for source lookup):
((aaK = require("module")), (dK_ = aaK.createRequire("/")));

// READABLE (for understanding):
const Module = require("module");
const bundleRequire = Module.createRequire("/");  // BUG: "/" is invalid on Windows

// Mapping: aaK→Module, dK_→bundleRequire
```

`createRequire` takes a filename argument and uses it as the resolution base. Passing the literal `/` works on POSIX (root dir exists), but on Windows there is no `/` — the resolution base is invalid, and the resolver throws.

The bundle was built with esbuild's `createRequire` polyfill that defaulted to `/` instead of the bundle's `__filename`.

### Fix

The build now passes `__filename` (the bundle's runtime location) to `createRequire`. Resolution then anchors at the bundle on every platform.

### Why this approach

The original bug was the **build configuration**, not the runtime code. Fixing the build avoids the alternative — `path.sep` branching at runtime — which would have shipped Windows-specific code paths into every bundle.

## 2. Mantle endpoint missing `x-api-key` header

**Type:** fix · **Modules:** LLM API, Mantle provider

```javascript
// ============================================
// mantleProviderModelMap - per-model Mantle endpoint entries
// Location: cli_inner_pretty.js:90540, 90549, 90568
// ============================================

// ORIGINAL (for source lookup):
mantle: null,
// ...
mantle: "anthropic.claude-haiku-4-5",

// READABLE (for understanding):
// In the per-model provider routing map, the "mantle" field holds the
// Mantle gateway's model identifier (or null if not deployed there).
// The request builder must populate x-api-key for any entry whose
// provider resolves to "mantle".
const modelProviderEntries = {
  "claude-haiku-4-5": { mantle: "anthropic.claude-haiku-4-5" /* ...other providers */ },
};

// Mapping: (field name "mantle" preserved — provider identifier)
```

The Mantle provider's request builder was setting `Authorization: Bearer ...` but not also setting `x-api-key`. Mantle's auth gateway requires `x-api-key` specifically. The header-presence check at `cli_inner_pretty.js:7932-7936` short-circuits if either header is present, so for other providers the omission didn't matter — but Mantle's gateway treated the request as unauthenticated.

Fixed by populating `x-api-key` for Mantle requests.

## 4. External SIGINT runs graceful shutdown

**Type:** fix · **Modules:** Signal handling

```javascript
// ============================================
// signalHandlers - SIGINT/SIGTERM/SIGHUP
// Location: cli_inner_pretty.js:44287, 44527, 196333, 234674
// ============================================

// ORIGINAL (for source lookup):
{ name: "SIGINT", number: 2, action: "terminate", description: "User interruption with CTRL-C", standard: "ansi" }
// ...
process.on("SIGINT", () => { ... gracefulShutdown(...) ... });

// READABLE (for understanding):
const SIGINT_DESCRIPTOR = {
  name: "SIGINT", number: 2, action: "terminate",
  description: "User interruption with CTRL-C", standard: "ansi",
};
// Process-level handler (not input-listener-scoped):
process.on("SIGINT", () => { /* ... */ gracefulShutdown(/* ... */); });

// Mapping: (signal name "SIGINT" preserved)
```

### Bug

External SIGINT (an IDE stop button, `kill -INT $pid`, terminal close button signaling SIGINT) was bypassing the graceful shutdown handler — the process exited abruptly, leaving:
- Terminal in raw mode (broken keyboard until reset).
- Alternate screen still active (lost scrollback on some terminals).
- No `--resume` hint printed.

Ctrl+C from inside the input handler *did* go through graceful — only **external** SIGINT was dropping it. The handler was bound to the input listener, not to the process.

### Fix

Bind SIGINT (and SIGTERM, SIGHUP) at the process level so any source triggers the graceful path:
1. Restore terminal modes (cooked, main screen, cursor visible).
2. Flush pending writes.
3. Print the `--resume <id>` hint so the user can return.
4. Exit cleanly.

### Why this approach

The principle: **terminal state is global; cleanup must run regardless of who signaled**. Tying cleanup to the input listener was a category error — it assumed the only interrupt source was the keyboard.

## 6. `--resume` "no low surrogate" sanitization

**Type:** fix · **Modules:** Resume, Transcript parsing

```javascript
// ============================================
// surrogateDetect - detects orphaned surrogates in tool error text
// Location: cli_inner_pretty.js:204136
// ============================================

// ORIGINAL (for source lookup):
if (Ee1.test(H)) return { kind: "too-complex", reason: "Contains lone surrogate" };

// READABLE (for understanding):
if (LONE_SURROGATE_REGEX.test(transcriptLine)) {
  return { kind: "too-complex", reason: "Contains lone surrogate" };
}

// Mapping: Ee1→LONE_SURROGATE_REGEX, H→transcriptLine
```

When a tool error message truncation split an emoji (UTF-16 surrogate pair), the resulting transcript line contained a lone surrogate. JSON parsing during `--resume` threw "no low surrogate in string." Pre-corrupted sessions are now sanitized on load (surrogate replaced with U+FFFD).

### Why this approach

- **Fix the truncator AND the loader.** Truncation should never split surrogate pairs going forward, but pre-fix sessions exist on disk. The loader has to repair them.
- **Replace, not fail:** Losing one corrupted character in an old transcript is better than losing the entire session.

## Summary

v2.1.131 is a two-line patch keeping VSCode-on-Windows users and Mantle deployments unblocked.

v2.1.132 is the **post-2.1.128/2.1.129 cleanup release** — graceful exit becomes truly graceful, Unicode-grapheme awareness sweeps the cursor/vim/paste paths, terminal-integration quirks (JetBrains 2025.2, Cursor, VS Code 1.92–1.104) get explicit workarounds, and the prompt-caching path is hardened on Bedrock/Vertex. The standout architectural change is **shifting SIGINT cleanup from input-listener-scope to process-scope** — making "ensure terminal is restored on exit" a true global invariant.
