## 1. `ANTHROPIC_BEDROCK_SERVICE_TIER` env var

**Type:** feature · **Modules:** Bedrock, Service tier

### v2.1.88 baseline

AWS Bedrock supports three service tiers (`default`, `flex`, `priority`) with different cost/latency tradeoffs. Claude Code didn't surface any way to select one.

### v2.1.122 state

```javascript
// ============================================
// bedrockServiceTier - X-Amzn-Bedrock-Service-Tier header
// Location: cli_inner_pretty.js:128110-128111, 273609, 318096
// ============================================

// Header definition (multiple action specs):
[0, { ["httpHeader"]: "X-Amzn-Bedrock-Service-Tier" }]

// Send if env var set:
...(process.env.ANTHROPIC_BEDROCK_SERVICE_TIER && {
  "X-Amzn-Bedrock-Service-Tier": process.env.ANTHROPIC_BEDROCK_SERVICE_TIER,
})

// Env vars discoverability list:
"ANTHROPIC_BEDROCK_SERVICE_TIER",

// Usage:
let A = process.env.ANTHROPIC_BEDROCK_SERVICE_TIER;
```

The header is sent only when the env var is set. Valid values are `default`, `flex`, or `priority`.

### Why this approach

**Cost/latency control surface.** Enterprises with predictable workloads can use `flex` for cost savings; latency-critical agents can use `priority`. Without the env var, all traffic went to AWS's default tier — leaving cost on the table.

**Why an env var (not a setting):** Service tier is often pinned at deploy time (per-environment, per-pipeline). Env vars are the natural shape for deploy-time config. Settings would also work but env-var aligns with how cloud credentials are typically set.

**Why no validation in the CLI:** AWS will reject invalid values with a clear error. Defending in the CLI would duplicate AWS's validation and lag changes when AWS adds new tiers.

## 2. `/resume` search by PR URL

**Type:** feature · **Modules:** /resume, PR linking

Pasting a PR URL (GitHub, GitHub Enterprise, GitLab, Bitbucket) into the `/resume` search box now finds the session that created that PR.

### Why this approach

**Reverse lookup.** Users who created a PR weeks ago and want to reopen the conversation that created it have a natural identifier: the PR URL. The reverse lookup is the obvious feature once `--from-pr` (v2.1.119 §4) exists.

**Why all four providers:** Same shape as `--from-pr` provider parity. The session-to-PR link is established at PR creation time and stored regardless of provider.

## 5. OTel numeric attributes — emitted as numbers

**Type:** Observability · **Modules:** OTEL

`api_request` and `api_error` log events were emitting numeric attributes as strings (the JSON-stringification was being applied uniformly). Now numbers stay numbers — so dashboards can aggregate them.

### Why this matters

Aggregation queries in OTel collectors (sum, p99, etc.) require numeric types. Stringified numbers broke aggregation silently. The fix is a one-line schema correction but downstream-significant.

## 9. Vertex AI / Bedrock `output_config: Extra inputs are not permitted`

**Type:** fix · **Modules:** Vertex AI, Bedrock

```javascript
// ============================================
// outputConfigCompat - Vertex/Bedrock filtering
// Location: cli_inner_pretty.js:5740, 6663-6668, 525270-525326
// ============================================

return H?.output_format ?? H?.output_config?.format;

if (H.output_config?.format)
  "Both output_format and output_config.format were provided. Please use only output_config.format (output_format is deprecated)."

return { ...q, output_config: { ...H.output_config, format: $ } };

// Stripping output_config for incompat models:

(delete IH.output_config, lm5(e, pH, IH, s, f), nm5(A.taskBudget, pH, s), im5(A.outputFormat, pH, s, A.model));
// Conditionally re-attach:
...(Object.keys(pH).length > 0 && { output_config: pH }),
```

Vertex AI and Bedrock were returning `invalid_request_error: output_config: Extra inputs are not permitted` on session-title generation and other structured-output queries. The `output_config` field is now properly filtered per model before request — only re-attached when there are fields the model accepts.

### Why this approach

**Provider compatibility matrix.** Different Anthropic-API consumers (Vertex, Bedrock, gateway, direct API) have different subset support for `output_config`. The fix:
1. Strip the whole thing.
2. Re-add only the subset this model/provider accepts.
3. Only re-attach if anything's left.

This is the cleanest pattern for "subset-of-features support" — and the deprecation warning in §6663 ("output_format is deprecated, use output_config.format") makes the migration path clear.

## 13. `!exit` / `!quit` in bash mode terminating the CLI

**Type:** fix · **Modules:** Bash mode

In bash mode, `!exit` / `!quit` were terminating the CLI (because they were being interpreted as the *CLI's* exit signals rather than bash commands). Now run as shell commands within the bash mode session.

### Why this approach

**Bash mode means bash.** A user in bash mode typing `!exit` is asking for the shell to exit (the shell session terminates, the CLI returns to its main loop). Conflating with the CLI's exit was a leak of UI abstraction into the bash mode.

## 14. Image resize 2576px → 2000px for newer models

**Type:** fix · **Modules:** Image processing

```javascript
// Location: cli_inner_pretty.js:200083-200084
"An image in the conversation exceeds the dimension limit for many-image requests (2000px). Start a new session with fewer images."
"An image in the conversation exceeds the dimension limit for many-image requests (2000px). Run /compact to remove old images from context, or start a new session."
```

Images sent to newer models were being resized to 2576px per side instead of the correct 2000px maximum for many-image requests. The 2576px is Opus 4.7's high-res limit for single-image requests; many-image requests still cap at 2000px.

### Why this matters

Hitting the 2576px cap on many-image requests returned 400 with an opaque error. The fix uses the correct ceiling per request shape.

## 17. Malformed hooks entry invalidating entire `settings.json`

**Type:** fix · **Modules:** Settings, Hooks

A malformed `hooks` entry in `settings.json` was invalidating the entire file (same pattern as v2.1.121 §30 for invalid enums). Now the bad hooks entry is skipped with a warning; other settings apply.

### Why this matters

Hooks are a common cut-and-paste target for user customization. A typo in hooks config shouldn't take down the whole settings file. This fix is the final piece in the "partial-recovery on bad settings" arc that started in v2.1.121.

## 18. Voice: Caps Lock keybindings show error

**Type:** UX · **Modules:** Voice mode, Keybindings

```javascript
// ============================================
// capsLockUnusable - error for terminal-non-deliverable keys
// Location: cli_inner_pretty.js:167812, 167835-167837
// ============================================

{ key: "capslock", reason: "Caps Lock is not delivered to terminal applications", severity: "error" }

// Normalized aliases that all map to capslock:
caps: "capslock",
"caps-lock": "capslock",
caps_lock: "capslock",
```

Keybindings bound to Caps Lock in voice mode now show an error since terminals don't deliver Caps Lock as a key event. Previously the binding was silently accepted but never fired.

### Why this approach

**Loud failure beats silent failure.** A user binding Caps Lock expected it to work; it wasn't. The error tells them why. The three aliases (`caps`, `caps-lock`, `caps_lock`) all normalize to the canonical `capslock` so the error fires regardless of how the user wrote the key name.

## Summary

v2.1.122 is **the cleanup pass after v2.1.121's stability push**:

- **Bedrock service tier** — gives enterprise users cost/latency control.
- **`/resume` search by PR URL** — completes the PR-binding arc.
- **OTel numeric attrs + `at_mention` event** — observability cleanup.
- **`output_config` filtering for Vertex/Bedrock** — the most-impactful per-user fix (no more "Extra inputs are not permitted").
- **Settings partial-recovery for malformed hooks** — finishes the v2.1.121 §30 arc.
- **Image resize 2000px** — closes a real "this should just work" gap.
- **Caps Lock error** — small but emblematic of the "fail loudly, not silently" pattern.

The pattern: **all the small things that don't fit a feature release but still bother users.** The `output_config` fix is the load-bearing one (it kept hitting Vertex/Bedrock users in normal flows like session-title generation). Everything else is texture.

v2.1.123 is then a one-liner (OAuth 401 retry loop with `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`) — exactly the "one bug snuck through" hotfix pattern.
