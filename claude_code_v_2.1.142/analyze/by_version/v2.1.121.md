# v2.1.121 — Source Diff Analysis

**Theme:** **`alwaysLoad`** MCP server config (skip tool-search deferral), `claude plugin prune` for orphan deps, `/skills` type-to-filter, **PostToolUse `updatedToolOutput` for all tools**, fullscreen scroll-preservation on type, scrollable overflow dialogs, OAuth/credentials reliability follow-through, **memory-leak fixes** (images, `/usage`, long-running tools), Bash deleted-cwd recovery, and a long observability/auth/scrollback tail.

This is the largest patch release in the 113-122 window.

## 1. `alwaysLoad` MCP server config

**Type:** feature · **Modules:** MCP, ToolSearch

### v2.1.88 baseline

All MCP server tools went through tool-search deferral — they weren't exposed in the up-front tool list, only surfaced when the model invoked ToolSearch. For users with a small number of specific tools they wanted always available, this was an awkward indirection.

### v2.1.121 state

```javascript
// ============================================
// alwaysLoad MCP config field
// Location: cli_inner_pretty.js:48887, 48911-48959, 211831, 237514
// ============================================

// Schema (per MCP server type — stdio, http, sse, websocket, sdk):
alwaysLoad: y.boolean().optional()

// Check at tool-search defer time:
if (H.alwaysLoad === !0) return !1;

// Mapping: H→serverConfig
```

When `alwaysLoad: true`, all tools from that server skip tool-search deferral and are always available in the model's tool list.

### Why this approach

**Tool-search deferral was a default that didn't always match user intent.** For "I always want my Notion MCP available," deferral added a turn of overhead (the model has to call ToolSearch first). Marking the server `alwaysLoad: true` skips that.

**Why per-server (not per-tool):** Most users group tools by domain (Notion, Slack, etc.) per server. Per-server granularity matches the configuration shape.

**Why opt-in:** Default deferral is still right for users with many MCP servers. Opt-in `alwaysLoad` for the few servers that justify the cost.

## 2. `claude plugin prune` for orphan auto-installed deps

**Type:** feature · **Modules:** Plugins, CLI

### v2.1.88 baseline

Auto-installed plugin dependencies stayed installed after their pinner was uninstalled. Over time, the plugin store accumulated orphan plugins — taking disk and surface.

## 4. PostToolUse `updatedToolOutput` for all tools

**Type:** feature · **Modules:** Hooks

### v2.1.88 baseline

A `PostToolUse` hook returning `hookSpecificOutput.updatedToolOutput` could only replace MCP tool output. For built-in tools (Bash, Read, Write), the hook could not modify the output the model saw.

### v2.1.121 change

`PostToolUse` hooks can now replace tool output for **all** tools via `hookSpecificOutput.updatedToolOutput`. Built-in tool outputs are now equally interceptable.

### Why this approach

**Symmetry + use-cases.** "Validate the bash output before the model sees it" and "redact sensitive content from a file Read" are now expressible. Restricting to MCP only was historical (MCP was the new surface and got the interception primitive first).

**Trade-off:** Hooks gain more power, and with it more responsibility. A buggy hook can corrupt the model's view of tool output for everything. The hook framework's error handling (fall through to original output on hook crash) mitigates.

## 5. Fullscreen: typing into prompt no longer snaps back

**Type:** UX · **Modules:** Fullscreen, Scroll

### v2.1.88 baseline

In fullscreen mode, typing into the prompt was snapping scroll back to the bottom. Users who scrolled up to read earlier content and started typing lost their position.

### v2.1.121 change

Typing now preserves the scroll position. Only explicit "scroll to bottom" actions (`End`, the click-to-bottom pill) snap.

### Why this approach

**Composition.** Reading earlier content while typing is a common workflow ("let me see what I said earlier, then respond"). Snapping defeated the workflow.

**Trade-off:** A user typing while expecting to see the latest output won't see it (their scroll is preserved). Mitigated by the new-messages pill (already exists).

## 19. Memory leak fixes — images, `/usage`, long-running tools

**Type:** fix · **Modules:** Memory

Three separate fixes:
- **Image processing memory leak (multi-GB RSS):** Many-image sessions were leaking image buffers. Now released.
- **`/usage` memory leak (up to ~2GB):** On machines with large transcript histories, `/usage` was retaining session arrays. Now freed after the dialog closes.
- **Long-running tools failing to emit progress:** Memory pressure when tools held outputs without flushing. Now bounded.

### Why this matters

Long sessions (especially with images) were crashing the CLI. The fixes are individually small but the aggregate is "Claude Code becomes a long-lived process viable."

## 20. Bash tool unusable after starting directory deleted/moved

**Type:** fix · **Modules:** Bash, cwd

If the directory Claude was started in was deleted or moved mid-session, the Bash tool became permanently unusable (every command failed with "no such directory"). Now falls back to the user's home or the most-recent valid cwd.

### Why this matters

A common scenario: user starts Claude in `~/work`, then `git checkout -b feature` in a script, then the script removes `~/work/.tmp`. If `.tmp` was Claude's cwd, Bash dies. The fix preserves the session.

## Summary

v2.1.121 is the **"stability + extension surface"** release:

- **`alwaysLoad`** — gives users escape hatch from MCP tool-search deferral when they want their tools immediately available.
- **`plugin prune`** — cleanup for the plugin ecosystem.
- **PostToolUse `updatedToolOutput` for all tools** — extends the v2.1.118 `mcp_tool` hook power to built-in tools.
- **Fullscreen scroll-on-type preservation + scrollable dialogs** — UX maturity.
- **Memory leak triple-fix (images, /usage, long-running tools)** — makes long sessions viable.
- **Bash deleted-cwd recovery, `--resume` corruption tolerance** — both speak to the "Claude as long-lived process" maturity.
- **OTel `finish_reasons` + `user_system_prompt`** — alignment with the GenAI semantic conventions.

The pattern: **a lot of "this was almost right" things become right.** Tool-search deferral was right for MCP servers as a class but wrong for the always-on subset. Hook output-replacement was right for MCP tools but inconsistent for built-ins. Each of these gets resolved.

The memory-leak triple-fix is the quiet hero: in aggregate, it converts "Claude Code is a snappy short-lived process" into "Claude Code is a snappy long-lived process."
